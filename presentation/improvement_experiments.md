# 발표 자료의 개선 실험 정리

발표 자료 19·20장의 "베이스라인 모델"과 "1차~4차 개선"이 각각 무엇을 바꾼 실험이었는지 정리한 문서다. 수치는 모두 저장소의 실험 보고서에서 옮겼고, 각 절 끝에 근거 파일을 적었다.

## 먼저 알아 둘 것

**평가 방식.** 사용자가 좋아한 Linux 게임 1개를 숨기고, 나머지 리뷰 기록으로 게임 10개를 추천한다. 숨긴 게임이 10개 안에 있으면 맞힌 것으로 센다.

- **Recall@10:** 숨긴 게임을 추천 10개 안에서 찾은 사용자의 비율.
- **NDCG@10:** 숨긴 게임이 1위에 가까울수록 높아지는 점수. 최고값은 1이다.

**비교 집단.** 같은 모델이라도 집단이 다르면 수치가 크게 다르다. 아래 표의 수치는 대부분 두 집단에서 나왔다.

| 이름 | 사용자 수 | 설명 |
|---|---:|---|
| 내부 검증 | 325,639명 | 학습 데이터에서 따로 뺀 계정. 모델 선택은 이 집단으로만 했다. |
| 100개 제한 평가셋 | 24,342명 | 게임당 리뷰를 최대 100개로 제한한 외부 데이터. 선택을 마친 뒤 결과만 확인했다. |

4차 개선만 새로 뺀 계정 10,000명으로 확인했다. 그래서 4차 개선의 수치는 위 두 집단의 수치와 직접 비교할 수 없다.

**채택 규칙.** 새 모델은 아래 다섯 조건을 모두 통과해야 기존 모델을 대신할 수 있다. 실험 전에 정했고, 결과를 본 뒤 바꾸지 않았다.

1. 내부 검증 NDCG@10이 기존 모델보다 높다(신뢰구간 하한이 0보다 큼).
2. 전체 Recall@10이 낮아지지 않는다.
3. 게임마다 따로 잰 NDCG의 평균이 낮아지지 않는다.
4. 비인기 게임(학습 데이터에서 좋아한 사용자가 1–999명인 게임)의 NDCG가 낮아지지 않는다.
5. 추천 목록이 빈 사용자가 늘지 않는다.

3·4번 조건은 인기 게임만 잘 맞히는 모델을 거르기 위한 것이다. 인기 게임 몇 개를 추천하면 전체 평균은 올라가지만, 사용자에게 새로운 게임을 찾아 주는 추천과는 거리가 멀다.

## 한눈에 보기

| 단계 | 무엇을 바꿨나 | 대상 모델 | 내부 검증 Recall@10 | 100개 제한 Recall@10 | 판정 |
|---|---|---|---:|---:|---|
| 베이스라인 | 소개글 비교, 함께 좋아한 게임 비교 | TF-IDF / Item-KNN | 1.93% / 40.08% | 3.58% / 11.19% | 출발점 |
| 1차 개선 | 소개글에 태그·장르 정보를 더함 | TF-IDF | 1.93% → 9.51% | 3.58% → 6.70% | 채택 |
| 2차 개선 | 리뷰를 많이 쓴 사용자의 영향을 줄임 | Item-KNN | 40.08% → 40.93% | 11.19% → 10.86% | 채택 |
| 3차 개선 | 개발사·유통사·기능 분류 정보를 더함 | TF-IDF | 9.51% → 14.51% | 6.70% → 9.64% | 채택 |
| 4차 개선 | 인기 게임 쏠림을 조절하는 선형 모델(DAN) | Item-KNN 대체 후보 | 40.51% → 45.58% (확인 평가 1만 명) | — | 미채택 |

최종 모델은 2차 개선을 적용한 **활동량 보정 Item-KNN**이다.

## 베이스라인 모델

개선 실험의 출발점이 된 두 모델이다.

- **소개글 TF-IDF:** 게임 소개글에 나온 단어를 비교한다. 사용자가 좋아한 게임과 소개글이 비슷한 게임을 추천한다.
- **Item-KNN (K=100):** 같은 사용자들이 함께 좋아한 게임을 "비슷한 게임"으로 본다. 게임마다 비슷한 게임을 100개까지 저장해 두고 추천에 쓴다. K=100은 이 100개를 뜻하며, 추천 개수 10개와는 다른 값이다.

| 평가 | 모델 | Recall@10 | NDCG@10 |
|---|---|---:|---:|
| 내부 검증 | Item-KNN | 40.08% | 0.244 |
| 내부 검증 | 소개글 TF-IDF | 1.93% | 0.012 |
| 100개 제한 평가셋 | Item-KNN | 11.19% | 0.075 |
| 100개 제한 평가셋 | 소개글 TF-IDF | 3.58% | 0.024 |

Item-KNN이 두 평가 모두에서 훨씬 높았다. 소개글 TF-IDF는 소개글 단어만으로는 취향을 거의 맞히지 못했고, 이것이 1차 개선의 출발점이 됐다.

근거: [baseline_v1.md](../EDA/reports/baseline_v1.md)

## 1차 개선: 소개글에 태그·장르 정보 추가

**문제.** 소개글 TF-IDF의 Recall@10은 내부 검증 1.93%, 100개 제한 평가셋 3.58%였다. 소개글은 게임마다 길이와 쓰는 말이 제각각이라, 같은 장르의 게임도 단어가 겹치지 않는 경우가 많았다.

**바꾼 것.**
- 소개글은 단어 하나와 두 단어 묶음을 함께 쓰도록 먼저 고정했다.
- 태그·장르로 별도의 TF-IDF를 만들었다.
- 두 점수를 합칠 때 소개글 비중을 25%, 50%, 75%, 100%로 바꿔 비교했고, 50:50이 가장 높았다.

**결과.**

| 평가 | 바꾸기 전 | 바꾼 뒤 |
|---|---:|---:|
| 내부 검증 Recall@10 | 1.93% | 9.51% |
| 내부 검증 NDCG@10 | 0.012 | 0.053 |
| 100개 제한 평가셋 Recall@10 | 3.58% | 6.70% |

**판정: 채택.** 다섯 조건을 모두 통과했다. 소개글 단어보다 태그·장르가 취향을 더 잘 드러낸다는 점을 확인한 실험이다.

근거: [model_improvement_v2.md](../EDA/reports/model_improvement_v2.md)

## 2차 개선: 리뷰를 많이 쓴 사용자의 영향 줄이기 (활동량 보정 Item-KNN)

**문제.**
- Item-KNN은 "두 게임을 함께 좋아한 사람이 많을수록 비슷한 게임"으로 판단한다.
- 그런데 리뷰를 25개 이상 남긴 계정 0.64%가 함께 리뷰된 게임 조합의 62.6%를 만들었다.
- 그래서 소수의 활동량 많은 사용자가 게임 사이의 관계를 사실상 정하고 있었다.

**바꾼 것.**
- 게임 사이의 유사도를 계산할 때, 사용자마다 리뷰한 게임 수의 역수만큼 가중치를 줬다.
- 리뷰를 100개 쓴 사용자의 한 표는, 리뷰를 5개 쓴 사용자의 한 표보다 작게 반영된다.

**결과.**

| 평가 | 바꾸기 전 | 바꾼 뒤 |
|---|---:|---:|
| 내부 검증 Recall@10 | 40.08% | 40.93% |
| 내부 검증 NDCG@10 | 0.244 | 0.252 |
| 100개 제한 평가셋 Recall@10 | 11.19% | 10.86% |

**판정: 채택.** 모델 선택은 내부 검증으로만 하기로 정했고, 내부 검증에서 다섯 조건을 모두 통과했다.

**주의할 점.** 100개 제한 평가셋에서는 오히려 0.33%p 낮아졌다. 이 결과는 선택을 마친 뒤 확인했고, 규칙대로 결과를 보고 선택을 바꾸지 않았다. 따라서 "모든 데이터에서 더 좋아졌다"고 말할 수는 없다. 이후 대규모 평가셋(395,421명)에서는 Recall@10 29.49%로, 기본 Item-KNN 29.05%와 인기순 추천 21.24%보다 높았다.

근거: [model_improvement_v3.md](../EDA/reports/model_improvement_v3.md), [modeling_backlog.md](../EDA/docs/modeling_backlog.md)(활동 계정 집중 진단), [forgemaster_model_evaluation.md](../EDA/reports/forgemaster_model_evaluation.md)

## 3차 개선: 개발사·유통사·기능 분류 정보 추가

**문제.** 1차 개선 뒤에도 TF-IDF는 기능 분류(싱글 플레이, 협동 등), 개발사, 유통사 정보를 쓰지 않았다. 같은 개발사의 게임을 좋아하는 경우처럼, 이 정보로 설명되는 취향을 놓치고 있었다.

**바꾼 것.** 소개글 50%에, 태그·장르·기능 분류·개발사·유통사를 묶은 정보 50%를 합쳤다.

**결과.**

| 평가 | 바꾸기 전(1차 개선) | 바꾼 뒤 |
|---|---:|---:|
| 내부 검증 Recall@10 | 9.51% | 14.51% |
| 내부 검증 NDCG@10 | 0.053 | 0.083 |
| 100개 제한 평가셋 Recall@10 | 6.70% | 9.64% |

**판정: 채택.** 내부 검증과 100개 제한 평가셋 모두에서 올랐다. 다만 이 모델도 Item-KNN보다는 크게 낮아서, 최종 추천 모델로 쓰지는 않았다.

근거: [model_improvement_v3.md](../EDA/reports/model_improvement_v3.md)

## 4차 개선: 인기 게임 쏠림을 조절하는 선형 모델 (DAN)

**문제.**
- 3차 개선과 같은 실험에서 EASE라는 선형 추천 모델이 내부 검증 Recall@10 45.59%로 가장 높았다.
- 하지만 비인기 게임 점수가 기존 모델보다 낮아 채택 조건을 통과하지 못했다.
- 그래서 "전체 성능은 유지하면서 비인기 게임 성능은 떨어뜨리지 않는 모델"을 찾는 것이 목표였다.

**바꾼 것.**
- 학습에서 새로 뺀 계정을 써서, 후보를 고르는 단계와 확인하는 단계를 나눴다.
  - **고르는 단계:** 145개 설정을 비교했다. EASE와 그 변형, DAN, fSLIM, LambdaMART, 문장 임베딩 기반 콘텐츠 모델 등이 포함됐다.
  - **확인하는 단계:** 채택 조건을 통과한 설정 중 가장 높은 DAN 하나를 고정했다. 그리고 한 번도 쓰지 않은 계정 10,000명으로 기존 모델과 비교했다.
- DAN은 사용자의 리뷰량과 게임의 인기도를 반영해, 인기 게임으로 쏠리는 정도를 조절하는 선형 모델이다.

**결과 (확인 평가 10,000명).**

| 지표 | 기존 모델(활동량 보정 Item-KNN) | DAN |
|---|---:|---:|
| Recall@10 | 40.51% | 45.58% |
| NDCG@10 | 0.251 | 0.288 |
| 게임별 평균 NDCG | 0.0657 | 0.0705 |
| 비인기 게임 NDCG | 0.0451 | 0.0388 (13.9% 낮음) |

**판정: 미채택.** 전체 성능과 게임별 평균은 올랐지만, 비인기 게임 NDCG가 13.9% 낮아 4번 조건을 통과하지 못했다.

**주의할 점.**
- 비인기 게임 구간은 322명·291개 게임으로 작다. 이 구간에서 맞힌 사용자 수는 두 모델 모두 22명으로 같았다. 그래서 이 차이가 실제 서비스에서도 그대로 나타난다고 확정할 수는 없다.
- 확인 평가에 쓴 계정은 이전 단계(베이스라인~3차 개선)의 학습에는 쓰였다. 따라서 프로젝트 전체에서 한 번도 쓰지 않은 최종 시험은 아니다.

근거: [model_improvement_v4.md](../EDA/reports/model_improvement_v4.md), [backlog_experiments_v4.md](../EDA/docs/backlog_experiments_v4.md)

## 함께 시도했지만 채택하지 않은 것

| 실험 | 바꾼 것 | 결과 | 채택하지 않은 이유 |
|---|---|---|---|
| 참고할 게임 수·유사도 조정 (1차 개선과 같은 시기) | Item-KNN이 참고하는 비슷한 게임 수(100/200/500개)와, 함께 좋아한 사람이 적은 게임 쌍의 유사도를 낮추는 정도(3단계)를 조합해 9가지 비교 | 내부 검증 Recall@10 최고 41.55% | 게임별 평균 NDCG와 비인기 게임 NDCG가 낮아짐 |
| EASE (3차 개선과 같은 시기) | 게임 사이의 관계를 선형 회귀로 한 번에 학습하는 모델 | 내부 검증 Recall@10 45.59% | 게임별 평균 NDCG와 비인기 게임 NDCG가 낮아짐 |
| LambdaMART (3차 개선과 같은 시기) | 두 모델의 추천 후보를 모아 다시 순위를 매기는 모델 | 내부 검증 Recall@10 42.53% | 게임별 평균 NDCG와 비인기 게임 NDCG가 낮아짐 |

세 실험 모두 전체 점수는 올랐다. 하지만 높아진 점수가 주로 인기 게임에서 나와 채택 조건을 통과하지 못했다.
