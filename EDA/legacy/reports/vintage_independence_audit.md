# A–VintageDon 독립성 검증과 엄격한 사용자 분할 대안

확인일: **2026-11-07 (Asia/Seoul)**. 요구 기준은 **학습 사용자와 테스트 사용자가 실제 Steam 계정 수준에서 겹치지 않도록 분리 가능한가**이다. 모델 학습·데이터셋 교체는 수행하지 않았다.

## 1. 판정

**현재 공개 A를 학습에 모두 사용하고 VintageDon을 테스트에 사용하는 조합은 엄격한 사용자 비중복 평가로 인증할 수 없다.** A의 원 Steam ID와 리뷰 ID가 공개 파일에 남아 있지 않으며, 여러 필드가 함께 맞는 중복 의심 기록도 다수 발견됐다. 일치하지 않는 기록만 남겨도 독립성이 증명되지는 않는다.

이에 따라 VintageDon의 이전 **B 우선 후보** 판단은 **규모·Linux 게임 범위 측면의 후보**로 한정한다. 엄격한 신규 사용자 일반화의 주평가로는 **A 안에서 사용자를 먼저 학습/검증/테스트로 분리**하는 구성을 권한다. VintageDon은 사용자 독립성을 보장하지 않는 보조 외부 평가로 분리해 보고할 수 있다.

검증 범위:

- A 리뷰 **41,154,794행 전체**, VintageDon 리뷰 **1,048,148행 전체**를 읽었다.
- A 원본 컬럼, 배포자의 익명화·리뷰 ID 설명, VintageDon 수집 코드 및 공식 Steam API 문서를 확인했다.
- 비교 가능한 속성으로 중복 의심 기록을 집계하고, 날짜를 바꾼 대조 조건과 비교했다. 개인별 ID·사용자 연결표는 보고서/JSON에 저장하지 않았다.
- A 내부의 결정적인 80/10/10 사용자 분할안을 전체 자료에 적용하여 집계·무결성을 검사했다. **정답 선택, 실제 학습/테스트 파일 저장, 모델 학습은 하지 않았다.**

## 2. 원본 식별자: 직접 연결할 수 없는 이유

| 항목 | A | VintageDon | 결론 |
|---|---|---|---|
| 사용자 키 | 내부 정수 `user_id`: 0~14,306,063 | 문자열 `author_steamid`: 원 Steam ID | 직접 조인 불가 |
| 리뷰 키 | `review_id`: **모든 행에서 0부터 시작하는 행 번호와 같음** | Steam 원본 `recommendationid` | 직접 조인 불가 |
| 게임 키 | Steam App ID | Steam App ID | 게임 연결은 가능하며 공통 카탈로그 사용은 정상 |
| 리뷰 시각 | 날짜만 있음, 2010-10-15~2022-12-31 | 초 단위 생성/갱신 시각, 생성 범위 2010-10-19~2025-09-06 UTC | 시간 범위가 겹침 |

A의 [배포자 설명](https://www.kaggle.com/api/v1/datasets/view/antonkozyriev/game-recommendations-on-steam)은 사용자 ID가 전처리에서 익명화됐다고 명시한다. 배포자는 [사용자 ID 질의](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam/discussion/393322)에서 App ID 외 원래 ID가 없고 증가형 인덱스로 사용자 ID를 익명화했다고 설명했으며, [리뷰 ID 질의](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam/discussion/424705)에서도 리뷰 ID는 전처리 중 생성한 레코드 번호라고 밝혔다. 공개 파일 목록은 games, games_metadata, recommendations, users 네 개로 매핑 파일은 확인되지 않았다.

실제 대조에서도 A의 `review_id`와 숫자만 같은 VintageDon 원본 리뷰 ID가 **147,298개** 있었지만, 그 ID로 붙인 행 가운데 게임·작성일·라벨까지 같은 경우는 **0개**였다. 이 숫자 일치는 의미 없는 번호 충돌이며 원 리뷰 중복 수가 아니다.

VintageDon [수집 코드](https://github.com/vintagedon/steam-dataset-2025/blob/4a8b5703ca837ba8023621f8018d9fdf18598373/work-logs/06-full-data-set-import/collect_full_reviews.py)는 Steam의 공개 리뷰 API에서 수집한다. [공식 Steam 문서](https://partner.steamgames.com/doc/store/getreviews)는 원 리뷰 ID, Steam ID, 생성 시각, 긍정 라벨과 플레이 시간 필드를 구분한다. **다른 수집 패키지라는 사실과 다른 사용자·리뷰라는 사실은 별개다.** 확인한 수집 경로는 A 파일을 입력으로 삼지 않지만, 둘 다 같은 Steam 리뷰 모집단을 사용한다.

## 3. 전체 리뷰 속성 대조

VintageDon 중 A 최종 리뷰 날짜까지 작성된 **462,791행**을 대조했다. VintageDon의 초 단위 시각을 UTC 날짜로 내리고 A의 원본 날짜와 비교하면서 아래 조건을 단계적으로 추가했다.

1. 기본: App ID + A의 원본 날짜/VintageDon의 UTC 작성일 + 긍정/부정.
2. 플레이 시간 추가: A `hours`를 0.1시간 단위로 비교한다. VintageDon의 리뷰 시점 시간과 누적 시간을 **각각** 비교하고 분→시간 변환의 내림/반올림 두 경우를 허용한다. A의 1,000시간 포화 값은 이 조건에서 제외한다.
3. 상세 조건: 위 조건에 `helpful == votes_up`, `funny == votes_funny`를 추가한다.

A의 공개 1차 설명에서 `hours`가 리뷰 시점인지 수집 시점 누적인지 확인되지 않았다. 따라서 이 조건은 필드 의미를 가정한 동일성 판정이 아니라 **두 가능한 시간 필드에 대한 일치 민감도 검사**다. 날짜·라벨·시간·투표는 서로 다른 리뷰에서도 같을 수 있고, 같은 리뷰에서도 수집 시점 사이에 바뀔 수 있다.

A 날짜는 시각 없는 날짜로 저장돼 있다. 원 수집 시간대와 생성일/수정일 의미가 독립적으로 확인되지 않았으므로, VintageDon UTC 생성일과의 날짜 정렬도 조건부다. 이 불확실성은 불일치 기록을 독립으로 판단할 수 없는 추가 이유다.

| 조건 | 실제 작성일에서 A 후보가 있는 VintageDon 리뷰 행 | 날짜 +7일 대조 | 날짜 +365일 대조 |
|---|---:|---:|---:|
| 게임·날짜·라벨 | 126,087 | 26,959 | 10,903 |
| 위 조건 + 리뷰 시점 플레이 시간 호환 | 48,615 | 1,321 | 495 |
| 위 조건 + 누적 플레이 시간 호환 | 76,691 | 1,141 | 412 |
| 두 시간 필드 중 하나라도 호환 | 78,605 | 1,604 | 577 |
| 시간 필드 중 하나 + 두 투표 수까지 일치 | **45,772** | **401** | **197** |
| 위 상세 조건 + 두 투표 합계가 1 이상 | 23,272 | 32 | 7 |

날짜를 바꾼 뒤에도 A 날짜 범위 안인 행만 비교하므로 대조 조건의 분모는 각각 **460,964행 / 385,973행**으로 다르다. 이는 민감도 대조이며, 보정된 위양성률·중복 추정률·통계적 유의확률을 계산한 것이 아니다.

상세 조건을 만족하는 행은 VintageDon 원 사용자 **34,660명**에게서 나왔다. 같은 VintageDon 사용자와 같은 A 내부 사용자 후보가 서로 다른 게임에서 반복되는지도 확인했다.

| 같은 A 사용자 후보와 상세 조건이 맞는 서로 다른 게임 수 | VintageDon 사용자 수 |
|---|---:|
| 2개 이상 | **3,938** |
| 3개 이상 | **1,646** |
| 5개 이상 | **675** |

두 날짜 대조에서는 위 다중 게임 조건을 만족한 사용자가 모두 0명이었다. 따라서 **실제 사용자·리뷰 중복을 의심할 강한 징후**가 있다. 다만 원 식별자 연결이 없으므로 45,772건을 확정 중복 리뷰 수로, 3,938명을 확정 동일인 수로 발표하거나 연결표로 사용해서는 안 된다. **정확한 사용자 중복률과 무일치 사용자들의 독립성은 검증 불가**다.

## 4. 필터를 적용했을 때 남는 평가 가능 규모

동일 사용자–게임 쌍 중 같은 라벨 중복을 합치고 라벨 충돌 쌍을 제외했다. 입력 게임은 A에 리뷰가 있는 게임, 정답은 그중 A `linux=True`인 긍정 게임이다. 한 정답을 숨긴 뒤 입력 k개가 남을 수 있는 **잠재 사용자 수**이며, 실제 분할은 아니다.

| 조건 | 입력 ≥1 | 입력 ≥3 | 입력 ≥5 | 사용자 독립성 인증 |
|---|---:|---:|---:|---|
| 기존 VintageDon 조건 | 16,615 | 5,751 | 3,175 | 불가 |
| 정답 리뷰만 2023년 이후 작성으로 제한 | 8,623 | 2,892 | 1,502 | 불가 |
| 입력·정답 모두 2023년 이후 작성으로 제한 | 7,816 | 2,399 | 1,189 | 불가 |
| 기본 일치 후보가 하나라도 있는 사용자 전체 제외 | 10,406 | 2,966 | 1,422 | 불가 |
| 상세 일치 후보가 하나라도 있는 사용자 전체 제외 | 13,232 | 3,985 | 2,000 | 불가 |

원본 VintageDon의 생성 시점이 2023년 이후인 행은 **585,357행**이다. 2023년 이후 생성 리뷰는 양쪽 날짜가 호환되는 원 생성일을 정확히 나타낸다는 조건에서 A와 같은 원 리뷰 기록이 될 수 없다. A의 날짜 의미·시간대는 미확인이다. 또한 **이 사용자가 과거 다른 게임에 남긴 리뷰가 A에 있을 가능성은 남는다**. 최신 리뷰만 남기거나 의심 사용자를 제거하는 방법으로 엄격한 신규 사용자 평가를 인증할 수 없다. 위 집계는 입력이 정답보다 먼저 작성됐는지 검사하지 않으며, A+C 메타데이터 시점까지 고려한 완전한 시간순 예측 실험도 별도로 설계해야 한다.

## 5. 검증 가능한 대안: A 내부 사용자 분할

**현재 학습 자료를 유지하면서 엄격한 사용자 비중복 주평가를 만드는 실용적인 방법**이다. 공개 A 내부에서 일관된 사용자 ID를 기준으로 모든 리뷰를 사용자 단위로 한 번만 배정한다. 플랫폼 밖 동일인의 복수 계정까지 판별하는 것은 범위에 포함하지 않는다.

전체 A를 정리하니 동일 라벨 중복 **16행**, 라벨 충돌 **5쌍·10행**이 있었고, 이를 제거한 **41,154,768쌍·13,781,059사용자**로 분할 가능성을 확인했다. 기존 `(user_id, app_id)` 중복 행 21개에는 충돌 쌍도 포함되므로, 전체 제외 행 수 26과 정의가 다르다.

분할 함수는 고정 namespace `A-v28-user-disjoint-preview-v1`의 SHA256 일부를 salt로 사용한 uint64 SplitMix64와 100개 버킷이다. `<80 / <90 / 그 외`를 학습/검증/테스트에 배정한다. 행 순서·Python 프로세스별 난수 hash에 의존하지 않는다. 버전과 입력 해시를 고정해야 같은 배정이 유지된다.

| 분할 | 전체 사용자 | 정리된 리뷰 쌍 | 입력 ≥1인 잠재 평가 사용자 | 입력 ≥5인 잠재 평가 사용자 |
|---|---:|---:|---:|---:|
| 학습 약 80% | **11,025,468** | **32,927,160** | 평가에 사용하지 않음 | 평가에 사용하지 않음 |
| 검증 약 10% | 1,377,860 | 4,117,445 | **366,572** | **127,985** |
| 테스트 약 10% | 1,377,731 | 4,110,163 | **368,101** | **127,919** |

전체 정리된 행과 사용자가 정확히 한 분할에만 배정된다. 배정된 실제 행에서 각 분할의 고유 사용자 집합을 다시 만들고 세 조합의 교집합이 모두 0인지 검사했다. 따라서 **분할 간 같은 A 사용자 ID 및 사용자–게임 쌍 교집합은 0**이다. 역순으로 사용자 ID를 입력해도 같은 배정인지 검사했다. 원본 수준에서 한 사용자 ID에 묶인 리뷰를 통째로 분리한 결과다.

주의할 점:

- **사용자 분할을 먼저 하고**, 학습 사용자만으로 공동 긍정 행렬·인기도·활동 필터·이웃을 계산한다. 전체 A를 k-core 처리한 뒤 분할하는 방식은 피한다.
- Linux 공통 카탈로그 6,630개 중 이번 학습 분할에 리뷰가 있는 게임은 **6,624개**다. 입력 ≥1 테스트 집단의 잠재 정답 중 **4쌍**은 학습 리뷰가 없는 게임이다. 모델별로 임의 삭제하지 말고 사전에 공통 후보·신규 게임 처리 정책을 고정해야 한다.
- 검증·테스트 사용자별로 Linux 긍정 정답을 실제로 선택한 다음, 정답과 입력의 교집합이 0이고 최소 입력 수를 충족하는지 추가 검사해야 한다. 위 표는 정답 선택 전 규모다.
- A+C 게임 메타데이터는 별도 고정 정책으로 사용한다. 검증/테스트 사용자의 리뷰 라벨을 학습 집계나 설정 선택에 넣지 않는다.
- VintageDon을 이 학습 행렬에 추가하면 A–VintageDon의 사용자 독립성 문제를 다시 검증해야 한다.

**VintageDon을 반드시 주 테스트로 유지하려면:** 원 Steam ID가 보존된 대형 리뷰 원본을 학습 자료로 사용하여 VintageDon 테스트 사용자와 같은 Steam ID의 모든 학습 리뷰를 제거하고, 원 리뷰 ID·사용자–게임 중복·라벨 충돌을 확인할 수 있어야 한다. 해당 구성도 실제 원본 전체 검증이 필요하며, 현재 A 익명 자료를 섞어서는 이 보장을 할 수 없다. VintageDon 하나에서 사용자 분할하는 대안도 가능하지만 주 학습 규모가 크게 줄어든다.


- [독립성 전체 집계 JSON](vintage_independence_metrics.json): 입력 해시, 식별자 구조, 일치 조건·대조 조건, 시각 분포, 필터별 적격 수.

이 검증은 개별 사용자를 재식별하거나 추정 연결표를 저장하지 않는다. A–VintageDon 조합은 **인증 불가**, A 내부 사용자 분할은 **분할안 무결성 검증 완료**로 구분하며, 실제 프로젝트 데이터 채택·학습·최종 성능 평가가 끝났다는 의미는 아니다.
