# 중복을 막을 수 있는 학습·테스트 데이터셋 조합 조사

확인일: **2026-11-07 (Asia/Seoul)**. 범위는 기존 평가 후보 5개, 현재 A/B, 추가 학습·보유 후보, 제외한 미러/파생 그래프다. 기준은 **같은 원 Steam 계정이 학습·검증·테스트에 동시에 들어가지 않도록 실제 식별자로 분리 가능한가**이다. 동일인의 복수 Steam 계정은 이 기준에 포함하지 않는다.

> **후속 전수 EDA 정정:** artermiloff 원본 CSV도 Steam ID 정밀도가 손상돼 사용 제외다. **Kieran 원본→frank를 권장**하며, 정리·계정 제외·검증 예약 후 학습 98,857,701쌍이 남았다. 모호한 리뷰–App ID 연결 제거 후 frank 입력≥5 후보는 24,571명이다. [전체 원본 EDA와 실제 누수 증거](large_review_frank_eda.md).


## 1. 결론과 권장 조합

**정확한 원 Steam ID를 보존한 Kieran 원본으로 A를 교체하면, 외부 테스트 사용자 전체를 학습에서 제외하는 조합을 만들 수 있다. artermiloff는 원본 자체가 반올림돼 제외한다.** 현재 익명 A의 리뷰를 함께 섞으면 이 보장은 할 수 없다. A의 게임 카탈로그/Linux 표시와 C의 설명·태그는 고정한 메타데이터 정책 아래 계속 사용할 수 있다.

## 2. 검증 수준

- **전수 계산 완료:** B 프로필·리뷰, VintageDon 리뷰 전체, frank 리뷰 2,631,430행과 보유 11,285,290행의 필요한 열 전체. B/VintageDon/frank의 세 쌍에 대해 실제 계정 중복과 사용자 제외 후 교집합을 계산했다.
- **대형 원본 전수 EDA 완료:** Kieran 113,883,717행은 원 계정 제외 검증을 통과했다. artermiloff 127,572,881행은 원본 ID 손상으로 실패했다. 두 자료의 상세 품질·누수·규모는 후속 EDA를 따른다. forgemaster는 기존 100행 표본 수준이다.
- **출처·구조 확인:** 익명 자료와 보유 자료의 ID 정책, 명시적 라벨 유무, 공개 매핑 여부를 조사했다. Mendeley/UCSD의 기존 제한 표본 결론은 그대로 표본 범위로 제한했다.

분리 가능성과 품질 인증은 다르다. `SteamID`라는 열 이름만으로 통과시키지 않고 원본 숫자 보존, 자료 간 원 리뷰 ID의 소유자 일관성, 라벨 변경, 누락 ID를 함께 확인한다.

## 4. 새로 확인한 전체 자료 결과

### 4.1 기존 B의 원 ID 연결

- 프로필 88,310행 → 내부 별칭 87,626개. 한 별칭이 여러 Steam ID로 연결되는 충돌은 **0개**였다.
- 리뷰 사용자 25,458명 중 **25,454명**을 명시적 `steam_id`로 연결했다. 매핑 없는 **4명·15행**은 격리했다.
- 숫자 17자리인 별칭과 명시적 Steam ID가 서로 다른 프로필 별칭이 **16개** 있었다. 숫자 모양만 보고 원 Steam ID로 추정하면 안 된다.
- 매핑·중복 정리 후 **58,416쌍·25,454계정**이며 리뷰 입력 평가 잠재 사용자는 **9,285명(≥1), 1,615명(≥5)**이다. 기존 9,287명/1,616명과는 미매핑 사용자 제외 조건이 다르다.
- 원 리뷰 ID는 없지만, 원 사용자 ID를 통째로 학습에서 제외하면 같은 계정의 어떤 게임 리뷰도 학습에 남지 않는다.

### 4.2 frank 리뷰: 외부 테스트 후보로 상향

원본 Hugging Face commit **`75694cc07a6cdc69f48f9c316ca1e3e38a3f0f89`**에 고정하고 HTTP Range로 필요한 열만 **모든 행**에서 읽었다. 리뷰 845MB·보유 505MB 원본 파일 전체를 받거나 전체 원본 SHA256를 독립 검증한 것은 아니다. 전송량은 리뷰 **90,157,518 B**, 보유 **35,695,461 B**였으며 내려받은 열별 투영 파일은 별도 SHA256를 기록했다.

|---|---:|---:|
| 원본 행 | 2,631,430 | 1,048,148 |

frank는 같은 라벨 중복 12행, 라벨 충돌 1쌍·2행을 제외했다. 원본 사용자 수 1,336,110명과 정리 후 수는 다르다. 관측된 앱당 최대 리뷰 수는 **100개**, 사용자별 고유 리뷰 게임 수 중앙값은 **1개**다. 전체 수집 방법이 카드에 자세히 설명돼 있지 않고 앱당 표집/도움됨/언어 등의 편향은 미해결이므로, 큰 적격 수만으로 대표성이나 성능 우위를 단정하지 않는다.

### 4.3 frank 보유 이력: 큰 행 수의 해석 수정

보유 **11,285,290행은 중복 사용자–게임 행이 0개**지만, 사용자 수는 **786명**뿐이다. 사용자별 고유 보유 게임 수 중앙값이 **12,674개**인 매우 큰 라이브러리 집단이다. 리뷰 사용자와 연결되는 보유 사용자는 **305명**, 기존 A 게임 공간에서 보유 입력과 Linux 긍정 리뷰 정답을 함께 갖춘 사용자는 **143명**이다. 실제 플레이 양수 입력도 이 조건에서 143명이다.

따라서 이 보유 자료를 수백만 사용자의 긴 이력 학습 자료로 해석하지 않는다. 리뷰 기반 87,573명 평가와 보유 기반 143명 평가는 다른 프로토콜이다.

VintageDon–frank의 **원 리뷰 ID 교집합은 197,548개**이며, 그 ID를 대조했을 때 사용자·게임 ID가 다른 경우는 **0개**였다. 이 검사는 단순히 17자리 형태만 같은지 확인하는 것보다 강한 원 식별자 호환성 근거다. 라벨이 달라진 345개 원 리뷰는 수정/수집 시점 차이일 수 있으므로 같은 리뷰를 독립된 새 평가 기록으로 세지 않는다. 원 리뷰 ID 대조는 정리 전 원본 열, 사용자–게임 대조는 충돌 정리 후 열을 사용하므로 두 교집합 수가 다르다.

테스트 쪽에서 입력 ≥1이 가능한 사용자 전체를 예약하고, **그 계정의 모든 학습 게임**을 제외한 예시다. 입력과 정답으로 실제 나누거나 학습 파일을 채택한 단계는 아니다.

| 학습 → 테스트 | 예약 테스트 사용자 | 제외한 학습 리뷰 쌍 | 남은 학습 리뷰 쌍 | 제외 후 사용자 교집합 |
|---|---:|---:|---:|---:|
| frank → VintageDon | 16,615 | **241,565** | **2,389,851** | **0** |
| VintageDon → frank | 87,573 | 149,523 | 898,616 | **0** |
| frank → 매핑 B | 9,285 | 2,011 | 2,629,405 | **0** |
| VintageDon → 매핑 B | 9,285 | 526 | 1,047,613 | **0** |
| 매핑 B → frank | 87,573 | 615 | 57,801 | **0** |
| 매핑 B → VintageDon | 16,615 | 46 | 58,370 | **0** |

사용자–게임 교집합도 모두 0이며, 원 리뷰 ID가 양쪽에 있는 frank↔VintageDon은 제외 후 **원 리뷰 ID 교집합도 0**을 확인했다. B는 원 리뷰 ID가 없어 그 추가 검사는 적용하지 않았다.

첫 행은 **바로 재현 가능한 분리 방식 검증용 조합**이다. 다만 239만 학습 리뷰는 현재 A보다 훨씬 작으므로 대형 A 대체 최종안으로 권하는 것은 아니다. 또한 이 조건의 VintageDon 잠재 정답 4,036쌍은 남은 frank 학습에 해당 게임 리뷰가 없고, 입력·정답 모두 학습 리뷰 게임으로 제한하면 잠재 사용자는 **13,312명**이다. 단순 계정 교집합 0만 확인하고 Item-KNN 지원 범위까지 충분하다고 해석해서는 안 된다.

## 6. 최종 구성 절차

1. **원본 고정:** 버전/commit/해시, 파일명과 App ID 대응, 라벨·시각·라이선스를 고정한다. 사용자 ID와 원 리뷰 ID는 처음부터 문자열로 읽고 float 변환을 금지한다. 미확인 ID는 격리하며 이름이나 플레이 시간으로 원 계정을 추정하지 않는다.
2. **평가 조건 고정:** 공식 Linux 카탈로그, 입력 최소 수, 숨길 긍정 정답 수, 리뷰/보유 프로토콜, 데이터 시점을 고정한다. A+C는 텍스트·태그·플랫폼 중심 메타데이터 정책을 정하고 외부 리뷰 집계 평판을 학습 피처에 자동 추가하지 않는다.
3. **사용자부터 분리:** 대형 단일 원본이면 동일 Steam ID의 모든 행을 하나의 학습/검증/테스트 분할에 배정한다. 여러 원 ID 자료를 합치면 **하나의 공통 namespace/시드**로 같은 Steam ID가 모든 출처에서 같은 분할에 가도록 한다. 출처마다 다른 seed나 접두사로 계정을 나누면 안 된다.
4. **외부 테스트면 전체 계정 제외:** 선택된 테스트 사용자 집합 `U_test`를 동결한다. 남은 학습 원본에서 검증 사용자 `U_val`을 정하고, **모든 학습 원천에서 `U_test ∪ U_val`에 속한 계정의 모든 행을 제외**한다. 테스트 쪽 입력 리뷰를 작성한 사용자도 같은 예약 사용자다. 일치하는 정답 리뷰만 지우는 방식으로는 부족하다.
5. **다중 신호도 같은 제외 적용:** 보유/플레이·친구 그래프·유사도 캐시·전처리 집계에도 같은 사용자 제외를 적용한다. 친구 그래프는 예약 사용자가 어느 끝점에라도 있으면 학습 그래프에서 제외한다. 원 ID가 없는 익명 A/Mendeley를 추가하면 다른 자료와의 비중복 보장이 깨진다.
6. **분할 안에서 정리·학습:** 원 리뷰 ID, 사용자–게임 중복과 라벨 변경을 검사한다. 테스트 라벨을 학습 원본 라벨로 덮어쓰지 않는다. 학습 쪽의 여러 스냅샷은 사전에 정한 최신 갱신 시각 우선/충돌 제외 규칙으로 처리한다. 인기도·k-core·이웃·가중치는 학습 사용자만으로 계산하고 설정은 검증셋에서 선택한다.
7. **테스트 사용자 내 입력/정답 분리:** 같은 사용자에서 입력과 숨김 Linux 긍정 게임이 겹치지 않도록 저장한다. 긍정·부정 입력 게임 모두 추천 목록에서 제외한다. 입력 없는 사용자나 이웃 없는 게임을 모델별로 몰래 삭제하지 않고 공통 평가 집단과 대체 추천 규칙을 유지한다.
8. **최종 파일을 다시 읽어 검사:** 학습/검증/테스트의 원 사용자 교집합, 원 리뷰 ID 교집합(제공 시), 사용자–게임 교집합이 0인지 확인한다. 테스트 입력–정답 교집합도 0이어야 한다. 최소 입력 수·Linux 긍정 라벨·모델 지원 범위와 제외 수를 함께 기록한다. 여러 외부 테스트셋을 쓰면 그 예약 사용자 합집합을 모든 학습 원천에서 제외한다.

이 절차는 신규 사용자 일반화를 위한 것이다. 소유 시점·카탈로그 시점과 사용자별 입력이 정답보다 먼저 발생했는지를 따로 검사하지 않으면 시간순 미래 예측 실험으로 부르지 않는다.

## 7. 원본 선택 시 실행 전 확인할 점

- **artermiloff:** 전체 실측 **127,572,881행·79,994 CSV**. 스키마·숫자 파일명은 일관되지만 원 계정 ID 자체가 float64 반올림으로 손상됐다. 저장 ID 형식 검사는 통과해도 실제 소유자와 달라 계정 제외에 사용할 수 없다. 전수 EDA에서 이전 표본 기반 판정을 뒤집었다.
- **Kieran:** 전체 113,883,717행 검사. 리뷰–게임 연결 충돌 ID 332,865개와 자료 간 추가 3개, 라벨 충돌 72쌍을 격리했다. 평가 계정 제외·검증 예약 후 학습 98,857,701쌍을 검증했다. 699MB 도움됨 필터 부분집합은 섞지 않았다.
- **forgemaster:** 카드상 15,437,471리뷰·6,976,390사용자·8,183게임. 원 사용자 ID는 사용할 수 있으나 A보다 게임/리뷰 범위가 작고 전체 Linux 커버리지 미측정이다. 카드의 시간 단위 설명과 API 분 단위는 별도 확인하고 첫 기준선은 이 단위를 선호 라벨로 사용하지 않는다.
- **익명 단일 원본:** Mendeley의 리뷰/보유 자료를 함께 쓸 때는 전 파일에서 익명 키가 일관되는지 전체 검사한다. SteamGameRecommender는 BFS 폴더 사이 사용자 반복을 먼저 통합한다. 이름이 같거나 ID 숫자가 다르다는 사실은 원 계정 분리 증거가 아니다.
- **UCSD v2:** 표본에서 추천 라벨이 없었다는 사실만으로 전체 파일에 없다고 단정하지 않는다. 2차 파서가 누락 `recommended`를 `False`로 바꾼 예시는 원본 부정 라벨의 증거가 아니다. 원 계정이 확인되는 행과 명시적 라벨이 실제 존재하는 행의 교집합을 전수 확인하기 전에는 본 실험에 넣지 않는다.
- **Condensing Steam:** 원 ID 연결 구조는 가능하지만, 자료는 2013~2014년 보유/플레이 중심이다. 데이터 라이선스/조건이 공개 배포 메타데이터에 명시되지 않았다. 논문 저작권 표시를 데이터 사용 허가/금지로 바꾸어 해석하지 않는다.
