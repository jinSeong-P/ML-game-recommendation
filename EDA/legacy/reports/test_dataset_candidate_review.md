# 외부 평가 후보 전체 검토 및 A 대체 학습 자료 비교

> **후속 전수 EDA 정정:** artermiloff 원본도 Steam ID가 float64 반올림으로 손상되어 사용 제외다. Kieran 원본→frank만 원 계정 제외 검증을 통과했다. 아래는 선행 검토 기록이며 최신 근거·98,857,701쌍 학습 규모·24,571명 평가 후보는 [전수 EDA](large_review_frank_eda.md)를 따른다.

확인일: **2026-11-07 (Asia/Seoul)**. 대상은 [기존 후보 문서](../docs/test_dataset_candidates.md)의 5개 후보 전체와, A 대체 검토 중 추가로 찾은 자료다. 사용자의 우선순위는 **품질·평가 타당성과 큰 규모**, 학습 신호는 **긍정/부정 리뷰 및 보유/플레이 이력**이다.

> **독립성 후속 검증:** A·VintageDon 전체 리뷰를 대조했고 상세 속성이 맞는 중복 의심 리뷰 45,772행을 확인했다. A 원 ID 매핑이 없어 **현재 A 학습 + VintageDon 테스트를 엄격한 신규 사용자 비중복 평가로 인증할 수 없다**. 아래의 B 우선 후보 판단은 규모·게임 범위에 한정하며, 엄격한 주평가는 A 내부 사용자 분할을 권한다. [독립성 검증·분할 대안](vintage_independence_audit.md).

> **학습 자료 교체까지 포함한 후속 조사:** [전체 학습·테스트 조합 보고서](dataset_train_test_combinations.md)에서 원 Steam ID 자료끼리의 사용자 전체 제외 방법을 정리했다. frank 리뷰 2,631,430행·보유 11,285,290행의 필요한 열 전체를 새로 집계했고, 리뷰 테스트 잠재 **87,573명(입력≥1), 24,577명(≥5)**을 확인했다. 보유 자료는 786명에 집중됐다. 기존 B 리뷰 사용자도 25,454명을 원 Steam ID로 연결했다. 아래의 frank 미측정 설명은 이 후속 결과로 갱신한다.

## 1. 확인 범위와 현재 판단

- **B와 VintageDon은 리뷰 전체 집계**를 수행했다. VintageDon의 공개 CSV ZIP을 다운로드하고 배포 API의 MD5와 일치함을 확인했다.
- **Mendeley·forgemaster·UCSD v2·100 Million+는 원본의 제한된 앞부분**을 확인했다. 100 Million+는 원본과 미러의 일부 ID도 직접 대조했다. 전체 사용자 분포를 측정한 것으로 해석하지 않는다.
- **B 보완:** VintageDon은 같은 기준으로 B보다 많은 평가 사용자와 훨씬 넓은 Linux 정답 게임 범위를 제공한다. Mendeley와 forgemaster도 필요한 필드를 확인했으므로 전체 집계 후보로 유지한다.
- **A 대체 최신 판정:** **Kieran 100 Million+ 원본→frank를 권장**한다. 전체 검사·계정 제외·검증 예약 후 학습 98,857,701쌍을 확인했다. **artermiloff 원본 자체도 ID가 이미 반올림돼 제외**한다. 아래 표본 기록의 원 ID 보존 추정은 전수 대조 결과로 정정했다. float64 HF 미러도 사용하지 않는다.
- 학습 데이터 교체, 고정 평가 분할 생성, 모델 재학습·성능 비교는 수행하지 않았다.

## 2. B와 VintageDon: 같은 기준의 전체 리뷰 집계

**정의:** `(user_id, app_id)`를 중복 제거한다. 동일 쌍에 상반된 라벨이 있으면 그 쌍을 제외한다. 입력에는 긍정·부정 리뷰를 모두 허용한다. 정답은 **A에 리뷰가 존재하고 A `linux=True`인 6,630개 App ID** 중 긍정 리뷰다.

사용자가 가진 서로 다른 입력 가능 게임 수가 `k+1` 이상이고 그 안에 Linux 긍정 게임이 있으면, 그 게임 하나를 숨긴 뒤 입력 `k`개 이상을 남길 수 있다. 아래는 그 **잠재 적격 사용자 수**이며 실제 난수 분할 결과가 아니다. 대표 비교에서는 입력도 A에 리뷰가 있는 게임으로 제한했다.

| 동일 라벨 중복으로 제거된 행 | 874 | 7 |
| 라벨 충돌로 제외한 사용자–게임 쌍 | 0 | 1 |
| 정리 후 사용자–게임 쌍 | 58,431 | 1,048,139 |
| 고유 사용자 | 25,458 | 701,883 |
| 서로 다른 App ID | 3,682 | 117,311 |
| 사용자별 고유 리뷰 게임 수 p25 / 중앙값 / p75 / p90 | 1 / 1 / 3 / 5 | 1 / 1 / 1 / 2 |
| 게임 1개만 리뷰한 사용자 비율 | 53.14% | 84.12% |

VintageDon은 입력 1개 기준 사용자 약 **1.79배**, 잠재 정답 게임 약 **5.31배**다. 그러나 사용자당 이력의 전반적인 밀도는 낮다. 큰 총량이 모든 사용자에게 긴 이력을 준다는 뜻은 아니다. App ID 총량에는 게임 외 DLC·소프트웨어 등이 포함될 수 있다.

**해석 주의:** 잠재 정답 쌍은 적격 사용자에게 가능한 정답을 모두 모은 수다. 모두 동시에 숨겨도 입력 수가 유지된다는 뜻은 아니다. 사용자당 정답 하나를 숨기는 분할을 만들면 실제 정답 쌍은 적격 사용자 수와 같아진다. 기존 보유 이력 기반 **15,294명 / 24,704쌍**과는 다른 프로토콜이다.

재현 코드: [audit_review_candidates.py](../scripts/audit_review_candidates.py). 입력 SHA256·분포·입력 범위별 집계: [JSON 결과](test_dataset_review_history_metrics.json). 개별 사용자 ID는 결과 파일에 저장하지 않았다.

## 3. 기존 후보 5개별 검토

### 3.1 Mendeley — Steam app/player data

[공식 v1·DOI 10.17632/89yxn7hmpt.1](https://data.mendeley.com/datasets/89yxn7hmpt/1). 2024-09-24 공개, **CC BY 4.0**. 공식 API에 등록된 크기는 리뷰 **2,142,608,287 B**, 앱 정보 21,672,948 B, 태그 43,413,814 B, 사용자 정보 39,104,055 B다. 공개 파일 리다이렉트와 파일 크기·Range 접근을 확인했다.

리뷰 앞 **4 MiB**의 제한된 표본에서 503개 App ID와 **12,668개 완전한 리뷰**를 확인했다. `steamid`, `voted_up`, 작성/갱신 시각, 플레이 시간이 있고, 표본의 익명 사용자 ID 460개가 여러 앱에 반복돼 게임 간 연결 가능성이 직접 관측됐다. 경계의 불완전한 리뷰는 제외했다. ID와 리뷰 키는 익명화돼 A의 내부 ID와 직접 연결할 수 없다.

**판단:** 리뷰와 보유 목록을 함께 다룰 수 있어 **B 보완용 우선 집계 후보**다. 전체 리뷰 행 수·고유 사용자 수·적격 Linux 사용자 수는 미측정이다. 2GB라는 용량만으로 A의 4,115만 리뷰보다 크다고 해석할 수 없다. 표본에는 2022년 말 이전 리뷰가 다수 있어 A와 같은 Steam 원천·시점이 겹치며 독립성 검증이 필요하다. 앞부분 표본으로 전체 이력 분포나 날짜 범위를 추정하지 않는다.

### 3.2 forgemaster — Steam Reviews Dataset

[Kaggle 원본](https://www.kaggle.com/datasets/forgemaster/steam-reviews-dataset). 공개 API에서 **v1·CC0**, CSV 11개, 합계 **5,318,015,798 B**를 확인했다. 카드가 직접 제시하는 규모는 **15,437,471리뷰 / 6,976,390사용자 / 8,183게임**이다. 기존 문서의 제3자 인용 수치를 배포자 카드에서도 확인했으나 전체 파일 재집계값은 아니다.

한 CSV의 앞 **65,536 B / 100행 표본**에서 17자리 숫자 토큰의 `steamid`, `appid`, `voted_up`의 true/false를 확인했다. 처음부터 사용자 ID를 문자열로 읽으면 원문의 숫자 표기를 보존할 수 있다.

**판단:** B용 중대형 후보로 유지한다. 카드상 평균 약 2.21리뷰/사용자이며 전체 다중 리뷰 분포와 Linux 정답 사용자 수는 미측정이다. 카드 기준으로 A보다 리뷰·사용자·게임 범위가 모두 작아 **규모를 늘리기 위한 A 교체 근거는 부족**하다. 원문 리뷰 텍스트·실제 Steam ID 등 부가 필드가 필요한 실험에는 별도 가치가 있다.

### 3.3 Kieran — 100 Million+ Steam Reviews / HF 미러

[Kaggle 원본](https://www.kaggle.com/datasets/kieranpoc/steam-reviews), [adde023 HF 미러](https://huggingface.co/datasets/adde023/steam-reviews). Kaggle API에서 **v2·MIT·2023-12-10 갱신**, CSV 2개를 확인했다. 주 파일 `all_reviews/all_reviews.csv` 원문은 약 **42.49GB**, `weighted_score_above_08.csv`는 약 699MB다. 카드와 HF 메타데이터의 리뷰 수는 **113,883,717개**, HF Parquet 크기는 약 **23.46GB**다. 파일 크기는 전체 다운로드 실측이 아닌 배포 메타데이터다. ZIP 첫 **256 KiB**만 부분 해제한 200개 완전한 원본 행에서 사용자 ID의 17자리 숫자 표기와 명시적 True/False 라벨을 확인했다.

HF에는 `author_steamid`, `appid`, `voted_up` 등이 **float64**로 저장돼 있다. 리뷰 ID로 대응한 원본–미러 첫 100행 중 **93행의 사용자 ID가 달랐다**. SteamID64 크기의 float64 간격은 16이므로 원래 서로 다른 ID가 같은 값으로 합쳐질 수 있다. 나중에 문자열로 바꾸어도 이미 소실된 비트는 복원되지 않는다. 손상 위험이 표본에서 실제 차이로 확인된 것이다. 미러의 **CC BY-NC 4.0** 표기는 원본 MIT와도 다르므로 같은 이용 조건이라고 가정하지 않는다.

**판단:** 리뷰 수가 A의 약 **2.77배**이고 원문 ID·라벨이 표본에서 확인돼 **A 대체를 우선 검증할 원본 후보**다. 전체 사용자 수·게임 수·다중 게임 이력·중복·라벨 충돌·Linux 정답 범위는 미측정이다. HF 미러는 사용자 단위 학습/평가에 보류한다. 작은 `weighted_score_above_08.csv`는 도움됨 점수로 고른 부분집합이므로 전체 리뷰를 대신하는 기본 학습 자료로 삼지 않는다. 게임 메타데이터와 Linux 플래그는 별도 카탈로그 조인이 필요하다.

### 3.4 VintageDon — Steam Dataset 2025

[고정 배포 Zenodo 17266923](https://zenodo.org/records/17266923), [공식 데이터 사전](https://github.com/vintagedon/steam-dataset-2025/blob/main/steam-dataset-2025-v1/DATA_DICTIONARY.md). 배포 API로 확인한 실제 DOI는 **10.5281/zenodo.17266923**이다. 저장소 일부 문서의 `17286923`과 다르다. 데이터 **CC BY 4.0**, 코드 MIT.

CSV 패키지 **320,368,878 B**를 내려받고 API MD5 `d56d18cc77e08b4ffc8ce84952b7319b`와 대조했다. `reviews.csv` 전체를 읽어 위 2절 수치를 계산했다. `author_steamid`는 17자리 문자열로 보존했고, 사용자·앱·라벨 결측 및 리뷰 ID 중복은 0건이었다. 리뷰 작성 시각은 **2010-10-19~2025-09-06 UTC**, 언어 30종이다.

**문서 정정:** 초기 카드에는 앱당 10개 표집 설명이 있으나, [최종 수집 코드](https://github.com/vintagedon/steam-dataset-2025/blob/4a8b5703ca837ba8023621f8018d9fdf18598373/work-logs/06-full-data-set-import/collect_full_reviews.py)는 `num_per_page=100&language=all`로 요청하며 앱별 cursor 순회를 하지 않는다. 실제 리뷰 파일도 App ID당 최대 100개였다. 따라서 **전 리뷰 수집본이 아니며 영어 전용도 아니다**.

**판단:** B의 Linux 게임 범위 보완을 실측으로 뒷받침하는 후보다. 다만 [후속 독립성 검증](vintage_independence_audit.md)에서 원 ID 연결 불가와 중복 의심 징후를 확인했으므로, **현재 A에 대한 엄격한 신규 사용자 테스트셋 채택은 권하지 않는다**. 보조 외부 평가에 사용한다면 사용자 중복 불확실성을 명시해야 한다. 앱당 제한 표집과 짧은 사용자 이력의 편향도 남아 있다. A보다 리뷰가 훨씬 적으므로 A의 주 학습 이력을 대체할 자료로는 권하지 않는다. 최신 앱 유형·메타데이터 보강에는 별도 가치가 있다.

### 3.5 UCSD — Steam v2

[UCSD 공식 페이지](https://cseweb.ucsd.edu/~jmcauley/datasets.html#steam_data)는 **7,793,069리뷰 / 2,567,538사용자 / 15,474아이템**을 기재한다. [공식 리뷰 gzip](https://cseweb.ucsd.edu/~wckang/steam_reviews.json.gz)은 **1,338,063,248 B**이며, v1 Australian 리뷰/보유 파일과는 별도다. 공식 Steam 데이터 설명에는 명시적 재사용 라이선스가 없다.

앞 **1 MiB 압축 바이트**를 제한 해제하고 `ast.literal_eval`로 **4,703개 완전한 행**을 읽었다. `product_id`, 텍스트, 날짜, 플레이 시간은 있지만 이 표본에서 `recommend`·`recommended`·`voted_up`는 없었다. `user_id`는 **1,978행(42.06%)**에만 존재했다. 표본의 한계를 전체 파일 결측률·전체 스키마 확정으로 확대하지 않는다.

gzip 끝의 ISIZE는 **4,273,159,526 (mod 2^32)**로 B manifest의 `steam_new.json` 크기와 일치하며, B의 기존 부분 표본 기록과 구조도 일치한다. B에 이미 포함된 파일의 재포장일 가능성이 높지만 전체 해시 동일성은 미검증이다.

**판단:** 명시적 Linux 긍정 정답용으로는 **보류**한다. 표본에서 확인되지 않은 긍정 라벨을 보유/플레이와 같은 의미로 보충할 수는 없다. 무라벨 리뷰 상호작용을 암묵적 신호로 쓰는 별도 실험은 가능하지만, 현재 A보다 작고 독립된 새 원천도 아니어서 A 교체의 우선순위는 낮다.

## 4. A를 대체할 학습 자료에 요구할 조건

A는 **41,154,794리뷰 / 13,781,059사용자 / 37,610 리뷰 게임**이며 사용자별 리뷰 중앙값은 1개다. 기존 긍정 k-core(사용자 ≥5·게임 ≥10 반복 적용)는 **1,621,480사용자 / 26,064게임 / 17,986,052쌍**이다. 따라서 새 후보도 동일 조건으로 정리한 뒤 **동일 사용자의 서로 다른 게임 수와 게임 간 공동 긍정 연결**을 비교해야 한다. A에는 원래 SteamID 대신 내부 정수 ID가 있으므로 외부 사용자와의 실제 동일인 여부를 직접 판정할 수 없다.

리뷰 기반 대체 후보는 다음을 만족해야 한다.

1. 원문 사용자 ID를 문자열/정확한 정수로 보존하고 게임 App ID와 명시적 라벨을 제공할 것.
2. 중복·충돌 제거 뒤에도 충분한 다중 게임 사용자와 Linux 양성 정답이 남을 것. 원문 리뷰 수만 비교하지 않는다.
3. 최신 게임의 추가분과 A/C 카탈로그 밖 게임을 구분하고, 공식 Linux 여부와 메타데이터를 새 기준일에 고정할 것.
4. 전체 원본을 고정 버전·해시로 보관하고, 학습/검증/테스트 사용자를 겹치지 않게 분리할 수 있을 것.

**A와 B를 함께 재설계할 때:** 원래 Steam ID가 온전히 남은 대형 리뷰 원본 하나에서 먼저 사용자를 학습/검증/테스트로 분리하면 사용자 비중복을 직접 검증할 수 있다. 이후 각 검증/테스트 사용자 내에서 입력과 Linux 양성 정답 게임을 분리한다. A 내부 ID와 외부 익명 ID가 다르다는 이유만으로 현재 외부 후보를 '학습에 없던 실제 사용자'라고 단정해서는 안 된다.

보유/플레이 이력은 별도 암묵적 학습 신호로 쓸 수 있다. **보유는 호감과 같지 않고 플레이 시간은 명시적 긍정/부정이 아니다.** ALS/BPR 또는 공동 플레이 이웃의 학습에는 적합할 수 있으나, 미관측 게임을 실제 부정으로 간주하지 않는다. 구매/플레이 회수 평가와 긍정 리뷰 회수 평가는 구분한다.

위 보유 자료의 규모는 리뷰 수와 합산하지 않는다. 특히 친구 관계는 사용자–게임 선호 관계가 아니다. 보유/플레이 자료를 채택하면 양성의 정의(예: 보유, 일정 플레이 시간)와 가중치를 학습 전에 고정해야 한다. 플레이 시간 문턱은 검증셋에서 정하고 최종 테스트셋으로 조정하지 않는다.

artermiloff는 원본 [카드 API](https://www.kaggle.com/api/v1/datasets/view/artermiloff/steam-games-reviews-2024)·[파일 목록 API](https://www.kaggle.com/api/v1/datasets/list/artermiloff/steam-games-reviews-2024)와 파일 표본을 확인했다. 다만 조사 중 요청 경로에 따라 카드 API가 HTTP 404 또는 200을 반환했으므로 재현 시 접근 안정성도 점검해야 한다. 약 14.23GB는 API 제공 총량이며 압축 해제 후 필요 저장 공간과 동일하다고 가정하지 않는다.

추가 검색에서 발견한 [Steam Co-Review Network](https://huggingface.co/datasets/lukeslp/steam-co-review-network)는 원시 리뷰가 아닌 **25,996개 게임·861,232개 링크의 가지치기된 집계 그래프**다. 사용자별 입력/정답 분할을 재구성할 수 없어 A의 원시 학습 자료를 대체할 후보에서는 제외한다. 위 artermiloff 원본과 이 파생 그래프를 같은 데이터로 취급하지 않는다.

## 5. 재현 및 남은 채택 조건

저장소 루트 PowerShell 기준:

```powershell
EDA/.venv/Scripts/python EDA/scripts/audit_review_candidates.py --vintage-zip EDA/data/raw/candidate_review/VintageDon/steam_dataset_2025_csv_package_v1.zip
```

원본 ZIP은 [Zenodo 고정 버전](https://zenodo.org/records/17266923)의 `steam_dataset_2025_csv_package_v1.zip`이다. 원본은 Git 제외 경로에 보관하며, 재현 스크립트는 기존 A/B 전처리 Parquet도 사용한다. 출력에는 모든 입력의 SHA256가 포함된다. 스크립트의 적격 수·중복/충돌 처리·ID 보존 로직은 독립적인 읽기 검토를 거쳤다.

미측정 후보의 전체 이력 집계, 학습/평가 원천 중복 감사, 고정 분할 및 성능 검증이 끝나야 최종 채택을 결정할 수 있다. 현재 결과는 자료의 구조·접근성·일부 전체 집계를 검토한 것이며 추천 성능 우위의 증거는 아니다.
