# B · bundle_data.json — 상품 번들 묶음 정보

## 1. 무엇을 나타내나?
- **원본**: B/`bundle_data.json` (약 834 KB).
- **한 줄**: 여러 게임·상품을 포함하는 **판매 번들**의 정보.
- **형식**: 줄 단위 Python 딕셔너리 리터럴. `ast.literal_eval`로 읽음.
- **중요**: 번들에 함께 묶인 게임들은 **함께 구매되었거나 함께 좋아했다는 뜻이 아니다**. 추천 정답이나 사용자-게임 양성 상호작용으로 사용하지 않기.

## 2. 확인된 구조와 파생 컬럼
전처리에서 직접 사용한 원본 키:
- 번들 수준: `bundle_id`(번들 식별자), `bundle_name`(번들 이름), `items`(상품 목록)
- 포함 상품: `items[*].item_id`(게임/상품 ID 문자열)

`B_bundle_items.parquet`에는 `bundle_id, bundle_name, item_id_raw, item_id` 4열로 펼친다. 이 중 `item_id_raw`(원문 보존 이름), `item_id`(숫자화)는 전처리 산출물. 실제 원본의 그 밖의 필드는 분석 코드에 사용되지 않아 **전체 원본 필드 여부는 미확인**이다.

## 4. 사용 가능성과 한계
- 상품 묶음에서 게임 카탈로그가 어떻게 함께 소개되는지 분석하는 보조 정보로는 의미가 있다.
- 개별 사용자의 취향·선호를 입증하지 못하며, 사용자별 보유 목록과 같은 데이터가 아니다.
- DLC·사운드트랙 등 게임 외 상품이 있을 수 있다. 숫자 변환 및 A/C 카탈로그 매칭을 거쳐야 한다.
- 공식 Linux 추천 베이스라인에서 **필수 피처는 아님**. 팀이 정한 두 방식(TF-IDF, Item-KNN)의 학습을 위해 무리하게 포함하지 않는 편이 적절하다(제안).

## 5. 베이스라인 전처리 제안 (미구현)
1. 첫 학습에서는 미사용, 데이터 구조·라이선스·메타데이터로만 기록.
2. 후속 탐색 시 `bundle_id,item_id` 중복 정리 및 ID 유효성 검사.
3. 번들 내부의 공동 등장 관계와 실제 사용자 선호 관계는 분리된 그래프로 취급.
4. 특정 번들의 Linux 게임 포함 여부는 A의 `linux` 플래그와 App ID 조인으로 평가.
