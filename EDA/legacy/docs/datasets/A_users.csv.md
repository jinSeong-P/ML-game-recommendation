# A · users.csv — 사용자별 활동 요약

## 1. 목적과 데이터 단위
- **원본**: A/`users.csv` (약 193 MB).
- **한 행**: 사용자 한 명의 **집계 활동 정보**. 개별 소유 게임 목록이 아니다.
- **연결**: `user_id`는 A `recommendations.csv` 사용자 ID와만 조인. B의 문자열 `user_id`와 연결하면 안 됨.

## 2. 컬럼 사전 — 원본 3개
| 컬럼 | Parquet 형식 | 의미 |
|---|---|---|
| `user_id` | int32 | A 내부 사용자 ID |
| `products` | int32 | 계정이 보유한 제품 수 계열 집계. **어떤 게임인지** 알려 주지 않음 |
| `reviews` | int32 | 사용자 리뷰 수 계열 집계 |

전처리 시 `dtype`만 지정하고 원본 행을 삭제하지 않는다.

## 3. EDA 실측
| 항목 | 값 |
|---|---:|
| 전체 사용자 행 | **14,306,064** |
| 사용자 ID 중복 | **0** |
| A 추천 리뷰와 매칭되는 사용자 | **13,781,059** |
| A `reviews` 값 = 실제 추천 리뷰 행 수 | **100% 일치** (매칭 사용자 기준) |
| `products` 중앙값 | **57개** |
| 보유 수 대비 리뷰 수 비율의 중앙값 | **약 3.3%** (리뷰 작성 사용자 매칭 기준) |
| 리뷰 수 0인 사용자(파일 전체) | **3.67%** |

형식상 null은 0건이지만, 활동 수가 없거나 적은 사용자가 존재한다. `products`를 관측된 사용자–게임 긍정 상호작용 수로 대체하면 안 된다.

## 4. 활용 가능성과 한계
- 사용자 활동도(활동 많은/적은 사용자), 리뷰 수와 보유 수 차이, cold-start 사용자군 분석에 유용하다.
- **보유한 특정 게임의 ID 목록이 없으므로** `users.csv`만으로 아이템 추천용 학습 행렬이나 개인화 사용자 벡터를 만들 수 없다.
- `products`는 성향 또는 선호 레이블이 아니라 **집계 값**이다. 보유 수가 많다고 특정 장르를 선호한다고 해석할 수 없다.
- B에서 입력하는 실제 보유 게임 목록은 B `australian_users_items.json`에만 있으며, A 사용자와 B 사용자 사이에 개인 단위 연속성이 없다.
- 학습/검증 사용자 분리 시 `users.csv`와 리뷰 이력을 사용자의 ID에 따라 일관되게 나눠야 한다(제안).

## 5. 베이스라인 전처리 제안 (미구현)
1. 첫 모델은 리뷰 이력을 이용해 만들고, `users.csv`는 사용자 활동도 통계/품질 점검용으로 유지.
2. `user_id` 조인 시 리뷰가 없는 사용자와 있는 사용자를 명시적으로 구분.
3. 리뷰 개수에 따른 층화 분석을 할 수 있으나, 테스트셋 정답이나 피처 누출이 없는지 확인.
4. 리뷰 수가 적은 사용자에게는 콘텐츠 추천 또는 인기순 대체 추천 경로를 설계.
