# EDA 요약 — Linux 지원 Steam 게임 개인화 추천

EDA는 탐색적 데이터 분석, 즉 추천 모델을 만들기 전에 자료의 구성과 품질을 살펴보는 분석을 뜻합니다.

- 작성: 2026-11-03 · 근거: `notebooks/01_eda.ipynb` 실행 결과(`reports/eda_metrics.json`, `reports/tables/*.csv`)
- **표기 규칙**: 따로 표시하지 않은 수치는 원본 자료에서 직접 계산한 값입니다. 해석이나 추정은 *(추정)* 으로 표시합니다.
- 이 보고서에서 **A는 학습 자료**([Game Recommendations on Steam](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam), v28, 2024-08-14), **B는 외부 평가 자료**([Steam Video Game and Bundle Data](https://www.kaggle.com/datasets/pypiahmad/steam-video-game-and-bundle-data)의 UCSD 복제본, v1), **C는 게임 설명 보완 자료**([Steam Games Dataset 2025](https://www.kaggle.com/datasets/artermiloff/steam-games-dataset), v2, 2025-03-13 `games_march2025_cleaned.csv`)를 뜻합니다. 게임은 Steam App ID(게임별 식별 번호)로 맞춰 보지만, 사용자 ID는 자료 간에 연결하지 않습니다.

## 읽는 방법

- **입력**은 추천을 받을 사용자가 가진 게임 목록입니다. 이 보고서에서는 보유 목록을 기본 입력으로 삼고, 별도로 표시할 때만 실제 플레이 시간으로 좁힙니다. **후보**는 추천 목록에 넣을 수 있는 게임입니다.
- **정답**은 B 사용자가 긍정적으로 평가한 게임 중, A에서 공식 Linux 지원 게임으로 확인되어 외부 평가에 쓰는 게임입니다. **한 쌍**은 사용자 한 명과 게임 한 개의 관계를 셉니다. 예를 들어 정답 쌍은 특정 사용자가 특정 게임을 긍정 평가한 관계 하나입니다.
- **Recall@10**은 사용자별 상위 10개 추천 중 정답의 비율을 계산한 뒤 평균한 값입니다. **NDCG@10**은 정답을 추천 순위에서 더 앞에 놓을수록 높아지는 점수입니다. 두 점수의 `@10`은 상위 10개까지 평가한다는 뜻입니다.
- **인기순 기준선**은 A에서 긍정 리뷰가 많은 게임부터 추천하는 간단한 비교 방법입니다. 보고서의 **롱테일 평가**는 A의 Linux 지원 게임 중 인기 상위 50개를 제외한 게임을 대상으로 합니다. 표에 별도의 범위가 표시된 경우에는 그 범위를 따릅니다.
- **k-core**는 한 번 기준을 적용하고 끝내는 방법이 아닙니다. 각 사용자의 리뷰 건수와 각 게임의 리뷰 건수가 모두 정한 최소 기준을 넘도록, 기준 미달 사용·게임을 제외하고 남은 자료에서 리뷰 수를 다시 세는 과정을 반복해 추립니다.
- `p90`과 `p99`는 각각 값의 90%, 99%가 그 값 이하인 위치를 뜻합니다. 밀도는 사용자-게임 조합 가운데 리뷰가 있는 비율이고, 희소성은 리뷰가 없는 조합의 비율입니다.
- **아이템 기반 k-최근접 이웃(Item-KNN)**은 함께 긍정 평가된 게임끼리 비슷하다고 보고, 사용자가 좋아한 게임과 가까운 게임을 추천하는 방식입니다. **교대 최소제곱법(ALS)**은 이용 이력에서 사용자와 게임의 취향 특징을 추정하는 추천 방식입니다. 새 사용자에게 ALS를 쓰려면 알려진 추천 특징에 그 사용자의 입력 이력을 반영하는 추가 계산(fold-in)이 필요합니다.
- **단어 빈도-역문서 빈도(TF-IDF)**는 각 게임 설명을 단어별 숫자 목록으로 바꾸되, 흔한 단어보다 게임을 구별하는 단어에 더 큰 비중을 주는 방법입니다. 두 목록에 비슷한 단어가 비슷한 비중으로 들어 있으면 코사인 유사도가 높습니다.
- `Coverage@10`은 평가 사용자들의 상위 10개 추천에 한 번 이상 나타난 후보 게임의 비율입니다. 게임별 macro recall은 각 정답 게임의 회수율을 따로 구한 뒤, 게임마다 같은 비중을 주어 평균한 점수입니다. bootstrap(사용자를 여러 번 다시 뽑는 방법) 신뢰구간은 평가 점수의 불확실성 범위를 추정합니다.

## 4. 외부 평가 가능성

평가 방법: B 사용자의 **보유 게임 중 A에도 있는 게임**을 입력으로 사용합니다. 같은 사용자가 이미 리뷰한 게임은 긍정·부정과 관계없이 입력에서 뺍니다. 해당 사용자가 긍정 리뷰한 A의 Linux 지원 게임을 정답으로 삼습니다.

| 입력 게임 수의 최소 기준 k | 평가 사용자 | 정답 쌍(사용자-게임 관계) | 정답 게임 수 |
|---|---|---|---|
| 1 | 15,676 | 25,135 | 829 |
| 5 | **15,294** | **24,704** | 829 |
| 10 | 14,697 | 23,981 | 826 |
| 20 | 13,076 | 21,796 | 818 |

- 입력을 실제 플레이 시간이 0분보다 큰 게임으로 제한해도 k=5에서 15,067명을 평가할 수 있습니다 (`tables/05_external_test_eligibility.csv`).
- 사용자당 정답 수의 중앙값은 1개이고, 정답이 2개 이상인 사용자는 5,886명입니다. 입력 게임 수의 중앙값은 46개입니다.
- 정답 게임의 99.99%는 A에서 긍정 리뷰가 10건 이상입니다. 이 게임들은 Item-KNN이 학습할 때 충분한 긍정 리뷰가 있습니다.
- 리뷰만 입력에 쓰는 대안 평가에서는 B 사용자의 긍정 리뷰를 하나씩 정답으로 떼어 내고, 나머지 리뷰로 추천합니다(leave-one-out 방식). 긍정 리뷰가 2건 이상인 사용자는 9,771명이고, 그중 Linux 정답이 1건 이상인 사용자는 8,771명입니다.
- **인기순 기준선 성능 확인** (k=5, 15,294명, A에서 Linux 지원 게임의 긍정 리뷰가 많은 순서로 추천하고 입력 게임은 제외):

| 기준선 | Recall@10 | NDCG@10 |
|---|---|---|
| A 전체 기간 인기순 | 0.539 | 0.373 |
| A 인기순, 2015년 이전 출시 게임만 | 0.547 | 0.377 |
| A의 2015년 이전 리뷰로 계산한 인기순 | 0.586 | 0.384 |
| 무작위(기대값) | 0.0015 | – |

- **정답 집중도**: 정답 쌍의 30.8%가 상위 3개 게임(Team Fortress 2, CS:GO, Garry's Mod)에, 50.7%가 상위 10개에 몰려 있습니다. **64.0%는 A의 Linux 지원 게임 가운데 인기 상위 50개**에 해당합니다 (`tables/05_top_target_items.csv`).
- **인기 상위 50개를 뺀 게임의 평가**: 정답에 인기 상위 50개가 아닌 게임이 하나 이상 있는 사용자 6,533명, 정답 8,885쌍, 게임 786개입니다. 이 사용자들을 인기순으로 평가하면 후보 게임 전체를 열어 두어도 Recall@10은 0.000입니다. 후보에서도 인기 상위 50개를 제외하면 Recall@10은 0.032, NDCG@10은 0.014입니다. 개인화 모델이 인기순 추천보다 나은지 이 평가로 확인할 수 있습니다.

## 5. 주요 위험 요소와 해결 방안

| 위험 | 근거(실측) | 해결 방안 |
|---|---|---|
| 인기 편향으로 간단한 비교 기준이 강함 | 인기순 Recall@10은 0.54이고, 정답 가운데 약 절반이 인기 상위 10개 게임에 속함 | 전체 평가와 함께 **인기 상위 50개를 제외한 게임의 Recall@10**, Coverage@10, 게임별 macro recall을 보고합니다. |

## 6. 권장 학습·평가 방법

1. **A로 학습**: 긍정 리뷰(`is_recommended=True`)를 사용자가 좋아한 신호로 삼습니다. 부정 리뷰는 학습에서 빼거나 별도 실험으로 봅니다. 모델 설정은 A 안에서 평가 사용자를 나누어 조정합니다. 이때 각 사용자에게 긍정 리뷰가 5건 이상, 각 게임에 긍정 리뷰가 10건 이상 남도록 반복해서 추리고, 사용자별 긍정 리뷰의 20%를 감춰 맞혀 봅니다.
2. **추천 가능한 게임**: 두 방식 모두 A에서 공식 Linux 지원으로 표시된 게임만 추천하도록 제한합니다.
3. **B로 외부 평가(재학습 없음)**: 입력 게임이 5개 이상인 15,294명을 평가합니다. 입력은 B의 보유 게임 가운데 A에도 있고 해당 사용자가 리뷰하지 않은 게임입니다. 정답은 그 사용자가 긍정 리뷰한 A의 Linux 지원 게임입니다. 이미 입력에 든 게임은 추천 목록에서 뺍니다.
4. **평가 점수**: 주 지표는 Recall@10과 NDCG@10입니다. 보조 지표로 Coverage@10과 롱테일 Recall@10(인기 상위 50개 게임 제외)을 봅니다. 비교 기준은 A의 Linux 지원 게임 인기순입니다.
5. **조건을 바꾼 재확인**: (a) A 전체 기간의 자료와 2015년 이전 자료만 쓴 경우, (b) 보유한 게임 전체를 입력한 경우와 실제 플레이 시간이 0보다 큰 게임만 입력한 경우를 비교합니다.

## 7. 다음에 만들 기능

1. 학습에 쓸 A의 긍정 리뷰와 B의 평가 자료(입력과 정답)를 정리해 `data/processed`에 Parquet 형식(분석 자료를 효율적으로 저장하는 파일 형식)으로 저장합니다. 노트북 5장에서 평가 자료를 만드는 코드를 재사용할 수 있도록 정리합니다.
2. A의 Linux 지원 게임 인기순 추천을 기준선으로 만들고, Recall, NDCG, Coverage, 인기 상위 50개를 제외한 게임의 평가 점수를 계산합니다. 노트북의 `eval_topk`는 상위 게임을 뽑아 평가하는 코드입니다.
3. **게임 설명으로 추천**: A의 태그와 설명을 사용하고, A에 태그가 없으면 C의 태그로 보완합니다. TF-IDF로 각 게임을 수치로 바꾼 뒤, 사용자가 입력한 게임들의 평균과 비슷한 게임을 추천합니다.
4. **비슷한 게임으로 추천(Item-KNN)**: A의 긍정 리뷰를 바탕으로 게임별 유사도를 계산하고, 각 게임의 가까운 이웃을 찾습니다. 새 사용자가 입력한 게임의 이웃 게임 점수를 합쳐 추천합니다.
5. (선택) 긍정적 이용 이력으로 취향을 학습하는 ALS도 만들고, 새 사용자의 입력을 반영하는 fold-in 계산을 추가합니다.
6. A 안에서 모델 설정을 조정하고, 마지막에 B에서 한 번 외부 평가해 결과를 표로 정리합니다.
