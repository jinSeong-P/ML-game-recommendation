| B 집합 | 고유 게임 | A에 존재 | A의 Linux | C에 존재 |

- **행 기준 커버리지가 더 높다**: B 보유 기록의 79.3%, 플레이타임 가중 88.0%, 긍정 리뷰의 90.2%가 A 게임. 긍정 리뷰의 54.5%는 A의 Linux 게임.
- **불일치 원인(실측 예시)**: 테스트·베타 클라이언트(`Dota 2 Test`, `Left 4 Dead 2 Beta`), 스토어에서 내려가거나 새 판본으로 교체된 게임(`Dead Island`, `Metro 2033`, `Arma 2`), 패치 테스트용 앱 등. A에 없는 게임은 보유자 중앙값 19명(매칭된 게임 54명)으로 사용자가 적은 게임 위주. 다만 `The Elder Scrolls V: Skyrim`(72850), `Rocket League`(252950)처럼 C에는 있으나 A에는 없는 인기 게임도 있다.

## 4. 외부 테스트 가능성

평가 방법: B 사용자의 **보유 게임(A 게임 목록, 리뷰한 게임 전부 제거)** 을 입력으로 주고, **A Linux 게임에 대한 긍정 리뷰**를 정답으로 한다.

| 최소 입력 수 k | 평가 사용자 | 정답 쌍 | 정답 고유 게임 |
|---|---|---|---|
| 1 | 15,676 | 25,135 | 829 |
| 5 | **15,294** | **24,704** | 829 |
| 10 | 14,697 | 23,981 | 826 |
| 20 | 13,076 | 21,796 | 818 |

- 입력을 '플레이 0분 초과'로 제한해도 k=5에서 15,067명 (`tables/05_external_test_eligibility.csv`).
- 사용자당 정답 중앙값 1, 2개 이상인 사용자 5,886명. 입력 게임 수 중앙값 46.
- 정답 게임의 99.99%가 A에서 긍정 10건 이상 → Item-KNN이 도달 가능한 아이템.
- 리뷰만 쓰는 대안(B의 긍정 리뷰 중 정답 한 개 숨김): 긍정 리뷰 2건 이상 9,771명, 그중 Linux 정답 1건 이상 8,771명.
- **인기순 추천 결과 확인** (k=5, 15,294명, A의 Linux 긍정 수로 정렬, 입력 게임 제외):

| 기준선 | Recall@10 | NDCG@10 |
|---|---|---|
| A 전체 기간 인기순 | 0.539 | 0.373 |
| A 인기순, 2015년 이전 출시 게임만 | 0.547 | 0.377 |
| A의 2015년 이전 리뷰로 계산한 인기순 | 0.586 | 0.384 |
| 무작위(기대값) | 0.0015 | – |

- **정답 집중도**: 정답 쌍의 30.8%가 상위 3개 게임(Team Fortress 2, CS:GO, Garry's Mod), 50.7%가 상위 10개, **64.0%가 A Linux 인기 상위 50개 게임**에 속한다 (`tables/05_top_target_items.csv`).
- **인기 상위 게임을 제외한 평가 집단**(상위 50개 제외 정답이 남는 사용자): 6,533명 · 정답 8,885쌍 · 게임 786개. 여기서 인기순 Recall@10은 0.000(후보 전체), 상위 50개를 후보에서도 빼면 0.032 (NDCG@10 0.014) → 개인화 모델의 차별성은 이 부분집합에서 드러날 것.

|---|---|---|

| 신호 의미 차이 | A 학습은 리뷰(긍정/부정), B 입력은 보유·플레이 | 입력·정답·학습 신호를 문서에 분리 표기. 입력 변형(보유 / 플레이>0) 두 가지로 민감도 확인 |

| A의 극단적 희소성·콜드 스타트 | 사용자 55%가 리뷰 1건, 88%가 긍정 5건 미만 | A 내부 검증은 k-core(사용자≥5, 게임≥10)에서 수행, 이력이 적은 사용자는 콘텐츠 기반·인기순 대체 추천 검토 |
| ID 미매칭 | B 보유 게임 27%(고유 기준), 행 기준 21%가 A에 없음 | A에 없는 게임은 입력에서 제외하고 그 비율을 보고. 테스트·베타 앱은 노이즈로 간주 |
| B 중복 | 중복 프로필 673명, (user,item) 중복 리뷰 874행 | user_id별 첫 프로필 사용, (user,item) 중복 제거(라벨 충돌 0) |

| 메타데이터 결측 | Linux 게임 설명 결측 23.4% | TF-IDF는 태그 중심 + 설명 보조. 태그 없는 게임은 C 태그로 보강 |

## 6. 당시 제안한 학습·평가 방법

1. **학습(A)**: 긍정 리뷰(`is_recommended=True`)를 implicit 상호작용으로 사용. 부정 리뷰는 학습 신호에서 제외하거나 별도 실험. 하이퍼파라미터는 A 내부 사용자 단위 hold-out(k-core 사용자, 사용자별 긍정 20% 숨김)으로만 조정.
2. **후보 제한**: 두 모델 모두 출력 후보를 A `linux=True` 게임으로 제한(공통 조건).
3. **외부 테스트(B, 재학습 없음)**: k=5 기준 15,294명. 입력 = 보유 게임 ∩ A 아이템 − 리뷰한 게임, 정답 = A Linux 게임 긍정 리뷰. 입력 게임은 추천 목록에서 제외.
4. **지표**: Recall@10, NDCG@10(주), Coverage@10, 롱테일 Recall@10(보조). 기준선은 A Linux 인기순.
5. **변형 실험**: (a) A 전체 vs A 2015년 이전 학습, (b) 입력 보유 vs 플레이>0.

## 7. 당시 제안한 구현 단계

1. `data/processed`에서 학습 행렬(A 긍정, k-core)과 B 평가셋(입력/정답 쌍)을 parquet으로 고정 저장 — 노트북 5장의 `ev` 생성 로직을 함수로 분리
2. 인기순 기준선 + 평가 함수(Recall/NDCG/Coverage/롱테일) 모듈화 — 노트북의 `eval_topk` 재사용
3. 콘텐츠 기반: A 태그(+설명, C 태그 보강) TF-IDF → 사용자 입력 게임 벡터 평균과의 코사인 유사도
4. Item-KNN: A 긍정 행렬로 아이템 코사인 유사도(상위 K 이웃) → 신규 사용자는 입력 게임 이웃 점수 합
5. (선택) implicit ALS + 신규 사용자 fold-in
6. A 내부 검증으로 튜닝 → B 외부 테스트 1회 평가, 결과표 작성
