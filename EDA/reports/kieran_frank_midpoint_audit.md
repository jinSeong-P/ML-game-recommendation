# Kieran·frank 초기 데이터와 평가 방법 점검

검토일: **2026-11-07**. [추가 실험·진단 목록](../docs/modeling_backlog.md)에 적힌 의심점 10개를 기존 진단 코드·집계와 실제 로컬 자료로 확인했다. 아래 정답 분포와 기준선은 **사용자마다 적격 긍정 Linux 정답 하나를 균등 추출할 때의 기대값**이다. 특정 seed로 생성한 테스트 성적은 아니다.

베이스라인 설계에 따른 학습·검증·테스트 분할과 실제 정답 목록·검증 정보는 후속 작업에서 생성·검증했다(seed 20261107). [분할 파일 안내](../docs/modeling_splits.md)를 참고한다. 이후 TF-IDF 소개글·토큰·벡터·검색도 준비했다. 이 보고서의 미완료 표기는 2026-11-07 검토 시점의 상태다. Kieran–frank 기준선 평가는 이후 완료했으며 결과는 [baseline_v1.md](baseline_v1.md)에 있다. 최신 Forgemaster 모델 평가는 별도 데이터셋의 [forgemaster_model_evaluation.md](forgemaster_model_evaluation.md)에 기록했다.

이 보고서에는 숨김 후 전체 입력이 5개 이상인 **24,571명**을 대상으로 한 과거 진단 결과가 있다. 이 집단은 기본 평가에 필요한 긍정 입력 조건을 추가하기 전에 만든 진단 집단이다. 당시 확정한 기본 평가의 EDA 예상 규모는 전체 입력 ≥5·긍정 입력 ≥1을 모두 만족하는 **24,342명**이다.

24,571명 집단의 과거 측정값은 감사 기록으로 보존하고, 24,342명 집단의 기대값과 구분한다. 24,342명은 이 감사 당시의 예상 규모였다. 이후 같은 사람들의 사용자·입력·정답 명단을 생성해 검증했다. 아래 기대값은 특정 seed로 얻은 모델 성능이 아니다.

## 2026-11-07 확정한 기본 설계

- Item-KNN은 Linux 여부와 관계없이 고정 입력 카탈로그 **37,610개 게임**에서 학습한다. 긍정 리뷰가 한 게임뿐인 사용자도 게임별 빈도와 코사인 정규화에 포함한다. 카탈로그 안 긍정 쌍 **78,315,268개**는 EDA 미리보기다. App ID 연결을 확정할 수 없는 원 리뷰는 계속 학습에서 제외한다.
- TF-IDF는 게임 소개글만 사용한다. A `description`을 우선하고 값이 null·빈 문자열·공백뿐일 때 C `short_description`으로 보충한다. 태그·장르는 기본선에 포함하지 않는다.
- 사용자별 적격 긍정 Linux 정답 하나를 균등 무작위로 숨긴다. 숨김 후 전체 입력 ≥5·긍정 입력 ≥1인 사용자를 평가하고 seed와 실제 정답 명단을 저장한다. 두 모델은 긍정 입력만 취향·추천 점수에 사용하고, 사용자 입력은 동일 가중 평균으로 집계한다. TF-IDF는 L2 정규화한 긍정 게임 벡터 평균과 후보의 코사인 유사도, Item-KNN은 각 긍정 입력과 후보의 유사도 합을 긍정 입력 수로 나눈 점수를 사용한다.
- 개인화 점수가 0보다 큰 후보만 최대 10개 추천한다. 양수 점수 후보가 10개보다 적으면 추천 목록의 남은 자리는 채우지 않는다. 추천 결과가 빈 사용자도 지표 계산에 포함한다. 남은 긍정·부정 입력 게임은 제외하되 숨긴 정답은 추천 후보에 둔다. 2026-11-07 검토 시점에는 이 규칙의 실제 구현과 모델별 적용 범위·지표를 아직 측정하지 않았다.
- 새로 추가한 평가·실험은 전체 입력 ≥3·긍정 입력 ≥1 조건, 플레이타임 가중 대체 집계 비교, 모델 개선 후 train 데이터의 인기도 순으로 추천 목록의 남은 자리를 보완하는 정책이다. 기본선에는 인기도 보완을 적용하지 않는다.

## 1. frank 정답 분포와 모델 비교

**판정: 분포 차이는 사실이다. ‘Item-KNN이 TF-IDF보다 불리하다’는 결론은 미확인이다.**

Kieran 학습 긍정 계정 수로 Linux 게임을 정렬하면 상위 10개가 학습 긍정 리뷰의 43.3023%를 차지하지만, frank의 사용자별 무작위 정답에서 차지하는 기대 비중은 0.05604%다. 상위 500개는 각각 92.9262%와 9.3918%다. frank 전체 리뷰는 앱당 최대 100행이고, 44,517개 앱 중 18,437개가 정확히 100행이다. 전체 행의 약 70.1%가 이 앱들에 속한다.

단, frank가 정확한 게임 균등 표본인 것은 아니다. 사용자별 이력 수·정답 수·최소 입력 조건이 추가로 분포를 바꾼다. 지정한 Git 커밋의 README에는 리뷰 추출 순서·무작위화 방법이 없어, 최대 100행이라는 관측만으로 무작위 표본이라고 인증할 수 없다.

상위 10개 정답 비중은 아직 사용자가 이미 리뷰한 게임을 제외하지 않은 값이다. 사용자별 제외 마스크와 숨긴 정답 복원을 적용해 인기도 기준선을 다시 계산했다.

| 집단 | 인기도 Recall@10 기대값 | 무작위 Recall@10 기대값 | 인기도 NDCG@10 기대값 |
|---|---:|---:|---:|
| frank 과거 전체 입력 ≥5 진단 집단, 24,571명 | 0.05814% | 0.15093% | 0.00022731 |
| frank + 긍정 입력 ≥1 기본 평가의 EDA 예상 집단, 24,342명 | 0.05869% | 0.15093% | 0.00022944 |
| Kieran 내부 검증 전체 입력 ≥5, 326,045명 | 31.96755% | 0.15090% | 0.20213687 |
| 예약 계정 Kieran 이력 + 긍정 입력 ≥1, 64,110명 | 9.49152% | 0.15116% | 0.05234870 |

인기도가 frank에서 무작위보다 낮은 현상은 이 조건에서 확인됐다. Recall 열은 백분율이고 NDCG 열은 0~1 범위다. 사용자마다 같은 가중치를 주고, 각 사용자가 가능한 정답마다 `1/정답 수`의 가중치를 받아 모든 정답 선택의 기대값을 계산했다. 무작위 기준선은 남은 Linux 후보를 균등한 확률로 순위를 매긴 경우다.

24,571명 값은 과거 전체 입력 ≥5 진단 집단의 측정값으로 남기고, 24,342명 값은 현재 기본 평가 집단의 사전 기대값으로 구분한다. 둘 다 특정 seed로 얻은 결과나 최종 모델 점수는 아니다. [분포 분석](kieran_frank_audit_distribution.json)에 원래 척도와 추가 조건을 기록했다. 협업 모델은 사용자 입력과 이웃 게임의 관계를 반영하므로, 인기도 결과만으로 Item-KNN 성능을 예측할 수 없다.

## 2. 검증셋과 테스트셋의 튜닝 조건

**판정: 검증·테스트 분포 차이는 사실이다. 검증에서 고른 설정의 실패는 아직 입증되지 않았다.**

과거와 같은 전체 입력 ≥5 조건에서 Kieran 검증 정답의 학습 인기도 상위 10개 비중은 30.7057%, 상위 500개 비중은 91.1549%다. frank의 0.05604%·9.3918%와 크게 다르다. 현재 기본 평가에는 긍정 입력 ≥1 조건도 필요하다. 따라서 이 비교는 그 조건을 추가하기 전 과거 진단값으로 보존한다. 계정이 서로 독립적인 것과 두 평가의 게임 분포가 비슷한 것은 별개의 조건이다.

따라서 검증 전체 평균만 최적화하면 인기 게임에 맞는 설정을 선택할 위험이 있다. 내부 검증에서 미리 정한 학습 인기도 구간별 성능과 전체 평균을 함께 확인하는 것이 타당하다. frank 테스트 정답·성능을 보고 설정이나 가중치를 고르는 것은 테스트 튜닝이므로 하지 않는다. frank와 비슷한 샘플링의 내부 검증을 만들지 여부는 별도 설계 결정으로 남긴다.

## 3. frank에 빠진 실제 긍정 이력

**판정: 누락된 알려진 긍정 이력은 존재한다. 이를 ‘오답 라벨 오류’라고 부르는 것은 부정확하다.**

전체 입력 ≥5인 과거 진단 집단 24,571명을 Steam 계정으로 정확히 연결했다. 평가 카탈로그 안의 이력 수 중앙값은 frank 10개, Kieran 44개다. 이 가운데 88.5475%의 사용자는 frank 리뷰에는 없지만 Kieran에 긍정 이력이 있는 Linux 게임이 하나 이상 있다. 해당 쌍은 모두 398,893개이며 사용자별 중앙값은 9개다.

현재 단일 정답 지표는 선택된 정답만 적중으로 센다. 다른 실제 긍정 게임은 부정 학습 라벨이 되지는 않지만, 추천 목록에서 정답보다 앞서면 선택된 정답의 Recall·NDCG를 낮출 수 있다. 따라서 숨긴 정답 회수 성능을 전체 취향 만족도나 모든 미관측 게임의 부정 여부로 해석할 수 없다.

보조 민감도 분석에서는 Kieran에만 있는 알려진 긍정 게임 또는 Kieran의 리뷰가 있는 게임을 추가 제외한다. 이때 **선택된 frank 정답은 추천 후보에 다시 포함**한다. 이 평가는 추가 사용자 정보를 쓰는 다른 조건이므로 기본 frank 결과와 구분해야 한다. 해당 계정의 Kieran 이력은 계속 학습에서 제외한다.

과거 24,571명 진단 집단에서 frank에는 없고 Kieran에만 있는 긍정 Linux 게임을 추가로 제외하면 인기도 Recall@10 기대값은 **0.05814%에서 0.07578%로** 바뀐다. Kieran에 알려진 Linux 리뷰 게임을 모두 추가 제외하면 **0.07781%**가 된다. 무작위 기준선은 각각 0.15131%와 0.15139%다. 제외 목록이 결과를 바꾸지만 이 인기도 기준선에서는 출처 간 분포 차이가 여전히 남는다. 이 추가 제외 조건에서 개인화 모델에 미치는 영향은 2026-11-07 검토 당시 실제 모델 평가 후 확인할 과제로 남아 있었다.

## 4. 예약 계정의 Kieran 이력을 보조 테스트로 사용

**판정: 구성 가능한 보조 평가 집단은 있다. frank가 평가용으로 부적합하거나 부족하다는 결론은 아니다.**

기존 frank 예약 계정 중 Kieran 이력에서 전체 입력 ≥5를 남길 수 있는 계정은 64,138명이고, 긍정 입력 ≥1까지 요구하면 64,110명이다. 이 계정들은 이미 학습·내부 검증에서 제외돼 있다. 전체 입력 ≥5 집단의 정답은 학습 인기 상위 10개 8.7149%, 상위 500개 58.8138%다.

이 평가는 frank와 Kieran의 출처 차이에 따른 결과 변화를 보는 데 유용하다. 다만 학습 자료와 출처가 같고, frank 평가와 계정도 겹친다. 긍정 입력 ≥1 조건의 frank 24,342명과 보조 Kieran 64,110명 사이에는 **21,038명**이 겹친다. 독립적인 두 사용자 표본으로 합산하거나 외부 테스트를 대체하지 않는다. 도입 여부와 query/target 구성은 아직 결정하지 않았다.

## 5. 모호한 리뷰를 제외하면서 발생한 게임별 근거 손실

**판정: 제외한 모호 리뷰가 일부 게임에 집중되어 게임별 학습 근거가 줄었다. 입력 카탈로그에 앱이 하나만 남았다는 이유로 해당 리뷰의 App ID를 바로잡을 수는 없다.**

332,865개 모호 리뷰 ID·686,161행이 31개 앱 조합, 서로 다른 63개 App ID에 집중돼 있다. 22개 조합에는 당시 입력 게임 목록 앱이 하나만 있고, 해당 ID는 329,756개다. Black Desert·Oblivion GOTY·SHOGUN 2 등의 앱 조합이 포함된다.

원본 자료와 평가 자료를 비교하면 63개 앱 모두 원 리뷰 행의 90% 이상이 제외됐고, **55개 앱은 리뷰 행이 전부 제외**됐다. 31개 앱 조합 가운데 연결된 모든 앱의 리뷰 행이 제외된 조합은 25개다. 따라서 게임별 리뷰 근거가 줄었다는 우려는 확인됐다.

‘앱 ID만 다르고 나머지는 모두 같다’는 표현도 전체에는 성립하지 않는다. 비교 가능한 필드(계정·라벨·작성/갱신 시각·플레이 시간·언어)가 앱 ID 외에는 모두 같은 ID는 **326,403개**이고, **6,462개**는 다른 필드도 다르다. 그중 긍정/부정 라벨이 다른 ID도 2개 있다. 원본에서 분석용으로 추출한 리뷰 필드에는 본문이 없어 본문 동일성까지 검사한 것은 아니다. [모호한 앱 연결 제외·학습 범위 분석](kieran_frank_audit_quarantine_scope.json)에 필드별 결과를 남겼다.

현재 frank 전체 입력 ≥5 집단에서 모호한 앱 연결을 제외하고도 남은 이력은 227쌍이고, 그중 긍정 Linux 리뷰는 31쌍이다. 이는 **남아 있는 frank 이력과 앱 조합이 겹치는 수**다. 모호한 App ID를 다시 연결했을 때 포함될 Kieran 리뷰 수나, 최종 평가에서 선택할 정답 수가 아니다. 특정 게임의 학습 손실이 작다는 근거로 사용할 수 없다.

카탈로그는 프로젝트가 선택한 게임 범위이며, 원 리뷰에 올바른 App ID를 증명하는 원장이 아니다. 같은 계정·라벨·시각이 복제된 것을 관측해도 어느 App ID가 맞는지 단독으로 입증하지 못한다. 원 게시물이나 출처에서 리뷰와 앱을 연결하는 근거를 확보하기 전에는 일괄적으로 App ID를 다시 지정해 리뷰를 포함하지 않는다. 현재처럼 모호한 연결을 제외하는 정책을 유지하고 게임별 손실을 기록한다.

## 6. Item-KNN 학습 규모 표현

**판정: 84,791,317쌍은 모든 게임을 포함한 train 데이터의 긍정 쌍 수로 맞다. 카탈로그 제한 모델의 최종 입력 수로 쓰면 잘못이다.**

| 집계 범위 | 긍정 사용자–게임 쌍 |
|---|---:|
| 모든 게임을 포함한 train 데이터 | 84,791,317 |
| 고정 입력 카탈로그 안 | 78,315,268 |
| 카탈로그 내 긍정 게임이 2개 이상인 사용자에서 나온 쌍 | 61,273,079 |

마지막 행은 공동 긍정의 비대각 연결을 만들 수 있는 사용자들의 쌍 수다. 1개 게임만 긍정한 사용자도 아이템 빈도와 코사인 분모에 기여할 수 있으므로, 무조건 버려도 같은 모델이라는 뜻은 아니다. 확정한 기본선은 **고정 입력 카탈로그 37,610개 안의 긍정 리뷰를 사용하고, 비Linux 게임과 긍정 singleton을 포함**한다. 표의 원본 집계는 EDA 측정값이다. 2026-11-07 검토 뒤 완성한 모델 입력과 평가 결과는 [baseline_v1.md](baseline_v1.md)에 기록했다.

## 7. 리뷰 시점과 카탈로그 시점

**판정: 시점 차이는 사실이다. 취향 변화나 신규 게임 추천 성능을 입증하는 자료는 아니다.**

Kieran 작성 시각은 2023-11-04까지, frank는 2025-11-19까지다. frank 원 리뷰 행의 37.8338%가 2025년이다. 사용자별 단일 정답의 기대 비중으로 보면 Kieran 종료 이후 작성된 정답은 전체 입력 ≥5 집단에서 약 43.5048%, 긍정 입력 ≥1 집단에서 약 43.6717%다.

기존 진단은 frank 원본의 중복 사용자–게임 행을 시각 집계에 다시 연결했다. 중복을 제거하고 최초 작성 시각으로 집계하면 43.504183%가 43.504773%로 바뀐다. 결론은 같고, 원본의 서로 다른 작성 시각이 있는 잠재 정답은 1쌍이다.

**범위 정정:** A 전체 마지막 출시일은 2023-10-24지만, 실제 `reviewed=True` 입력 카탈로그와 Linux 정답 카탈로그의 마지막 출시일은 모두 **2023-08-24**다. 2025년 리뷰는 대부분 기존 게임에 대한 이후 관측이지, 2025년 출시 게임을 평가한다는 뜻이 아니다.

카탈로그 밖 frank 리뷰는 예약 계정 전체에서 193,268/858,236쌍(22.5192%), 전체 입력 ≥5 집단에서 144,820/632,829쌍(22.8845%)이다. 이 비율도 서로 다른 모집단을 구분한다. 현재 평가는 시간순 미래 예측이 아니라 고정 게임 범위에서 누락된 선호 게임을 찾는 평가다.

## 8. 학습 데이터의 긍정 사용자 수가 적거나 없는 정답 게임

**판정: 학습 자료에서 긍정 리뷰를 남긴 사용자가 적거나 없는 정답 게임이 있다. 전체 지표에 미치는 영향은 정답의 가중치와 실제 추천 결과로 확인해야 한다.**

Linux 후보 6,630개 가운데 train에서 긍정 리뷰를 남긴 사용자가 0명인 앱은 36개, 5명 미만인 앱은 224개다. 224개에는 긍정 사용자가 0명인 36개가 포함된다. Kieran 원본에 리뷰가 없는 27개와 Kieran train 긍정 사용자가 없는 36개는 서로 다른 조건이다. Kieran 원본 리뷰가 없는 27개 중 14개는 frank에 리뷰가 있다.

실제 가능한 frank 정답과 맞춰 보면, 전체 입력 ≥5 집단에서 **사용자별 선택 정답이 속할 것으로 기대되는 비중**은 train 긍정 사용자 0명 **0.21583%**, 1~4명 **0.43003%**, 5명 이상 **99.35414%**다. 긍정 입력 ≥1 집단에서는 각각 0.21786%·0.42997%·99.35217%다.

긍정 학습 사용자가 0명인 게임에는 가능한 정답 197쌍·18개 앱이 있고, 이 가운데 적어도 하나의 정답을 가진 계정은 189명이다. 그렇다고 189명 전원이 학습 근거가 없는 정답을 뽑는다는 뜻은 아니다.

train에서 긍정 리뷰를 남긴 사용자가 없는 후보에는 공동 긍정 Item-KNN이 점수를 매길 수 없다. 소개글이 있으면 TF-IDF는 점수를 낼 수 있어 두 모델이 점수를 낼 수 있는 게임 범위가 다르다. 반대로 train 긍정 리뷰가 있어도 사용자의 입력 게임과 연결되는 이웃이 반드시 있는 것은 아니다.

이 차이 때문에 모델마다 다른 정답이나 사용자를 골라 평가하지 않는다. 확정한 기본선은 점수가 양수인 개인화 후보만 최대 10개 추천한다. 후보가 10개보다 적으면 추천 목록의 남은 자리는 채우지 않으며, 적격 사용자의 빈 결과도 Recall@10·NDCG@10 계산에 포함한다. 2026-11-07 검토 시점에는 모델별로 점수를 낼 수 있었던 게임 수와 빈 추천 비율을 아직 측정하지 않았다. 기본선에는 인기도나 무작위 추천으로 추천 목록의 남은 자리를 채우는 처리가 없다.

## 9. 소개글 원천의 길이 차이와 확정

**판정: 길이·정보량 차이는 사실이다. A 우선·C 짧은 소개글 보충을 기본선으로 확정했으며, 2026-11-07 검토 시점에는 실제 TF-IDF 성능을 아직 측정하지 않았다.**

고정 입력 37,610개 앱에서 비어 있지 않은 A `description`의 길이 중앙값은 211자, C `about_the_game`은 1,142자다. 원문 길이이므로 HTML·문구 정리 뒤의 토큰 수나 품질과 같지는 않다. 개별 벡터 정규화도 정보량·어휘 차이를 없애지는 않는다.

A 짧은 소개글은 36,993개, C 짧은 소개글은 33,025개다. A 우선·C 짧은 소개글 보충이면 37,531/37,610개(99.7899%)이고, Linux 후보는 6,613/6,630개(99.7436%)다. 두 짧은 소개글이 모두 있는 32,487개 중 28,707개(88.3646%)는 앞뒤 공백 제거 후 같다.

기본선은 A `description`을 우선 사용하고, 값이 null·빈 문자열·공백뿐이면 C `short_description`으로 보충한다. 소개글 TF-IDF에만 사용하며 태그·장르는 섞지 않는다. 사전 연결 감사의 원문 존재율은 입력 37,531/37,610개, Linux 후보 6,613/6,630개다. 사용자별 단일 정답 기대 비중으로 짧은 소개글이 둘 다 없는 정답은 약 0.1655%다. 이는 원문 존재 기준이며 토큰화 후 모델 지원 비율이 아니다. 이후 원문을 legacy 메타데이터에서 연결·정리하고 토큰·TF-IDF 벡터를 별도 저장했다. 유효 벡터는 전체 37,527개·Linux 6,613개다. [콘텐츠 준비·지원 감사](../docs/tfidf_content.md)에 실제 저장 범위와 결측 영향을 기록했다.

## 10. Linux 표시 불일치

**판정: 자료 간 불일치는 사실이다. 원인이 시점 변화인지, 수집 오류인지까지는 미확인이다.**

당시 입력 게임 목록에서 A 비Linux·C Linux는 137개, A Linux·C 비Linux는 52개다. A Linux 중 C에서 찾을 수 없는 앱은 534개다. C에 없는 앱을 Linux 미지원으로 간주하지 않는다.

전체 입력 ≥5 집단에서 사용자별 정답 하나를 고를 때를 기준으로 A에서는 Linux지만 C에서는 Linux가 아닌 앱의 기대 비중은 약 0.6422%다. C에서 찾지 못한 앱의 비중은 약 4.9857%다. 두 모델은 같은 A 카탈로그로 비교하므로 조건은 일관되지만, 이 목록을 2026년 현재 공식 Linux 지원 게임 전체로 볼 수는 없다. 현재 지원 현황을 말하려면 기준 시각을 정하고 공식 출처를 다시 확인해야 한다.

Linux 기준 변경은 후보·정답·적격 사용자와 학습 제외 계정 범위까지 바꿀 수 있다. 이번 감사에서는 고정 표시와 카탈로그를 변경하지 않았다.
