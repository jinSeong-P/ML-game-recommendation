## Forgemaster 검토 후 성능 개선과 평가 보완

2026-11-08에 현재 결과와 공개 연구를 검토한 후 추가한 **미실행 후속 작업**이다. 기존 모델 선택, 전체 사용자 NDCG@10 주지표, 입력·정답·추천 정책은 유지한다. 아래의 평가 기준 변경안과 새 모델은 다음 실험의 프로토콜에서 검토할 후보이며, 백로그 등록만으로 채택한 것은 아니다.

### 근거와 진행 순서

- [Forgemaster 전체 평가](../reports/forgemaster_model_evaluation.md) 395,421명에서 활동량 보정 Item-KNN의 Recall@10은 29.49%로 기본 모델의 29.05%보다 높지만, 게임별 평균 Recall은 7.21%로 기본 모델의 7.46%보다 낮다. 전체 평균 향상과 여러 게임에 걸친 개선을 함께 확인한다.
- [평가 JSON](../reports/forgemaster_model_evaluation.json)의 학습 긍정 사용자 100–999명 게임에서는 TF-IDF의 Recall@10이 7.88%, 활동량 보정 Item-KNN이 5.68%다. 이는 조건부 결합을 검토할 근거이며, 사용자별 적중이 실제로 상호 보완적인지는 추가 진단이 필요하다.
- [이전 v3 내부 검증](../reports/model_improvement_v3.md)에서 EASE λ=100은 Recall@10 45.5870%를 기록했지만, 학습 긍정 사용자 1–999명 게임의 NDCG가 Item-KNN 대조군보다 약 26% 낮아 채택되지 않았다. 이 내부 검증 수치와 Forgemaster 수치는 학습·평가 조건이 달라 직접 비교하지 않는다.

진행 순서는 **새 평가 분리 설계 → 두 모델의 적중 교집합·후보 포함률 진단 → 조건부 결합과 RLAE/RDLAE 비교 → 학습형 콘텐츠 표현 검토**다. SASRec는 시간순 평가를 정비한 뒤 비교할 후순위로 유지한다. 신규 후보의 성능 향상 폭은 아직 측정하지 않았다.

### 먼저 보완할 평가

- [ ] **새 확인용 평가셋과 모델 선택용 검증셋 분리:** 과거 개발에 실제 사용한 계정·기간을 확인하고, 이후 개발에서 열어보지 않을 별도 확인용 평가셋을 확보한다. 해당 계정을 모델 학습과 설정 선택용 검증에서 모두 제외하고 설정을 확정한 뒤 평가한다. 현재 Forgemaster 재학습의 계정 분리와 과거 설정 선정 과정 전체의 독립성을 구분한다. 이미 반복 확인한 frank·Forgemaster 결과를 새 독립 최종 테스트로 부르지 않는다. Forgemaster에서 최소 입력을 ≥3개로 넓히면 적격 사용자가 395,421명에서 741,465명으로 늘어나므로, 새 적격 계정 전체를 사전에 분리하고 필요한 재학습을 수행한다.
- [ ] **시간순 학습·검증·테스트 보완:** 기존 2022년 말 기준 재학습 실험을 출발점으로 삼아 모든 사용자에게 공통 시간 경계를 적용한다. 예측 시점 이전의 리뷰·입력·추천 가능 게임과 당시 이용 가능한 메타데이터를 사용하도록 설계한다. 리뷰 수정 시점과 라벨의 관측 시점을 확인하고, 과거 메타데이터를 복원할 수 없으면 그 한계를 남겨 완전한 시간순 평가와 구분한다. 기존 무작위 정답 숨김과 결과를 별도로 보존한다. [시간 누수 연구](https://arxiv.org/abs/2010.11060), [RecSys 2025 분할 비교](https://arxiv.org/abs/2507.16289).
- [ ] **신규 게임·짧은 이력 사용자 평가:** 현재 Forgemaster 전체 평가는 후보 6,630개 중 2,100개 게임이 정답으로 등장하며, 학습 긍정 사용자가 없는 정답은 0개다. 신규 게임 성능을 별도 평가하고 학습 긍정 사용자 수·입력 길이별 사용자 수, 게임 수, Recall/NDCG를 보고한다. 최소 입력 ≥3개 실험은 위의 계정 사전 분리 작업을 선행한다. 후보를 관측 게임으로 줄여 난도를 낮추지 않으며 빈 추천도 분모에 유지한다.
- [ ] **모델 간 차이와 정답 추출 변동의 불확실성 확인:** Forgemaster 전체 집단의 기본 Item-KNN·활동량 보정 Item-KNN·TF-IDF·인기순 모델을 같은 사용자·정답으로 비교해 Recall/NDCG 차이의 짝지은 신뢰구간을 추가한다. 기존 리뷰 수 제한 전후의 신뢰구간과 구분한다. 정답 추출 시드를 바꾼 반복 평가의 변동도 확인하되 같은 사용자가 반복된 결과를 독립 표본처럼 합산하지 않는다. 여러 설정 중 고른 모델의 개선은 별도 확인용 평가셋에서 검증한다.
- [ ] **다음 버전의 모델 교체 기준 검토:** 전체 NDCG@10을 우선하고 Recall, 게임별 평균, 학습 긍정 사용자 1–999명 게임, 빈 추천을 함께 확인하는 취지를 유지한다. 보조 지표가 점추정값으로 조금만 낮아져도 탈락하는 현재 규칙을 검토하고, 실질적으로 허용할 수 있는 감소폭과 신뢰구간 판정 방법을 새 결과를 보기 전에 명시한다. 기존 탈락 모델을 새 기준으로 소급 채택하지 않는다. EASE의 희귀 게임 성능 저하는 작은 수치 변동과 구분해 검토한다.

### 실제 추천 상황과의 차이 보완

2026-11-08에 현재 평가 방식이 실제 추천과 어떻게 다른지 검토하고 추가한 **미실행 아이디어**다. 현재 평가는 같은 사용자·정답·후보에서 모델을 상대 비교하는 데 적합하다. Recall@10 같은 절대값은 실제 서비스 성능이나 사용자 만족도로 해석하지 않는다. 아래 항목은 주지표와 모델 교체 기준을 바꾸지 않는 보고용 평가로 시작하며, 채택 기준에 넣을지는 결과를 보기 전에 따로 정한다.

- [ ] **시간 누수 규모 보고:** 정답을 무작위로 숨기면 두 가지 미래 정보가 들어갈 수 있다. 첫째, 같은 사용자가 정답보다 나중에 쓴 리뷰가 입력에 들어간다. 둘째, 다른 사용자가 나중에 쓴 리뷰로 게임 간 유사도를 학습한다. Forgemaster 평가 자료는 2021년 4월까지이지만 Kieran 학습 자료는 2023-11-04까지 이어진다. 정답보다 나중에 작성된 입력의 비율, 정답 작성 시점보다 늦게 출시된 후보의 비율, 정답 시점 이후의 학습 리뷰 비율을 집계해 먼저 보고한다. 보완은 위 **시간순 학습·검증·테스트 보완** 항목에서 진행한다.
- [ ] **리뷰가 적은 사용자 평가:** 기본 평가는 정답을 숨긴 뒤 리뷰 게임이 5개 이상인 사용자만 보고, v3 보조 평가도 3개 이상까지만 넓혔다. 학습 긍정 쌍 78,315,268개 중 긍정 게임이 2개 이상인 사용자의 쌍은 61,273,079개다. 따라서 긍정 리뷰가 1개뿐인 사용자가 약 1,704만 명으로 학습 사용자의 절반을 넘는다. 실제 서비스에서 가장 많은 사용자층이 평가에서 빠져 있는 셈이다. 남은 리뷰 게임이 1–2개, 3–4개인 사용자를 별도 집단으로 고정하고 입력 길이별 Recall@10·NDCG@10·빈 추천 비율을 보고한다. 기본 평가 결과와 개선량을 직접 비교하지 않으며, 위 **신규 게임·짧은 이력 사용자 평가**의 계정 사전 분리 원칙을 따른다.
- [ ] **리뷰하지 않은 게임을 오답으로 세는 한계 보고:** 정답 1개만 맞은 것으로 보므로, 사용자가 좋아할 수 있지만 아직 리뷰하지 않은 게임을 추천해도 실패로 센다. 그래서 절대 점수는 낮게 나오고, 사용자가 어차피 찾아 리뷰하는 인기 게임을 맞히는 모델이 유리할 수 있다. 정답 게임의 학습 사용자 수 구간별 결과를 계속 함께 보고한다. 인기 게임 정답의 비중을 낮춘 추가 확인 지표(예: 학습 사용자 수 역가중 Recall)를 검토하되, 가중치 정의는 평가 결과를 보기 전에 고정한다.
- [ ] **추천 목록의 다양성·새로움·커버리지 보고:** v1·v2 보고서에는 추천된 게임 수/6,630과 추천 게임의 학습 사용자 수 중앙값이 있다. 하지만 v3 지표 CSV와 Forgemaster 평가에는 같은 항목이 없다. 주요 평가마다 다음 네 가지를 같은 표로 보고한다: 추천된 게임 수(카탈로그 커버리지), 추천 노출이 일부 게임에 몰린 정도(예: 지니 계수), 추천 게임의 평균 학습 사용자 수(로그 기준), 목록 안 태그 기반 다양성. 정확도와 함께 보는 추가 확인 지표이며, 이것만으로 모델을 고르지 않는다.
- [ ] **싫어할 게임을 피하는 능력 확인:** 현재는 긍정 게임만 정답으로 쓴다. 부정 평가한 Linux 게임 1개를 함께 숨기고 제외 목록에서도 빼서 추천 가능하게 둔 뒤, 그 게임이 Top 10에 들어간 비율을 보고하는 보조 평가를 검토한다. 이 비율은 낮을수록 좋다. 부정 리뷰에는 가격·버그처럼 취향과 무관한 이유가 섞여 있으므로 해석용으로만 쓴다. v3의 부정 감점·후보 제외 실험은 모델이 부정 신호를 쓰는 방법이었고, 이 항목은 평가 쪽에서 확인하는 방법이다.
- [x] **n개 이상 적중률 평가 — v3 정답 2개 결과 집계 완료:** 기존 v3의 저장된 정답·추천 자료를 재사용해 4개 모델의 검증 217,720명과 frank 14,819명을 집계했다. 결과는 [정답 2개 적중률 보고서](../reports/multi_target_hit_rates_v3.md)와 [결과 CSV](../reports/tables/multi_target_hit_rates_v3.csv)에 있다.
  - **지표와 분모:** 각 집단에서 정답 2개가 있는 같은 사용자 집단을 분모로 고정해 1개 이상·2개 모두 적중률, 사용자당 평균 적중 수, Precision@10(적중 수 ÷ 10)을 보고한다.
  - **범위와 해석:** 이는 주지표와 모델 채택 기준을 바꾸지 않는 보고용 보조 평가이며, 기존 v3 결과를 재사용한 것이다. v4 확인 평가와는 별도 결과다. 리뷰하지 않은 게임은 계속 오답으로 세므로 n이 커질수록 이 한계의 영향이 커질 수 있다.
  - **미실행 확장:** 정답 3개를 숨기는 추가 평가와 n=3 지표는 아직 실행하지 않았다. 계정 분할에서 정답 m개를 숨긴 뒤 전체 입력 ≥5·긍정 입력 ≥1을 유지하면 평가 대상이 줄어들므로, 별도 범위로 다룬다.

### 모델 개선 후보

- [ ] **1순위 — 적중 교집합·상위 후보 포함률 진단 후 조건부 결합:** 사용자별 추천 산출물을 복원하고 같은 사용자·정답에서 두 모델 모두 적중, 한 모델만 적중, 모두 실패한 비율을 계산한다. 고정 모델로 상위 100개 후보를 생성해 모델별·합집합의 정답 포함률도 측정하며 정답을 후보에 추가하지 않는다. 진단 결과를 바탕으로 후보 게임의 학습 긍정 사용자 수, 사용자 입력 길이 등 추론 때 알 수 있는 특징으로 결합 비중을 학습한다. 추천할 때 숨긴 정답을 아는 것처럼 어느 모델을 쓸지 선택하지 않는다. 결합 모델 학습·설정 선택·최종 확인 계정을 분리하고, 기존 RRF와 LambdaMART 실험 및 현재 단일 모델을 대조군으로 둔다.
- [ ] **2순위 — RLAE·RDLAE:** EASE의 대각 제약을 완화하는 RLAE와, 입력 일부를 무작위로 가리는 효과도 반영하는 RDLAE를 검토한다. 같은 새 학습·검증 분할에서 Item-KNN 및 EASE와 비교하고, 전체 지표와 게임별·희귀 게임 지표를 함께 확인한다. 전체 카탈로그 행렬의 메모리와 계산 비용을 먼저 점검한다. 타 데이터에서의 개선을 이 프로젝트의 예상 향상 폭으로 사용하지 않는다. [SIGIR 2023 논문](https://arxiv.org/abs/2305.12922), [저자 구현](https://github.com/jaewan7599/RDLAE_SIGIR2023).
- [ ] **3순위 — 콘텐츠 표현을 학습 리뷰의 선호 관계와 정렬:** MARec·AlphaRec을 참고해 소개글·태그 등으로 만든 게임 표현을 학습 리뷰의 공동 선호 관계에 맞춰 학습한다. 기존 고정 MiniLM 평균 프로필, TF-IDF, 태그에서 ALS 벡터를 예측한 ridge 실험과 구분한다. 학습 계정의 리뷰만 선호 학습에 사용하고, 일반 게임과 학습 리뷰가 적거나 없는 게임을 나누어 평가한다. [MARec](https://arxiv.org/abs/2404.13298), [AlphaRec](https://arxiv.org/abs/2407.05441).
- [ ] **후순위 — SASRec 실제 학습·평가:** 기존 순차 모델 백로그의 미실행 범위를 이어간다. 시간순 평가를 정비한 뒤 이벤트 순서·동점 처리·학습 설정을 사전에 정하고 시간순 Item-KNN과 비교한다. 리뷰 작성 순서와 실제 구매·플레이 순서를 구분해 해석한다. [SASRec](https://arxiv.org/abs/1808.09781).

### 모델 후보

- [ ] **V4-1 · 높음 — DAN을 적용한 EASE:**
  - **방법:** 세 가지를 함께 바꾼다. 사용자 활동량으로 가중한 Gram(XᵀD_u^−βX), 게임 학습 사용자 수에 비례하는 대각 정규화(λ + p/(1−p)·n_i), 입력·후보 계수의 인기도 지수 조정(α)이다.
  - **기존 실험과의 차이:** `ease_lambda100_exact`(내부 검증 Recall@10 45.59%, 기준 3·4 탈락)는 공통 λ만 바꿨다. `activity_inverse_degree_cosine_k100`은 코사인 KNN이다.
  - **출발 범위:** α={0, .1, .2, .3}, β={0, .5, 1}, p={0, .3}. β가 바뀌면 Gram 규모가 달라지므로, λ 원값 비교와 λ 규모를 맞춘 비교를 구분한다. 학습 사용자 수가 0인 게임은 음수 지수 계산을 따로 처리한다.
  - **위험:** 인기도를 지나치게 억제하면 기준 1·2를 잃을 수 있다. 문헌에도 MSD에서 전체 NDCG가 낮아진 반례가 있다.
  - **비용:** Gram float32 5.66GB, Linux 후보 계수 약 1GB로 CPU에서 가능하다. 공식 코드처럼 float64 사본을 여러 장 만들면 RAM 33GB에서 위험하다.
  - **근거:** [논문](https://arxiv.org/abs/2504.05805), [구현](https://github.com/psm1206/DAN)
- [ ] **V4-2 · 높음 — RLAE의 ξ별 계산 재사용:**
  - **방법:** 같은 λ에서 P=(XᵀX+λI)⁻¹의 대각 원소 P_jj를 저장하면, 후보 점수는 EASE 점수에 max(λP_jj, 1−ξ)를 곱한 형태가 된다. 그러면 ξ={0, .25, .5, .75, 1}을 분해 한 번으로 비교할 수 있다. 이 식은 워커가 유도한 것으로, 구현 전에 확인한다.
  - **RDLAE 분리:** RDLAE의 p={0, .1, .3}은 분해를 다시 해야 하므로 따로 비교한다.
  - **저장:** v3 코드는 계산 뒤 분해 결과를 지우므로, v4 첫 계산부터 후보 6,630개의 대각 원소와 설정을 저장한다.
  - **확인할 것:** 배율이 모든 후보에서 같으면 순위가 바뀌지 않으므로 활성 제약 비율과 배율 분포를 함께 본다. 양수 배율은 같은 분해의 EASE 대비 빈 추천을 보존하지만, 현재 KNN 대비 기준 5는 따로 확인한다.
  - **근거:** [논문](https://arxiv.org/abs/2305.12922), [구현](https://github.com/jaewan7599/RDLAE_SIGIR2023)
- [ ] **V4-3 · 높음 — 추천 근거를 쓰는 제한된 잔차 gate:**
  - **방법:** s = q_CF + η·g·q_content로 점수를 낸다. q는 각 모델의 양수 점수를 사용자별 최댓값으로 나눈 값이고, g∈[0,1], η={0, .1, .25, .5}다.
  - **g의 특징:** 추론 시점에 알 수 있는 것만 쓴다. 남은 긍정 입력 수, 후보와 연결된 입력 수, 기여 유효 개수, 최대 기여 비중, 두 모델의 순위 동의, 10위와 11위의 점수 차, 콘텐츠 결측 여부다. 적중 교집합은 진단에만 쓴다.
  - **기존 실험과의 차이:** `selected_rrf_adaptive_0_5`(Recall@10 41.16%, 기준 3·4 탈락)는 학습 사용자 수만으로 비중을 정했다. v3 재정렬 특징 8개에는 입력별 기여 집중도와 근거 개수가 없다.
  - **기대와 한계:** 비음수 가산이라 기준 5는 구조적으로 보존되지만 기준 1–4는 보장하지 않는다.
  - **비교 순서:** 고정 비중, 기존 특징, 새 근거 특징 순서로 비교한다. 새로 맞힌 사용자와 잃은 사용자를 함께 보고한다.
  - **근거:** [FWLS](https://arxiv.org/abs/0911.0460)
- [ ] **V4-4 · 높음(선행 작업) — 학습 사용자 수 구간별 후보 예산:**
  - **방법:** v3 LambdaMART는 이전 대조군 두 모델의 양수 상위 50개씩을 후보로 썼다. 다음 세 구성을 비교한다.
    - 현재 모델 50+50
    - 단순 확대 100+100
    - 같은 최대 200개 예산의 구간 확보: CF 100 + 콘텐츠 50 + 콘텐츠 중 학습 사용자 수 1–99명 25 + 100–999명 25
  - **규칙:**
    - 중복을 제거한 뒤 빈자리를 채우는 순서를 고정하고, 실제 후보 수를 기록한다.
    - 양수 후보가 부족하면 200개 미만을 허용한다. CF의 양수 Top 10은 항상 포함한다.
    - 최종 Top 10에 희귀 게임을 강제로 배정하지 않는다.
    - 후보 정책을 바꾸면 재정렬기의 학습 후보도 같은 정책으로 만든다.
  - **근거:** Forgemaster 학습 사용자 수 100–999명 정답 25,092명에서 콘텐츠 Recall@10은 7.88%, 활동량 보정 KNN은 5.68%다. 외부 평가 값이므로 예산 튜닝에는 쓰지 않는다.
  - **보고:** 최종 적중은 후보 포함률을 넘을 수 없다. 전체·게임별·구간별 후보 포함률을 최종 지표와 연결해 보고한다.
- [ ] **V4-5 · 높음 — 게임 단위 KNN 교사 정렬:**
  - **v4 실행 후 추가 진단:** 첫 16개 학습 설정과 채널 결합은 비교했지만 추천 성능은 낮았다. 현재의 작은 코사인 회귀 목표와 미관측 쌍 상한은 두 집단의 상대 순위를 충분히 구분하지 못했다. 학습 그래프 20,000쌍 진단과 한계는 [실패 진단](../reports/alignment_diagnostic_v4.json)에 기록한다. 후속 단계에서는 알려진 관계와 약한 미관측 쌍 사이의 상대 순위 손실을 검토하고, 사용자 선택 라벨 대신 학습 그래프 안의 별도 관계 검증으로 학습 상태를 확인한다. 기존 결과를 덮어쓰지 않으며, 미관측 쌍을 확정 부정으로 취급하지 않는다.
  - **방법:** 고정 콘텐츠 벡터를 작은 MLP로 64/128차원에 투영하고, 현재 채택 Item-KNN의 게임 간 유사도를 재현하도록 학습한다.
  - **기존 실험과의 차이:** ALS 벡터를 예측한 `metadata_ridge_alpha100_*` 계열과 달리 교사가 KNN 관계이고, 사용자 ID 테이블이 없다.
  - **설계:**
    - 후보별 top100 그래프는 비대칭이다. 입력·후보 projector를 따로 두거나, 절단 전 대칭 코사인을 교사로 쓴다.
    - 표본은 상위 20/50 이웃과 약한 미표기 쌍을 1:1–1:4로 섞는다. 저장 이웃 밖의 0을 비선호로 보지 않는다.
    - 학습 사용자 수가 0인 게임은 손실에서 빼고 추론에만 쓴다.
  - **위험:** 콘텐츠가 더 잘 맞히던 희귀 구간이 교사 쪽으로 끌려갈 수 있다. 유사도 재현 오차를 채택 지표 대신 쓰지 않는다.
  - **비용:** 작은 MLP라 12GB GPU로 충분하다고 추산한다.
  - **근거:** [NFC](https://link.springer.com/article/10.1007/s11257-021-09303-w), [NFC 구현](https://github.com/cesarebernardis/NeuralFeatureCombiner), [MARec](https://arxiv.org/abs/2404.13298)
- [ ] **V4-6 · 중간 — 강한 고정 다국어 인코더와 필드별 표현:**
  - **현재:** `description_sentence_embedding`(Recall@10 0.54%)과 메타데이터 결합(6.20%)은 고정 MiniLM·128토큰·평균 프로필이었다.
  - **방법:** 같은 원문·집계에서 인코더만 바꾼다. 1차 후보는 Qwen3-Embedding-0.6B, 대안은 BGE-M3 dense 표현이다. 길이 512/1,024토큰을 비교한 뒤, 소개글과 구조화 메타데이터를 별도 채널로 나눈다. 모델별 공식 pooling과 정규화를 따른다.
  - **비용:** 512토큰 상한이면 한 채널에 최대 약 1,926만 토큰이다. 처리량 가정에 따라 약 1–5시간이 걸린다.
  - **위험:** 유명 게임명이나 홍보 문구를 연결해 기준 3·4가 나빠질 수 있다.
- [ ] **V4-7 · 중간 — 제약 위반에 반응하는 다목적 재정렬:**
  - **현재:** `lambdamart_300_trees`(Recall@10 42.53%)는 기준 3·4에서, `lambdamart_300_trees_game_weighted`(39.88%)는 기준 2에서 탈락했다.
  - **방법:** 고정 가중 대신, 게임별 동일 가중 손실과 학습 사용자 수 1–999명 정답 손실에 상한을 둔다. 상한을 넘으면 multiplier를 갱신한다(AL-LM 방식).
  - **출발 범위:** 15 leaves, 100/300 trees, μ={1, 10}. 정답 구간은 학습 손실 구분에만 쓰고 추론 특징에는 넣지 않는다.
  - **한계:** LightGBM LambdaMART에 바로 쓸 수 있는 공식 구현이 확인되지 않았다. surrogate 제약이 실제 기준 1–5를 보장하지도 않는다.
  - **근거:** [AL-LM](https://arxiv.org/abs/2002.05753)
- [ ] **V4-8 · 중간 — fSLIM:**
  - **방법:** 입력 이웃 m={200, 500} 안에서 비음수 L1+L2 회귀로 Linux 후보 열의 계수를 학습한다. L2는 100/1000, L1은 열별 λ_max 대비 {0, .001, .01}이다.
  - **기존 실험과의 차이:** `min_cooccurrence_*`, `lift_selected_cosine_scored_k100`, `unpruned_cosine`은 이웃 선택과 유사도만 바꿨다.
  - **위험:** L1이 희귀 게임 열을 모두 0으로 만들면 기준 4·5가 나빠진다. 같은 이웃 집합의 KNN과 비교하고, 열별 0 계수율을 보고한다.
  - **근거:** [SLIM 문서](https://github.com/KarypisLab/SLIM/blob/master/doxygen/documentation.dox)
- [ ] **V4-9 · 중간 — 리뷰별 정규화·해시 표본·대표 벡터:**
  - **현재:** `train_review_body_tfidf`는 App ID 263340을 99.35%의 사용자에게 추천했다. 원본 순서로 게임당 최대 100개, 총 2,250,919개 리뷰를 게임별 한 문서로 합친 결과다.
  - **방법:**
    1. 리뷰 ID 해시 표본 16/32개, 리뷰당 128/256토큰 상한을 두고 반복 문구를 진단한다.
    2. 리뷰별로 정규화한 TF-IDF의 평균과 비교한다.
    3. 고정 임베딩과 대표 벡터 1/3개를 비교한다.

    메타데이터에는 {0, .05, .1, .25}의 작은 비중으로 더한다.
  - **주의:** 기존 first100 캐시를 섞으면 해시 표본이 되지 않으므로 원본을 다시 읽어야 한다. 쏠림이 줄어도 정확도가 오르는 것은 아니다.
  - **비용:** 임베딩을 쓰면 최대 약 1.5억 토큰, 처리량 가정에 따라 약 9–43시간이다.
- [ ] **V4-10 · 중간 — 계정별 공동 리뷰 쌍 기여량 조절:**
  - **근거:** 긍정 게임이 d개인 계정은 d(d−1)/2쌍을 만든다. 1/d로 가중해도 총 기여는 (d−1)/2로 커진다.
  - **방법:** w_u = (1−ρ)/d_u + ρ/(d_u·max(1, d_u−1)), ρ={0, .25, .5, 1}. 먼저 현재 이웃을 고정하고 가중치만 바꾸며, 이웃 재선택은 따로 비교한다. 긍정 리뷰가 1개인 계정도 그대로 유지한다.
  - **위험:** 활동 계정은 학습 사용자 수 10–99명 게임 근거의 28.0%도 제공한다. 그래서 기준 1–4가 모두 위험하며, V4-1보다 후순위다.
- [ ] **V4-11 · 중간 — 작은 결합 모델에 Group DRO·CVaR 적용:**
  - **방법:** 내부 학습 부분에서 긍정 입력 길이(1 / 2–4 / 5+) × 입력 게임 학습 사용자 수 3구간으로 집단을 고정한다. 작은 gate에 집단별 최악 손실을 섞거나(강도 {0, .1, .25, .5}), CVaR({.1, .25, .5})를 적용한다.
  - **근거:** 긍정 입력 수 중앙값은 내부 검증·frank 모두 7이지만, 입력 게임의 학습 사용자 수 중앙값은 49,616과 162다. 외부 분포에 맞춰 집단 경계나 가중을 정하지 않는다.
  - **위험:** 잡음이 많은 집단에 집중하면 기준 2·3·4를 잃을 수 있다. 정규화와 조기 종료를 둔다.
  - **근거 자료:** [추천 DRO](https://arxiv.org/abs/2501.18117), [Group DRO](https://arxiv.org/abs/1911.08731)
- [ ] **V4-12 · 낮음 — 원문 근거가 붙은 LLM 게임 프로필:**
  - **방법:** 공개 소개글에서 고정 스키마(게임 방식, 시점, 협동·경쟁, 진행 형태, 분위기)를 원문 근거와 함께 추출한다. 명시되지 않은 값은 null로 둔다. LLM 없이 같은 필드를 채운 템플릿을 필수 대조군으로 둔다.
  - **범위:** 공개 정보가 전혀 없는 Linux 후보 10개는 이 방법으로 복구할 수 없다.
  - **비용:** 게임당 입력 1,024토큰·출력 256토큰이면 생성에만 수십–백여 GPU 시간이 걸린다(가정).
  - **근거:** [LLM-Rec](https://aclanthology.org/2024.findings-naacl.39.pdf)

### 평가 보완의 구체화

위 「먼저 보완할 평가」와 「실제 추천 상황과의 차이 보완」 항목을 실행할 때 참고할 세부 기준이다.

- **계정 역할:**
  - 기초 모델 학습, 결합·재정렬 학습, 설정 선택, 마지막 확인으로 나눈다.
  - 기존 3-fold cross-fitting으로는 여러 설정 중에서 고르는 선택 편향이 없어지지 않는다.
  - 이미 본 내부 검증 사용자를 다시 나눠도 새 확인용 자료가 되지 않는다.
  - 짧은 이력 확장 계정은 기초 모델 학습 전에 제외한다.
- **시간 경계:**
  - 공통 T0/T1/T2로 학습 기간, 선택용 정답 기간, 확인용 정답 기간을 나눈다.
  - 다음 항목도 추천 시점에 맞춘다: 입력과 제외 목록, 학습 사용자 수와 인기 통계, 출시 여부(가능하면 Linux 지원 여부), 리뷰 수정, 누적 플레이타임.
  - 현재 메타데이터만 쓸 수 있으면 "상호작용 시간만 통제한 평가"로 표시한다.
- **신뢰구간:**
  - 고정 정답에서 전체 평균 차이: 같은 사용자끼리 짝지어 bootstrap한다.
  - 게임별 평균 차이: 게임 집합을 고정하고 게임 안에서 사용자를 재표집한다.
  - 정답 시드에 따른 변동: 같은 사용자의 결과를 묶는다. 사용자×시드 행을 독립 표본으로 보지 않는다.
  - 재학습과 설정 선택에 따른 변동은 고정 예측 bootstrap에 포함되지 않는다.
  - 여러 최종 후보를 확인할 때의 다중 비교 처리와 허용 감소폭은 결과를 보기 전에 정한다.
- **인기도 역가중:**
  - 관측 확률을 식별할 수 없으므로 불편향 IPS라고 부르지 않는다. 민감도를 보는 추가 확인 지표로 부른다.
  - 가중은 w_i = min(W, [n_ref/(n_i+a)]^γ), γ={0, .5, 1}, W={10, 50}로 둔다.
  - 유효 표본 수와 최대 게임 기여율을 함께 적는다. 학습 사용자 수가 0인 게임은 smoothing하고 따로 표시한다.
- **후보 단계의 분모:**
  - 최종 평가는 계속 Linux 6,630개를 기준으로 한다.
  - 후보 밖 정답도 분모에 남기고, 정답을 후보에 억지로 넣지 않는다.
  - "정답 + 무작위 99개" 같은 표본 후보 평가로 바꾸지 않는다.
- **짧은 이력과 신규 게임:**
  - 남은 전체 리뷰 수(1–2 / 3–4 / 5+)와 긍정 입력 수(1 / 2 / 3–4 / 5–9 / 10+)를 구분한다.
  - 정답을 숨긴 뒤 입력이 0이면 무입력 집단으로 따로 표시한다.
  - 신규 게임 평가는 해당 게임의 학습 상호작용을 모두 빼고, 교사 그래프와 학습 사용자 수를 다시 만든다.
  - 학습 사용자 수가 적은 게임과 0인 게임은 다른 집단으로 본다.
- **정확도 외 지표:**
  - 커버리지: 추천된 고유 게임 수/6,630
  - 노출 지니·엔트로피: 추천되지 않은 게임까지 포함해 계산
  - 새로움: smoothing한 학습 사용자 수로 구한 음의 로그 확률
  - 목록 내 다양성: 태그 거리 기준. 목록 길이가 2개 이상인 사용자 수를 분모로 따로 적음
  - 평균 추천 길이와 빈 추천 수를 함께 적는다.
  - 숨긴 부정 게임의 포함률을 미관측 게임 전체의 거짓 양성률로 해석하지 않는다.

2026-11-08에는 두 v1 모델의 학습·평가와 v2 진단·개선 비교를 완료했다. 이후 과제로 남겨 둔 태그·장르 보강은 v2에서 비교했다. 부정 신호, 여러 정답, 전체 입력 ≥3, 다른 입력 집계 방식, 인기순 보완은 v3에서 별도 실험했다. 완료 상태는 [v1 결과](../reports/baseline_v1.md), [v2 실행 결과](../reports/model_improvement_v2.md), [모델 실행 안내](baseline_models.md)를 기준으로 구분한다.

이 문서에서 긍정 사용자 수는 학습에서 해당 게임을 긍정 평가한 사용자 수를 뜻한다.

**분할 생성 완료:** `split_v1`, seed **20261107**로 전체 train/validation 자료, Item-KNN의 긍정 학습 입력, 검증·frank 평가의 입력 이력·정답, 사용자 명단과 제외 목록을 저장하고 전체 데이터를 검증했다. 학습에 사용한 긍정 리뷰는 **78,315,268쌍**, 검증 평가는 **325,639명**, 테스트는 **24,342명**이다. 실제 경로와 검증 근거는 [분할 파일 안내](modeling_splits.md)에 기록했다.

2026-11-08에는 소개글·토큰·TF-IDF 인덱스·코사인 검색도 준비했다. [콘텐츠 준비 결과](tfidf_content.md)에 사용 가능한 범위와 한계를 기록했다. Item-KNN(K=100) 학습과 고정 사용자 전체에 대한 공통 검증·frank 테스트도 완료했다.

| 모호 리뷰 처리 | 모호한 리뷰는 분석에서 제외한다. 제외한 게임 수와 모델별 점수 산출 가능 여부를 기록한다. |
| 숨김 후 입력 | 정답을 숨긴 뒤 남은 적격 리뷰 이력을 사용한다. 긍정 리뷰만 취향과 점수 계산에 쓰고, 이미 리뷰한 긍정·부정 게임은 다시 추천하지 않는다. 입력의 시간 순서는 제한하지 않는다. |

태그와 장르는 베이스라인 소개글에 섞지 않는다. 같은 평가 방식에서 모델이나 특징을 비교할 때는 사용자, 숨긴 정답, 후보 범위를 같게 맞춘다. 보강 점수의 비중과 전처리 설정은 내부 검증 자료로 선택한다.

## 모델 개선 실행 — v2 완료

2026-11-08 사용자가 승인한 네 단계 실행을 완료했다. 실행의 목적·절차·완료 조건은 [실행 절차와 시각화](model_improvement_execution.md)에, 실험값·성능 저하를 함께 확인하는 보조 지표·채택 기준은 [v2 프로토콜](../data/reference/improvement_protocol_v2.json)에 기록했다. 기존 v1 규칙과 결과는 보존했다. 최종 검증 설정은 [모델 선택 기록](../data/reference/improvement_selection_v2.json)에서 확정했다. Item-KNN은 보조 기준에 따라 v1을 유지했고, 콘텐츠 모델은 T2+메타데이터 50:50을 선택했다. 고정한 모델의 frank 참조 평가도 완료했으며 자동 테스트 85개가 통과했다.

**재현 결과 확인:** [재현 스크립트](../scripts/reproduce_improvement_review.py)와 [집계](../reports/baseline_review_reproduction_v2.json)에 v1 성능·해시값·인기도 기준선, 저장된 연결의 공동 리뷰 수, 결측, 추천 쏠림, 이미 확인한 frank 자료에서 사후 계산한 코사인 민감도를 기록했다. 아래 내용은 중간 검토 기록의 해석을 보완한 것으로, 당시 기록과 구분한다.

- 46.1%는 Linux 후보 토큰 수 80분위 경계 **45토큰 초과** 게임의 추천 자리 비중이다. 경계 동점 때문에 이 게임은 정확한 상위 20%가 아니라 1,252/6,630개(18.88%)다. App ID 동점 규칙으로 정확히 20%인 1,326개를 고르면 47.12%다.
- 불용어 21개 목록·분모가 남지 않아 해당 가중치 비중은 원래 정의대로 재현하지 못했다. T0의 명시한 단어 목록/DF와 실제 점수 기여를 새 근거로 사용한다.
- 소개글 결측 5.81%는 **고정한 소개글만 쓰는 T1~T3**의 지원 한계를 나타낸다. 태그·장르를 추가하는 T4나 새 정보원을 쓰는 모든 TF-IDF 설정이 불가능하다는 뜻은 아니다.
- 인기도 구간 재가중은 기술적으로 분포를 맞춰 보는 근사치이지 인과 설명이 아니다. validation에 train 긍정 사용자가 0명인 정답이 없다는 점도 전제로 명시한다. validation 가중치나 사용자 명단을 frank에 맞추지 않는다.
- 추천 게임의 train 긍정 사용자 수와 입력–후보 사이의 공동 사용자 수는 서로 다른 통계다. 희귀 게임 추천의 중앙값만으로 약한 연결이 해롭다고 확정하지 않는다.
- 두 Top10 적중의 합집합 12.25%는 실제 결합 모델 성적이 아니다. 0.91%는 **Item-KNN 정답 점수가 0인 사용자**의 조건부 TF-IDF 적중률이며, 추천 목록 전체가 빈 사용자만의 성적이 아니다. 코사인 조건으로 사용자를 뺀 수치도 사후 진단이고 공식 지표·튜닝 기준으로 사용하지 않는다.

2026-11-08에는 [Item-KNN·TF-IDF 개선 기획안](model_improvement_plan.md)을 실행했다. 기존 v1의 확정 규칙과 완료 결과는 유지하고, 아래 v2 진단·검증은 별도 버전으로 수행했다. 실제 성능, 보조 기준, 최종 선택은 [v2 실행 결과](../reports/model_improvement_v2.md)에 기록했다.

- [x] **완료 — Item-KNN 연결 실패 분해(K0):** 정답의 train 긍정 사용자 수가 0명인 경우, 모든 긍정 입력 게임의 train 긍정 사용자 수가 0명인 경우, 원시 연결 없음, 이웃 제한으로 연결 소실, 순위 실패, 적중 등 전체 여섯 범주를 기록했다. 검증 325,639명과 frank 24,342명의 합계, v1의 0점·적중 수를 재현했다. frank 결과는 이미 확인한 참고 자료다.
- [x] **완료 — Item-KNN 이웃 수·감쇠(K1/K2):** 미리 정한 K=100/200/500 × λ=0/10/50의 9개 조합을 내부 검증했다. 감쇠를 적용한 뒤 원시 연결 전체에서 이웃을 다시 골랐고, K100/λ0 결과가 v1과 완전히 일치하는지 확인했다. 전체 평균은 좋아진 후보도 게임별 평균과 긍정 사용자 수 1–999 구간의 보조 기준을 통과하지 못해 v1을 유지한다.
- [x] **완료 — TF-IDF 진단·단독 변경(T0~T3):** 341개 층화 사례·7,243개 단어 기여를 저장하고 sublinear TF, unigram+bigram, 조건부 max_df=0.5를 각각 비교했다. 고빈도 단어의 오추천 기여 19.31%로 T3 실행 조건을 충족했다. 소개글 단독 최선은 T2이며 T4 전에 고정했다.

태그·장르 보강(T4), 다국어 분절과 입력 집계는 아래 기존 백로그와 연결한다. 기존 frank는 이미 관측된 참조 테스트로 구분하고, 후속 설정 선택은 train/validation에서만 수행한다.

## 구현 백로그

- [x] **완료 — 소개글 TF-IDF 입력과 검색:** A `description` 우선·C `short_description` 결측 보충 원문·정리 텍스트·토큰·출처를 저장했다. 기본 단어 TF-IDF와 L2 정규화 벡터, 긍정 입력 동일 가중 평균·Linux 코사인 검색을 구현·검증했다. ## 중간점검에 따른 수정 계획

2026-11-07의 [의심점 판정](../reports/kieran_frank_midpoint_audit.md)을 구현 작업으로 옮긴 계획이다. 학습 범위, 소개글 형식, 최소 입력 조건, 동일 가중 평균, 빈자리 유지, 모호한 리뷰 제외는 **사용자가 확정했다**. 분할 파일과 소개글·토큰·TF-IDF 인덱스·검색 기능을 구현하고 검증했다. Item-KNN 학습과 고정 사용자 전체에 대한 추천·평가도 구현하고 실행했다. 아래 추가 평가는 v3의 별도 보조 평가로 진행했으며 기본 평가 조건은 유지했다. 조건이 충족되지 않아 실행하지 않은 후속 작업은 문서 상단 상태표에 표시했다.

학습 전 네 가지 변경점의 선택지·장단점·선택 근거는 [학습 전 변경점 조사](pretraining_options.md)에 정리했다. 해당 문서의 상태표에도 이번 확정을 반영했다.

### 별도로 선택할 후속 작업

- [x] **v3 실험·진단 완료 — 예약 계정 Kieran 보조 평가:** 예약 계정 64,110명의 Kieran 보조 명단을 고정하고 대조군·선택 모델을 평가했다. 학습으로 되돌리지 않았고 frank와 사용자 중복이 있어 독립 표본으로 합산하지 않는다. [v3 결과](../reports/model_improvement_v3.md).
- [ ] **모호 리뷰 복구 참고:** 현재 베이스라인은 모호한 리뷰를 분석에서 제외하는 것으로 확정했다. 나중에 독립적인 App ID 연결 근거를 확보하면 별도 변경으로 검토한다. 리뷰를 복구할 때는 정제 버전, 품질, 분할, 긍정 사용자 수를 다시 확인한다.
- [ ] **Linux/게임 카탈로그 갱신:** 최신 게임과 현재 Linux 지원 현황을 평가할 필요가 있을 때 별도 버전을 만든다. 평가 대상 사용자 범위가 바뀌면 새 테스트 계정 예약 범위를 계산하고, 기존 예약 계정도 포함해 계정 분리를 다시 확인한다.
- [x] **v3 실험·진단 완료 — 아이디어 — 검증 샘플링 보완:** 아래 게임별 리뷰 수 제한 보조 검증을 수행했다. 주 검증·채택 기준을 바꾸거나 frank 추출 분포를 재현했다고 주장하지 않는다. [v3 결과](../reports/model_improvement_v3.md).

분할과 누수 검사, Item-KNN 학습, 두 모델의 전체 사용자 추천, 공통 기준선과 긍정 사용자 수 진단을 완료했다. K=100과 기존 TF-IDF 설정, NDCG@10 우선·Recall@10 보조 기준, train 긍정 사용자 수 구간을 성능 확인 전에 확정했다. 검증 자료를 다시 학습하거나 조정하지 않았다. 이후 설정은 내부 검증으로만 선택한다. 추가 평가를 채택할지도 해당 테스트 결과를 확인하기 전에 정한다.

## 중간점검 의심 사항의 검증 결과

2026-11-07에는 로컬 자료를 바꾸지 않고 다시 집계했다. 사용자별로 추천 후보에서 제외할 게임을 반영해 무작위 기준선과 인기도 기준선의 기대값도 계산했다. 자세한 근거와 한계는 [중간점검 판정 보고서](../reports/kieran_frank_midpoint_audit.md)에 기록했다. 아래 체크 표시는 **의심점을 확인했다**는 뜻이다. 개선 조치를 했거나 모델 학습·최종 분할을 완료했다는 뜻도, 미정 규칙에 대해 사용자가 승인했다는 뜻도 아니다. [기존 진단 관측값](../reports/kieran_frank_eval_diagnostics.json)은 당시 기록으로 보존한다.

- [x] **frank 정답 분포 차이 — 확인:** 사용자별 후보 제외를 반영했을 때 인기도 기준 Recall@10 기대값은 0.05814%, 무작위 기준은 0.15093%다(전체 입력 ≥5, 24,571명). 인기도 기준이 무작위보다 낮다는 의심이 확인됐다. 이 값은 최종 seed를 정하기 전 계산한 기대값이다. 이후 고정 명단에서 측정한 Item-KNN·TF-IDF 성능과 실제 인기도 기준선은 [베이스라인 보고서](../reports/baseline_v1.md)에 따로 기록했다.
- [x] **검증·테스트 분포 차이 — 확인:** 전체 입력 수 조건이 같은 Kieran validation에서 인기도 기준 Recall@10 기대값은 31.96755%로 frank와 크게 다르다. 이 차이는 validation에서 선택한 설정이 실패했다는 증거가 아니다. 모델 설정은 계속 내부 검증에서만 선택한다.
- [x] **알려진 긍정 이력 누락 — 확인:** 사용자의 88.5%에게 Kieran-only 긍정 Linux 이력이 있으며, 모두 합해 398,893쌍이다. 이 게임들이 관측되지 않았다는 이유만으로 부정 학습 라벨을 붙인 것은 아니다. 다만 단일 정답 회수 지표가 불완전해지는 문제는 실제다. 이 긍정 이력을 후보 제외 목록에 추가하면 인기도 기준 Recall@10 기대값은 0.07578%로 바뀐다. 이 이력은 학습에 사용하지 않았고 숨긴 정답은 추천 후보로 되돌렸다.
- [x] **예약 계정 Kieran 보조 평가 — 구성·평가 완료:** 긍정 입력이 남아 있는 사용자 64,110명을 v3에서 평가했다. frank에서 긍정 입력을 보유한 사용자 24,342명 중 21,038명과 겹치므로 독립 사용자 표본이나 외부 테스트 대체재가 아니다. frank만으로 평가할 수 없다는 결론은 맞지 않으며, 이 보조 평가는 주 평가를 대체하지 않는다.
- [x] **모호한 리뷰 제외로 인한 앱별 손실 — 확인, 일괄 복구 근거 부족:** 332,865개 ID·686,161행이 31개 조합·63개 앱에 집중되어 있으며, **55개 앱은 원 리뷰 전체를 분석에서 제외했다**. 326,403개 ID는 비교할 수 있는 필드에서 앱 ID만 다르고, 6,462개는 다른 필드도 다르다. 카탈로그 앱이 하나인 22개 조합의 329,756개 ID도 앱 연결이 올바르다는 증거가 되지 않는다. 원 게시물 같은 별도 연결 근거 없이 카탈로그 소속만으로 리뷰를 복구하지 않는다. 227쌍·긍정 Linux 31쌍은 안전한 frank 이력과 분석 제외 앱 조합이 겹친 수이지 복구할 수 있는 리뷰 수가 아니다.
- [x] **Item-KNN 규모 표현 — 범위 구분:** 84,791,317은 모든 게임의 학습 긍정 쌍 수다. 확정된 고정 카탈로그 안의 긍정 쌍은 78,315,268개이며, 이 가운데 긍정 게임이 ≥2개인 사용자에게서 나온 쌍은 61,273,079개다. 긍정 리뷰가 하나뿐인 사용자도 정규화 빈도 계산에 포함하므로 마지막 수만을 전체 학습 규모로 쓰지 않는다.
- [x] **시점 차이 — 확인 및 범위 정정:** Kieran 리뷰는 2023-11-04, frank 리뷰는 2025-11-19에 끝난다. 2025년 원 리뷰 비중은 37.8%, Kieran 종료 이후 작성된 것으로 기대되는 정답 비중은 약 43.5%다. 마지막 출시일 2023-10-24는 A 전체 자료의 값이고 실제 입력·Linux 정답 카탈로그는 **2023-08-24**까지다. 카탈로그 밖 게임 비중은 예약 계정 전체에서 22.5%, 입력 ≥5 집단에서 22.9%다. 취향 변화나 신규 게임에 대한 일반화 성능이 입증된 것은 아니다.
- [x] **학습 긍정 근거 부족 — 확인:** Linux 후보 6,630개 중 36개는 학습 긍정 사용자 수가 0명이며, 이를 포함해 224개는 5명 미만이다. 전체 입력 ≥5 집단에서 선택 정답의 기대 비중은 긍정 사용자 수 0명일 때 0.21583%, 1~4명일 때 0.43003%다. 모델별로 사용자나 정답을 제외하지 않고 점수 산출 가능 여부를 보고한다. 개인화 점수가 없는 자리는 비우는 것이 베이스라인 정책이다.
- [x] **소개글 길이·정보량 차이 — 확인, 성능에 미치는 영향은 미확인:** A의 짧은 소개글과 C의 긴 소개글 길이 중앙값은 211자·1,142자다. 확정한 A 우선·C 짧은 소개글 보충 규칙은 입력 37,531/37,610개, Linux 후보 6,613/6,630개를 포함한다. 두 출처의 짧은 소개글이 같은 비율 88.4%도 다시 확인했다. 실제 원문을 고정하고 전처리해야 한다.
- [x] **Linux 표시 불일치 — 확인, 원인은 미확인:** A에는 비Linux, C에는 Linux로 표시된 앱 137개, 반대 사례 52개, A에서 Linux로 표시됐지만 C에 없는 앱 534개를 다시 확인했다. C에 없는 앱이 Linux를 지원하지 않는다는 뜻은 아니다. 현재 평가 정답 기대 비중에서 약 0.64%는 C에 비Linux로 표시됐고 약 4.99%는 C에 수록되지 않았다. 시점 변화와 수집 오류 중 무엇이 원인인지는 자료만으로 판단할 수 없어 고정 카탈로그를 유지했다.

검증 뒤 실행할 작업과 선택 사항은 위 **중간점검에 따른 수정 계획**에서 관리한다. 의심점을 확인한 표시와 실제 구현 완료를 구분한다.

## 베이스라인 v1 중간 검토 후속 작업

아래 작업은 2026-11-08에 v1을 변경하지 않고 중간 검토하면서 시작했다. 당시 지표와 사용자 2,000명의 추천을 다시 계산하고 누수·해시값을 확인한 결과, 자동 테스트 53개에서도 차이가 없어 [v1 결과](../reports/baseline_v1.md)를 유지했다. 이후 [재현 스크립트](../scripts/reproduce_improvement_review.py), K0/T0 산출물, v2 실험으로 확인한 항목은 완료로 표시했다. 아직 확인하지 못한 원인과 후속 작업은 남겼다.

실험 후보와 순서는 [개선 기획안](model_improvement_plan.md)의 K·T 항목을 따른다. 이 절에는 기획을 실행하기 전에 정할 사항과 근거가 되는 수치만 적는다.

### 튜닝 전에 처리할 작업

- [x] **완료 — 검증 선택 기준 보완:** 전체 NDCG 우선·Recall 보조 기준을 유지하고, 로그 긍정 사용자 수 구간, 정답 게임별 평균 NDCG, 긍정 사용자 수 1–999인 게임의 NDCG, 빈 목록, paired-bootstrap을 추가했다. 미리 정한 보조 기준 하나라도 통과하지 못하면 v1을 유지한다. v1 구간 경계 `[19,67,413.75]`와 결과는 보존한다.
- [x] **완료 — K0·K1 사전 관측 반영:** 이웃 제한으로 빠진 연결은 validation 55,487명·frank 13,448명에서 다시 확인했다. frank에서 나머지 정답 0점 사용자 4,371명은 정답의 긍정 사용자 수가 0명인 52명, 입력 게임의 긍정 사용자 수가 0명인 3명, 원시 연결이 없는 4,316명으로 나뉜다. 공동 리뷰 ≥5로 새로 연결되는 frank 사용자 5,278명은 전체의 21.68%, 0점 사용자 중 29.62%다. 저장된 연결 가운데 공동 리뷰 사용자가 1명인 비율 56.7%, 5명 미만인 비율 79.4%를 재현했다. 3×3 실험으로 K와 감쇠의 상호작용도 확인했다. frank 값은 설정 선택에 사용하지 않았다.
- [x] **완료 — TF-IDF 소개글 결측 영향 구분:** Linux 17개·검증 18,921명(5.81%)·frank 34명(0.14%)을 다시 확인했다. 고정 소개글만 쓰는 T1~T3에서 생기는 지원 손실로 보고하되 공식 지표의 분모에는 계속 포함한다. T4 메타데이터도 없는 검증 정답은 18,884명이므로, 메타데이터를 추가해도 결측 손실 대부분은 해소되지 않는다. 새 소개글 출처는 별도 버전의 후속 작업으로 남겼다.
- [x] **완료 — T0 추천 쏠림 정의·기여 검증:** 46.1%는 45토큰 초과·후보 18.88%의 비중으로 정정했고 정확한 상위 20%는 47.12%다. 원래 불용어 21개 목록·분모는 재현 불가로 남겼다. 고정 층화 사례의 실제 단어 기여를 저장하고 T3의 사전 실행 조건을 확인했다. 추천 쏠림의 단일 원인이 입증된 것은 아니다.
- [x] **완료 — 이번 추가 평가 범위 확정:** 검증 자료에서 최종 설정을 확정한 뒤 그 모델만 frank 참조 평가에 사용한다. 예약 계정 보조 평가와 Kieran-only 긍정 민감도는 이번 v2에서 다루지 않고 아래 후속 항목으로 남겼다. 기존 frank 자료를 다시 사용하는 평가를 새로운 독립 최종 검증이라고 부르지 않는다.

### 해석과 보고서 보완

- [x] **완료 — 검증·테스트 차이의 표현:** frank의 긍정 사용자 수 분포에 맞춰 validation 성적을 다시 가중한 Recall 약 7.30%/2.24%를 재현했다. 이는 분포 차이를 설명하는 근사치이지 성능 차이의 인과적 분해가 아니다. validation 가중치나 사용자 명단을 바꾸거나 일반화 성능이 하락했다고 단정하는 데 사용하지 않는다.
- [x] **v3 실험·진단 완료 — 같은 인기도에서 frank가 더 높은 이유 조사:** 긍정 사용자 수 100–999명인 집단을 전체 데이터에서 다시 집계했다. 입력 수, 최대 콘텐츠 유사도 같은 연관성을 기록했지만 성능 차이의 인과 원인은 확인하지 못했다. `backlog_diagnostics_v3.json`과 [v3 결과](../reports/model_improvement_v3.md)를 참고한다.
- [x] **v3 실험·진단 완료 — 시리즈작·중복 소개글 영향 분리:** 제목을 정규화한 결과, 소개글이 같은 게임, 유사도가 높은 게임을 따로 집계했다. 실제로 가장 유사한 입력·제목 사례도 저장했다. 공식 분모는 유지한다. 시리즈나 에디션이 같은 상품인지는 별도 App ID 근거가 있어야 한다. [v3 결과](../reports/model_improvement_v3.md).
- [x] **완료 — frank 희귀 게임 추천 분포 보고:** v1 추천 게임의 긍정 사용자 수 중앙값 183,070명/57명을 재현하고 v2 후보별 긍정 사용자 수 중앙값과 커버리지도 추가했다. 추천 게임의 긍정 사용자 수와 입력–후보 연결의 공동 사용자 수는 별개의 값이다. 희귀 게임 추천 자체를 품질 저하로 해석하지 않는다.
- [x] **완료 — 보고서에 보조 진단 추가:** 로그 긍정 사용자 수 구간, 사용자 수와 게임 수, 인기도 기준선, 게임별 평균, paired-bootstrap 신뢰구간, 빈 목록, 추천 커버리지, 긍정 사용자 수 중앙값, 계산 비용을 추가했다. 긍정 사용자 수가 적은 구간의 작은 표본과 validation에 train 긍정 사용자가 0명인 정답이 없다는 한계를 적었다.
- [x] **v3 실험·진단 완료 — 후속 — Item-KNN·콘텐츠 모델 결합:** 실제 RRF 순위 결합과 후보 게임의 학습 긍정 사용자 수에 따른 콘텐츠 점수 비중을 비교했다. 정답을 알고 두 모델의 top10을 합쳐 적중한 결과는 실제 추천 성능으로 사용하지 않았다. [v3 결과](../reports/model_improvement_v3.md).

## v2 이후 성능 개선 아이디어

2026-11-08에 v2 결과, 데이터 특징, 공개 방법론을 함께 살펴 정리한 아이디어의 실행 이력이다. 아래에는 v3에서 실제로 실험·진단한 상태를 반영했다. 최초의 기대나 가설을 측정 결과인 것처럼 바꾸어 해석하지 않는다. 일부 아이디어는 이미 확인한 frank 결과에서 시작했으므로, frank를 다시 평가해도 독립 검증은 아니며 설정 선택에 사용하지 않는다.

## 부정 리뷰 베이스라인과 후속 실험

첫 번째 방법을 베이스라인으로 선택했고, 나머지는 후속 실험으로 남겼다. 부정 리뷰를 자료에 보존하는 것과 학습이나 추천 점수에 실제 사용하는 것은 다르다. 평가 사용자가 남긴 입력 이력에 있는 게임은 긍정·부정 모두 다시 추천하지 않는다. 숨긴 정답은 입력 이력과 취향 계산에서 제외하고, 후보 제외 목록에서는 빼서 추천할 수 있게 한다. 아직 리뷰하지 않은 게임을 부정 평가로 간주하지 않는다.

| 방법 | 적용 위치 | 동작 | 장점·한계 |
|---|---|---|---|
| **확정 베이스라인 — 긍정 신호만으로 순위 계산** | 사용자 입력 집계 | 긍정 리뷰 게임만 취향 벡터와 추천 점수에 사용한다. 부정 리뷰한 게임은 다시 추천하지 않는다. | 단순한 비교 기준이다. 다른 비슷한 게임에 부정 신호를 전달하지 않는다. |
| 후속 — 부정 게임 유사도 감점 | 사용자 입력 집계·후보 점수 | 긍정 게임과의 평균 유사도에서 부정 게임과의 평균 유사도에 감점 계수를 곱한 값을 뺀다. | 기존 TF-IDF와 양의 Item-KNN 유사도를 유지하면서 적용할 수 있다. 가격이나 버그 때문에 싫어한 게임도 취향에 맞지 않는 것으로 확대 해석할 수 있다. |
| 후속 — 부정 게임의 유사 후보 제외 | 후보 필터 | 부정 리뷰한 게임과 유사도가 일정 값 이상인 새 후보를 제외한다. | 피하고 싶은 게임을 명확히 반영한다. 임계값에 따라 추천 후보가 지나치게 줄 수 있다. |
| 후속 — 학습에 긍정·부정 관계 반영 | Item-KNN 유사도 학습 | Kieran 학습 리뷰에서 긍정–긍정, 긍정–부정 등의 관계를 나누어 이웃과 추천 점수를 계산한다. | 집단의 부정 선호 패턴을 활용할 수 있다. 단순 +1/−1 코사인은 두 사용자가 함께 부정 평가한 게임도 양의 유사도에 반영한다. 따라서 각 관계의 의미, 실제 관측 여부, 긍정 사용자 수를 따로 정해야 한다. |

TF-IDF에서는 긍정 소개글 벡터의 평균에서 부정 소개글 벡터의 평균을 빼는 Rocchio형 프로필도 만들 수 있다. 입력 게임과 후보 게임 벡터를 같은 방식으로 L2 정규화하고 같은 가중치를 주면, 이 방식과 위의 평균 유사도 감점은 후보 순위가 같아질 수 있다. 최종 사용자 벡터를 L2 정규화하는 것만으로는 별도의 순위 개선 실험이 되지 않는다.

부정 입력이 없으면 후속 감점 값은 0이다. 현재 기본 평가는 정답을 숨긴 뒤 긍정 입력 ≥1을 요구하므로, 긍정 입력이 없는 사용자는 두 모델 모두에서 제외한다. 평가 조건을 충족한 사용자라도 모델이 양수 점수를 만들지 못하면 빈 목록을 반환하며 평가에는 계속 포함한다. 감점 계수와 후보 제외 임계값은 후속 실험의 validation에서 정하고 테스트 자료로 조정하지 않는다.
