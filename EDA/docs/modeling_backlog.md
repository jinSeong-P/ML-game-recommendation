## 확정한 범위

2026-11-07 사용자 결정에 따라 Kieran → frank 베이스라인의 학습 범위, 소개글 정보원, 최소 입력 조건, 입력 집계 방식, 게임을 추천하지 못할 때의 처리, 모호한 리뷰 제외 정책을 확정했다.

2026-11-08에는 두 v1 모델의 학습·평가와 v2 진단·개선 비교를 완료했다. 이후 과제로 남겨 둔 태그·장르 보강은 v2에서 비교했다. 부정 신호, 여러 정답, 전체 입력 ≥3, 다른 입력 집계 방식, 인기순 보완은 v3에서 별도 실험했다. 완료 상태는 [v1 결과](../reports/baseline_v1.md), [v2 실행 결과](../reports/model_improvement_v2.md), [모델 실행 안내](baseline_models.md)를 기준으로 구분한다.

이 문서에서 긍정 사용자 수는 학습에서 해당 게임을 긍정 평가한 사용자 수를 뜻한다.

**분할 생성 완료:** `split_v1`, seed **20261107**로 전체 train/validation 자료, Item-KNN의 긍정 학습 입력, 검증·frank 평가의 입력 이력·정답, 사용자 명단과 제외 목록을 저장하고 전체 데이터를 검증했다. 학습에 사용한 긍정 리뷰는 **78,315,268쌍**, 검증 평가는 **325,639명**, 테스트는 **24,342명**이다. 실제 경로와 검증 근거는 [분할 파일 안내](modeling_splits.md)에 기록했다.

2026-11-08에는 소개글·토큰·TF-IDF 인덱스·코사인 검색도 준비했다. [콘텐츠 준비 결과](tfidf_content.md)에 사용 가능한 범위와 한계를 기록했다. Item-KNN(K=100) 학습과 고정 사용자 전체에 대한 공통 검증·frank 테스트도 완료했다.

태그와 장르는 베이스라인 소개글에 섞지 않는다. 같은 평가 방식에서 모델이나 특징을 비교할 때는 사용자, 숨긴 정답, 후보 범위를 같게 맞춘다. 보강 점수의 비중과 전처리 설정은 내부 검증 자료로 선택한다.

## 모델 개선 실행 — v2 완료

2026-11-08 사용자가 승인한 네 단계 실행을 완료했다. 실행의 목적·절차·완료 조건은 [실행 절차와 시각화](model_improvement_execution.md)에, 실험값·성능 저하를 함께 확인하는 보조 지표·채택 기준은 [v2 프로토콜](../data/reference/improvement_protocol_v2.json)에 기록했다. 기존 v1 규칙과 결과는 보존했다. 최종 검증 설정은 [모델 선택 기록](../data/reference/improvement_selection_v2.json)에서 확정했다. Item-KNN은 보조 기준에 따라 v1을 유지했고, 콘텐츠 모델은 T2+메타데이터 50:50을 선택했다. 고정한 모델의 frank 참조 평가도 완료했으며 자동 테스트 85개가 통과했다.

**재현 결과 확인:** [재현 스크립트](../scripts/reproduce_improvement_review.py)와 [집계](../reports/baseline_review_reproduction_v2.json)에 v1 성능·해시값·인기도 기준선, 저장된 연결의 공동 리뷰 수, 결측, 추천 쏠림, 이미 확인한 frank 자료에서 사후 계산한 코사인 민감도를 기록했다. 아래 내용은 중간 검토 기록의 해석을 보완한 것으로, 당시 기록과 구분한다.

- 46.1%는 Linux 후보 토큰 수 80분위 경계 **45토큰 초과** 게임의 추천 자리 비중이다. 경계 동점 때문에 이 게임은 정확한 상위 20%가 아니라 1,252/6,630개(18.88%)다. App ID 동점 규칙으로 정확히 20%인 1,326개를 고르면 47.12%다.
- 불용어 21개 목록·분모가 남지 않아 해당 가중치 비중은 원래 정의대로 재현하지 못했다. T0의 명시한 단어 목록/DF와 실제 점수 기여를 새 근거로 사용한다.
- 소개글 결측 5.81%는 **고정한 소개글만 쓰는 T1~T3**의 지원 한계를 나타낸다. 태그·장르를 추가하는 T4나 새 정보원을 쓰는 모든 TF-IDF 설정이 불가능하다는 뜻은 아니다.
- 인기도 구간 재가중은 기술적으로 분포를 맞춰 보는 근사치이지 인과 설명이 아니다. validation에 train 긍정 사용자가 0명인 정답이 없다는 점도 전제로 명시한다. validation 가중치나 사용자 명단을 frank에 맞추지 않는다.
- 추천 게임의 train 긍정 사용자 수와 입력–후보 사이의 공동 사용자 수는 서로 다른 통계다. 희귀 게임 추천의 중앙값만으로 약한 연결이 해롭다고 확정하지 않는다.
- 두 Top10 적중의 합집합 12.25%는 실제 결합 모델 성적이 아니다. 0.91%는 **Item-KNN 정답 점수가 0인 사용자**의 조건부 TF-IDF 적중률이며, 추천 목록 전체가 빈 사용자만의 성적이 아니다. 코사인 조건으로 사용자를 뺀 수치도 사후 진단이고 공식 지표·튜닝 기준으로 사용하지 않는다.

2026-11-08에는 [Item-KNN·TF-IDF 개선 기획안](model_improvement_plan.md)을 실행했다. 기존 v1의 확정 규칙과 완료 결과는 유지하고, 아래 v2 진단·검증은 별도 버전으로 수행했다. 실제 성능, 보조 기준, 최종 선택은 [v2 실행 결과](../reports/model_improvement_v2.md)에 기록했다.

- [x] **완료 — Item-KNN 연결 실패 분해(K0):** 정답의 train 긍정 사용자 수가 0명인 경우, 모든 긍정 입력 게임의 train 긍정 사용자 수가 0명인 경우, 원시 연결 없음, 이웃 제한으로 연결 소실, 순위 실패, 적중 등 전체 여섯 범주를 기록했다. 검증 325,639명과 frank 24,342명의 합계, v1의 0점·적중 수를 재현했다. frank 결과는 이미 확인한 참고 자료다.
- [x] **완료 — Item-KNN 이웃 수·감쇠(K1/K2):** 미리 정한 K=100/200/500 × λ=0/10/50의 9개 조합을 내부 검증했다. 감쇠를 적용한 뒤 원시 연결 전체에서 이웃을 다시 골랐고, K100/λ0 결과가 v1과 완전히 일치하는지 확인했다. 전체 평균은 좋아진 후보도 게임별 평균과 긍정 사용자 수 1–999 구간의 보조 기준을 통과하지 못해 v1을 유지한다.
- [x] **완료 — TF-IDF 진단·단독 변경(T0~T3):** 341개 층화 사례·7,243개 단어 기여를 저장하고 sublinear TF, unigram+bigram, 조건부 max_df=0.5를 각각 비교했다. 고빈도 단어의 오추천 기여 19.31%로 T3 실행 조건을 충족했다. 소개글 단독 최선은 T2이며 T4 전에 고정했다.

태그·장르 보강(T4), 다국어 분절과 입력 집계는 아래 기존 백로그와 연결한다. 기존 frank는 이미 관측된 참조 테스트로 구분하고, 후속 설정 선택은 train/validation에서만 수행한다.

## 구현 백로그

- [x] **완료 — 소개글 TF-IDF 입력과 검색:** A `description` 우선·C `short_description` 결측 보충 원문·정리 텍스트·토큰·출처를 저장했다. 기본 단어 TF-IDF와 L2 정규화 벡터, 긍정 입력 동일 가중 평균·Linux 코사인 검색을 구현·검증했다. - [x] **완료 — 긍정 신호 베이스라인:** Item-KNN은 Kieran 학습 계정 사이의 공동 긍정 리뷰로 이웃을 학습한다. 두 모델은 평가 대상 사용자의 남은 긍정 리뷰만 취향과 순위 점수에 쓴다. 남은 입력 이력에서 긍정·부정 평가한 게임은 모두 후보에서 제외한다. 정답으로 숨긴 게임만 제외 목록에서 빼 추천할 수 있게 둔다.

## 중간점검에 따른 수정 계획

2026-11-07의 [의심점 판정](../reports/kieran_frank_midpoint_audit.md)을 구현 작업으로 옮긴 계획이다. 학습 범위, 소개글 형식, 최소 입력 조건, 동일 가중 평균, 빈자리 유지, 모호한 리뷰 제외는 **사용자가 확정했다**. 분할 파일과 소개글·토큰·TF-IDF 인덱스·검색 기능을 구현하고 검증했다. Item-KNN 학습과 고정 사용자 전체에 대한 추천·평가도 구현하고 실행했다. 아래 추가 평가는 v3의 별도 보조 평가로 진행했으며 기본 평가 조건은 유지했다. 조건이 충족되지 않아 실행하지 않은 후속 작업은 문서 상단 상태표에 표시했다.

학습 전 네 가지 변경점의 선택지·장단점·선택 근거는 [학습 전 변경점 조사](pretraining_options.md)에 정리했다. 해당 문서의 상태표에도 이번 확정을 반영했다.

- [ ] **Linux/게임 카탈로그 갱신:** 최신 게임과 현재 Linux 지원 현황을 평가할 필요가 있을 때 별도 버전을 만든다. 평가 대상 사용자 범위가 바뀌면 새 테스트 계정 예약 범위를 계산하고, 기존 예약 계정도 포함해 계정 분리를 다시 확인한다.
- [x] **v3 실험·진단 완료 — 아이디어 — 검증 샘플링 보완:** 아래 게임별 리뷰 수 제한 보조 검증을 수행했다. 주 검증·채택 기준을 바꾸거나 frank 추출 분포를 재현했다고 주장하지 않는다. [v3 결과](../reports/model_improvement_v3.md).

분할과 누수 검사, Item-KNN 학습, 두 모델의 전체 사용자 추천, 공통 기준선과 긍정 사용자 수 진단을 완료했다. K=100과 기존 TF-IDF 설정, NDCG@10 우선·Recall@10 보조 기준, train 긍정 사용자 수 구간을 성능 확인 전에 확정했다. 검증 자료를 다시 학습하거나 조정하지 않았다. 이후 설정은 내부 검증으로만 선택한다. 추가 평가를 채택할지도 해당 테스트 결과를 확인하기 전에 정한다.

## 중간점검 의심 사항의 검증 결과

2026-11-07에는 로컬 자료를 바꾸지 않고 다시 집계했다. 사용자별로 추천 후보에서 제외할 게임을 반영해 무작위 기준선과 인기도 기준선의 기대값도 계산했다. 자세한 근거와 한계는 [중간점검 판정 보고서](../reports/kieran_frank_midpoint_audit.md)에 기록했다. 아래 체크 표시는 **의심점을 확인했다**는 뜻이다. 개선 조치를 했거나 모델 학습·최종 분할을 완료했다는 뜻도, 미정 규칙에 대해 사용자가 승인했다는 뜻도 아니다. [기존 진단 관측값](../reports/kieran_frank_eval_diagnostics.json)은 당시 기록으로 보존한다.

- [x] **frank 정답 분포 차이 — 확인:** 사용자별 후보 제외를 반영했을 때 인기도 기준 Recall@10 기대값은 0.05814%, 무작위 기준은 0.15093%다(전체 입력 ≥5, 24,571명). 인기도 기준이 무작위보다 낮다는 의심이 확인됐다. 이 값은 최종 seed를 정하기 전 계산한 기대값이다. 이후 고정 명단에서 측정한 Item-KNN·TF-IDF 성능과 실제 인기도 기준선은 [베이스라인 보고서](../reports/baseline_v1.md)에 따로 기록했다.
- [x] **검증·테스트 분포 차이 — 확인:** 전체 입력 수 조건이 같은 Kieran validation에서 인기도 기준 Recall@10 기대값은 31.96755%로 frank와 크게 다르다. 이 차이는 validation에서 선택한 설정이 실패했다는 증거가 아니다. 모델 설정은 계속 내부 검증에서만 선택한다.
- [x] **알려진 긍정 이력 누락 — 확인:** 사용자의 88.5%에게 Kieran-only 긍정 Linux 이력이 있으며, 모두 합해 398,893쌍이다. 이 게임들이 관측되지 않았다는 이유만으로 부정 학습 라벨을 붙인 것은 아니다. 다만 단일 정답 회수 지표가 불완전해지는 문제는 실제다. 이 긍정 이력을 후보 제외 목록에 추가하면 인기도 기준 Recall@10 기대값은 0.07578%로 바뀐다. 이 이력은 학습에 사용하지 않았고 숨긴 정답은 추천 후보로 되돌렸다.
- [x] **예약 계정 Kieran 보조 평가 — 구성·평가 완료:** 긍정 입력이 남아 있는 사용자 64,110명을 v3에서 평가했다. frank에서 긍정 입력을 보유한 사용자 24,342명 중 21,038명과 겹치므로 독립 사용자 표본이나 외부 테스트 대체재가 아니다. frank만으로 평가할 수 없다는 결론은 맞지 않으며, 이 보조 평가는 주 평가를 대체하지 않는다.
- [x] **모호한 리뷰 제외로 인한 앱별 손실 — 확인, 일괄 복구 근거 부족:** 332,865개 ID·686,161행이 31개 조합·63개 앱에 집중되어 있으며, **55개 앱은 원 리뷰 전체를 분석에서 제외했다**. 326,403개 ID는 비교할 수 있는 필드에서 앱 ID만 다르고, 6,462개는 다른 필드도 다르다. 카탈로그 앱이 하나인 22개 조합의 329,756개 ID도 앱 연결이 올바르다는 증거가 되지 않는다. 원 게시물 같은 별도 연결 근거 없이 카탈로그 소속만으로 리뷰를 복구하지 않는다. 227쌍·긍정 Linux 31쌍은 안전한 frank 이력과 분석 제외 앱 조합이 겹친 수이지 복구할 수 있는 리뷰 수가 아니다.
- [x] **Item-KNN 규모 표현 — 범위 구분:** 84,791,317은 모든 게임의 학습 긍정 쌍 수다. 확정된 고정 카탈로그 안의 긍정 쌍은 78,315,268개이며, 이 가운데 긍정 게임이 ≥2개인 사용자에게서 나온 쌍은 61,273,079개다. 긍정 리뷰가 하나뿐인 사용자도 정규화 빈도 계산에 포함하므로 마지막 수만을 전체 학습 규모로 쓰지 않는다.
- [x] **시점 차이 — 확인 및 범위 정정:** Kieran 리뷰는 2023-11-04, frank 리뷰는 2025-11-19에 끝난다. 2025년 원 리뷰 비중은 37.8%, Kieran 종료 이후 작성된 것으로 기대되는 정답 비중은 약 43.5%다. 마지막 출시일 2023-10-24는 A 전체 자료의 값이고 실제 입력·Linux 정답 카탈로그는 **2023-08-24**까지다. 카탈로그 밖 게임 비중은 예약 계정 전체에서 22.5%, 입력 ≥5 집단에서 22.9%다. 취향 변화나 신규 게임에 대한 일반화 성능이 입증된 것은 아니다.
- [x] **학습 긍정 근거 부족 — 확인:** Linux 후보 6,630개 중 36개는 학습 긍정 사용자 수가 0명이며, 이를 포함해 224개는 5명 미만이다. 전체 입력 ≥5 집단에서 선택 정답의 기대 비중은 긍정 사용자 수 0명일 때 0.21583%, 1~4명일 때 0.43003%다. 모델별로 사용자나 정답을 제외하지 않고 점수 산출 가능 여부를 보고한다. 개인화 점수가 없는 자리는 비우는 것이 베이스라인 정책이다.
- [x] **소개글 길이·정보량 차이 — 확인, 성능에 미치는 영향은 미확인:** A의 짧은 소개글과 C의 긴 소개글 길이 중앙값은 211자·1,142자다. 확정한 A 우선·C 짧은 소개글 보충 규칙은 입력 37,531/37,610개, Linux 후보 6,613/6,630개를 포함한다. 두 출처의 짧은 소개글이 같은 비율 88.4%도 다시 확인했다. 실제 원문을 고정하고 전처리해야 한다.
- [x] **Linux 표시 불일치 — 확인, 원인은 미확인:** A에는 비Linux, C에는 Linux로 표시된 앱 137개, 반대 사례 52개, A에서 Linux로 표시됐지만 C에 없는 앱 534개를 다시 확인했다. C에 없는 앱이 Linux를 지원하지 않는다는 뜻은 아니다. 현재 평가 정답 기대 비중에서 약 0.64%는 C에 비Linux로 표시됐고 약 4.99%는 C에 수록되지 않았다. 시점 변화와 수집 오류 중 무엇이 원인인지는 자료만으로 판단할 수 없어 고정 카탈로그를 유지했다.

검증 뒤 실행할 작업과 선택 사항은 위 **중간점검에 따른 수정 계획**에서 관리한다. 의심점을 확인한 표시와 실제 구현 완료를 구분한다.

## 베이스라인 v1 중간 검토 후속 작업

아래 작업은 2026-11-08에 v1을 변경하지 않고 중간 검토하면서 시작했다. 당시 지표와 사용자 2,000명의 추천을 다시 계산하고 누수·해시값을 확인한 결과, 자동 테스트 53개에서도 차이가 없어 [v1 결과](../reports/baseline_v1.md)를 유지했다. 이후 [재현 스크립트](../scripts/reproduce_improvement_review.py), K0/T0 산출물, v2 실험으로 확인한 항목은 완료로 표시했다. 아직 확인하지 못한 원인과 후속 작업은 남겼다.

실험 후보와 순서는 [개선 기획안](model_improvement_plan.md)의 K·T 항목을 따른다. 이 절에는 기획을 실행하기 전에 정할 사항과 근거가 되는 수치만 적는다.

### 튜닝 전에 처리할 작업

- [x] **완료 — 검증 선택 기준 보완:** 전체 NDCG 우선·Recall 보조 기준을 유지하고, 로그 긍정 사용자 수 구간, 정답 게임별 평균 NDCG, 긍정 사용자 수 1–999인 게임의 NDCG, 빈 목록, paired-bootstrap을 추가했다. 미리 정한 보조 기준 하나라도 통과하지 못하면 v1을 유지한다. v1 구간 경계 `[19,67,413.75]`와 결과는 보존한다.
- [x] **완료 — K0·K1 사전 관측 반영:** 이웃 제한으로 빠진 연결은 validation 55,487명·frank 13,448명에서 다시 확인했다. frank에서 나머지 정답 0점 사용자 4,371명은 정답의 긍정 사용자 수가 0명인 52명, 입력 게임의 긍정 사용자 수가 0명인 3명, 원시 연결이 없는 4,316명으로 나뉜다. 공동 리뷰 ≥5로 새로 연결되는 frank 사용자 5,278명은 전체의 21.68%, 0점 사용자 중 29.62%다. 저장된 연결 가운데 공동 리뷰 사용자가 1명인 비율 56.7%, 5명 미만인 비율 79.4%를 재현했다. 3×3 실험으로 K와 감쇠의 상호작용도 확인했다. frank 값은 설정 선택에 사용하지 않았다.
- [x] **완료 — TF-IDF 소개글 결측 영향 구분:** Linux 17개·검증 18,921명(5.81%)·frank 34명(0.14%)을 다시 확인했다. 고정 소개글만 쓰는 T1~T3에서 생기는 지원 손실로 보고하되 공식 지표의 분모에는 계속 포함한다. T4 메타데이터도 없는 검증 정답은 18,884명이므로, 메타데이터를 추가해도 결측 손실 대부분은 해소되지 않는다. 새 소개글 출처는 별도 버전의 후속 작업으로 남겼다.
- [x] **완료 — T0 추천 쏠림 정의·기여 검증:** 46.1%는 45토큰 초과·후보 18.88%의 비중으로 정정했고 정확한 상위 20%는 47.12%다. 원래 불용어 21개 목록·분모는 재현 불가로 남겼다. 고정 층화 사례의 실제 단어 기여를 저장하고 T3의 사전 실행 조건을 확인했다. 추천 쏠림의 단일 원인이 입증된 것은 아니다.
- [x] **완료 — 이번 추가 평가 범위 확정:** 검증 자료에서 최종 설정을 확정한 뒤 그 모델만 frank 참조 평가에 사용한다. 예약 계정 보조 평가와 Kieran-only 긍정 민감도는 이번 v2에서 다루지 않고 아래 후속 항목으로 남겼다. 기존 frank 자료를 다시 사용하는 평가를 새로운 독립 최종 검증이라고 부르지 않는다.

### 해석과 보고서 보완

- [x] **완료 — 검증·테스트 차이의 표현:** frank의 긍정 사용자 수 분포에 맞춰 validation 성적을 다시 가중한 Recall 약 7.30%/2.24%를 재현했다. 이는 분포 차이를 설명하는 근사치이지 성능 차이의 인과적 분해가 아니다. validation 가중치나 사용자 명단을 바꾸거나 일반화 성능이 하락했다고 단정하는 데 사용하지 않는다.
- [x] **v3 실험·진단 완료 — 같은 인기도에서 frank가 더 높은 이유 조사:** 긍정 사용자 수 100–999명인 집단을 전체 데이터에서 다시 집계했다. 입력 수, 최대 콘텐츠 유사도 같은 연관성을 기록했지만 성능 차이의 인과 원인은 확인하지 못했다. `backlog_diagnostics_v3.json`과 [v3 결과](../reports/model_improvement_v3.md)를 참고한다.
- [x] **v3 실험·진단 완료 — 시리즈작·중복 소개글 영향 분리:** 제목을 정규화한 결과, 소개글이 같은 게임, 유사도가 높은 게임을 따로 집계했다. 실제로 가장 유사한 입력·제목 사례도 저장했다. 공식 분모는 유지한다. 시리즈나 에디션이 같은 상품인지는 별도 App ID 근거가 있어야 한다. [v3 결과](../reports/model_improvement_v3.md).
- [x] **완료 — frank 희귀 게임 추천 분포 보고:** v1 추천 게임의 긍정 사용자 수 중앙값 183,070명/57명을 재현하고 v2 후보별 긍정 사용자 수 중앙값과 커버리지도 추가했다. 추천 게임의 긍정 사용자 수와 입력–후보 연결의 공동 사용자 수는 별개의 값이다. 희귀 게임 추천 자체를 품질 저하로 해석하지 않는다.
- [x] **완료 — 보고서에 보조 진단 추가:** 로그 긍정 사용자 수 구간, 사용자 수와 게임 수, 인기도 기준선, 게임별 평균, paired-bootstrap 신뢰구간, 빈 목록, 추천 커버리지, 긍정 사용자 수 중앙값, 계산 비용을 추가했다. 긍정 사용자 수가 적은 구간의 작은 표본과 validation에 train 긍정 사용자가 0명인 정답이 없다는 한계를 적었다.
- [x] **v3 실험·진단 완료 — 후속 — Item-KNN·콘텐츠 모델 결합:** 실제 RRF 순위 결합과 후보 게임의 학습 긍정 사용자 수에 따른 콘텐츠 점수 비중을 비교했다. 정답을 알고 두 모델의 top10을 합쳐 적중한 결과는 실제 추천 성능으로 사용하지 않았다. [v3 결과](../reports/model_improvement_v3.md).

## v2 이후 성능 개선 아이디어

2026-11-08에 v2 결과, 데이터 특징, 공개 방법론을 함께 살펴 정리한 아이디어의 실행 이력이다. 아래에는 v3에서 실제로 실험·진단한 상태를 반영했다. 최초의 기대나 가설을 측정 결과인 것처럼 바꾸어 해석하지 않는다. 일부 아이디어는 이미 확인한 frank 결과에서 시작했으므로, frank를 다시 평가해도 독립 검증은 아니며 설정 선택에 사용하지 않는다.

### 우선순위를 낮출 항목

- **중국어·일본어·한국어(CJK) 분절과 다국어 토큰화:** Linux 후보 소개글의 99.5%는 라틴 문자이고, 소개글이 있는 후보 중 비라틴 문자는 18개다. 관련 백로그는 유지하되 우선순위를 낮춘다.
- **frank `user_games` 활용:** 테스트 사용자 24,342명 중 이 자료에 포함된 사용자는 84명뿐이므로 입력 이력이나 플레이타임 보강에 쓸 수 없다.
- **SASRec 등 순차 모델:** 시간 경계를 기준으로 다시 학습해 평가하고 학습 이력 규모를 진단했다. 2022년 말까지 긍정 게임이 ≥5개인 학습 사용자는 3,119,614명이므로 학습은 가능할 수 있다. 이벤트 순서, 동점 처리, 학습 설정을 별도로 확정한 뒤 진행할 후속 작업이며 SASRec의 실제 성능은 측정하지 않았다.
- **인기순으로 빈자리 채우기:** v3에서 이 정책을 실험했지만 선택 모델에는 적용하지 않았다. 빈 목록은 드물고, 기존 frank에서 인기도 기준 Recall은 약 0.07%였다. 이 진단과 실험 결과를 함께 참고한다.

| 기본 정답 명단 생성 | **완료:** 무작위 1개, seed **20261107**, 검증 325,639명·테스트 24,342명의 실제 입력 이력·정답을 담은 파일 목록·검증 정보(manifest)를 저장하고 확인했다. |

## 부정 리뷰 베이스라인과 후속 실험

첫 번째 방법을 베이스라인으로 선택했고, 나머지는 후속 실험으로 남겼다. 부정 리뷰를 자료에 보존하는 것과 학습이나 추천 점수에 실제 사용하는 것은 다르다. 평가 사용자가 남긴 입력 이력에 있는 게임은 긍정·부정 모두 다시 추천하지 않는다. 숨긴 정답은 입력 이력과 취향 계산에서 제외하고, 후보 제외 목록에서는 빼서 추천할 수 있게 한다. 아직 리뷰하지 않은 게임을 부정 평가로 간주하지 않는다.

| 방법 | 적용 위치 | 동작 | 장점·한계 |
|---|---|---|---|
| **확정 베이스라인 — 긍정 신호만으로 순위 계산** | 사용자 입력 집계 | 긍정 리뷰 게임만 취향 벡터와 추천 점수에 사용한다. 부정 리뷰한 게임은 다시 추천하지 않는다. | 단순한 비교 기준이다. 다른 비슷한 게임에 부정 신호를 전달하지 않는다. |
| 후속 — 부정 게임 유사도 감점 | 사용자 입력 집계·후보 점수 | 긍정 게임과의 평균 유사도에서 부정 게임과의 평균 유사도에 감점 계수를 곱한 값을 뺀다. | 기존 TF-IDF와 양의 Item-KNN 유사도를 유지하면서 적용할 수 있다. 가격이나 버그 때문에 싫어한 게임도 취향에 맞지 않는 것으로 확대 해석할 수 있다. |
| 후속 — 부정 게임의 유사 후보 제외 | 후보 필터 | 부정 리뷰한 게임과 유사도가 일정 값 이상인 새 후보를 제외한다. | 피하고 싶은 게임을 명확히 반영한다. 임계값에 따라 추천 후보가 지나치게 줄 수 있다. |
| 후속 — 학습에 긍정·부정 관계 반영 | Item-KNN 유사도 학습 | Kieran 학습 리뷰에서 긍정–긍정, 긍정–부정 등의 관계를 나누어 이웃과 추천 점수를 계산한다. | 집단의 부정 선호 패턴을 활용할 수 있다. 단순 +1/−1 코사인은 두 사용자가 함께 부정 평가한 게임도 양의 유사도에 반영한다. 따라서 각 관계의 의미, 실제 관측 여부, 긍정 사용자 수를 따로 정해야 한다. |

TF-IDF에서는 긍정 소개글 벡터의 평균에서 부정 소개글 벡터의 평균을 빼는 Rocchio형 프로필도 만들 수 있다. 입력 게임과 후보 게임 벡터를 같은 방식으로 L2 정규화하고 같은 가중치를 주면, 이 방식과 위의 평균 유사도 감점은 후보 순위가 같아질 수 있다. 최종 사용자 벡터를 L2 정규화하는 것만으로는 별도의 순위 개선 실험이 되지 않는다.

부정 입력이 없으면 후속 감점 값은 0이다. 현재 기본 평가는 정답을 숨긴 뒤 긍정 입력 ≥1을 요구하므로, 긍정 입력이 없는 사용자는 두 모델 모두에서 제외한다. 평가 조건을 충족한 사용자라도 모델이 양수 점수를 만들지 못하면 빈 목록을 반환하며 평가에는 계속 포함한다. 감점 계수와 후보 제외 임계값은 후속 실험의 validation에서 정하고 테스트 자료로 조정하지 않는다.
