# Item-KNN·TF-IDF 개선 기획안

작성일: **2026-11-08** · 상태: **v2 실행 완료·최초 기획 이력 보존** · 기준: `baseline_v1`, `split_v1`

2026-11-08 사용자가 **진단 수치 재현 → 평가 보호 지표 보완 → K0·T0 진단 → 개선 실험**의 실행을 승인했다. 단계별 목적·절차·통과 조건과 실제 후보값·채택 기준은 [실행 절차](model_improvement_execution.md), [고정 v2 프로토콜](../data/reference/improvement_protocol_v2.json)에 기록한다. **아래는 최초 기획 시점의 근거·가설·대안 비교를 보존한 이력**이다. ‘아직 미분해’ 등의 표현도 당시 상태이며 현재 진단·실험·선정은 [v2 실행 결과](../reports/model_improvement_v2.md)를 기준으로 확인한다.

실행에서는 K1/K2의 상호작용을 확인하도록 K×λ 3×3 비교를 사전 지정했고, 검증 게임별 평균·지원 1–999·빈 목록 보호와 paired-bootstrap 채택 조건을 보완했다. T0로 조건부 T3 실행을 결정하고 소개글 단독 모델을 먼저 고정한 뒤 T4를 비교했다. 기존 v1 설정·결과는 그대로 보존한다.

## 1. 두 모델의 문제가 다른 이유

| 모델 | 확인된 핵심 문제 | 우선 확인할 원인 | 개선 방향 |
|---|---|---|---|
| Item-KNN | frank 정답의 **73.20%가 0점**. 입력과 정답 사이에 저장된 유사도 연결이 없음 | 원래 공동 긍정 리뷰가 없는지, 후보별 이웃 100개에서 잘렸는지 아직 미분해 | 연결 손실을 분리한 뒤 이웃 수 확대. 이후 약한 연결의 신뢰도 보정 |
| TF-IDF | frank 정답의 **99.26%가 양수 점수**지만 Top 10 적중률은 **3.58%** | 공통 단어, 짧은 소개글의 정보 부족, 구문 표현, 여러 취향의 평균화 중 무엇이 순위를 흐리는지 미확인 | 단어 기여도·오추천 사례 진단, 소개글 표현 개선, 별도 태그·장르 점수 결합 |

Item-KNN에는 정답까지 점수가 전달되는지가 중요하고, TF-IDF에는 정답을 다른 후보보다 높게 구분하는 능력이 중요하다. 낮은 지표를 두 모델의 같은 문제로 취급하지 않는다.

### 현재 성능과 실패 분해

아래 수치는 [기존 결과 JSON](../reports/baseline_v1.json)에 저장된 집계에서 계산했다. 새로운 모델이나 추가 평가 실행 결과가 아니다.

| 집단 | 모델 | Recall@10 | NDCG@10 | 정답 0점 | 정답 양수지만 Top 10 밖 | 정답 Top 10 적중 |
|---|---|---:|---:|---:|---:|---:|
| 검증 325,639명 | Item-KNN | 40.0757% | 0.244328 | 55,671명·17.10% | 139,466명 | 130,502명 |
| 검증 325,639명 | TF-IDF | 1.9251% | 0.012064 | 20,163명·6.19% | 299,207명 | 6,269명 |
| frank 24,342명 | Item-KNN | 11.1905% | 0.074859 | 17,819명·73.20% | 3,799명 | 2,724명 |
| frank 24,342명 | TF-IDF | 3.5782% | 0.024254 | 179명·0.74% | 23,292명 | 871명 |

세 실패·적중 열은 집단별 전체 사용자 수로 합산된다. 진단상 `전체 적중률 = 정답 양수 점수 사용자 비율 × 그중 Top 10 적중 비율`로 분해할 수 있다. frank에서 Item-KNN은 **26.80% × 41.76%**, TF-IDF는 **99.26% × 3.60%**다. 조건부 비율은 원인 설명에만 쓰고, 공식 Recall/NDCG의 전체 사용자 분모는 유지한다. 양수 점수가 있다는 사실 자체가 의미 있는 선호를 찾았음을 보장하지는 않는다.

추천 목록이 비는 문제도 따로 봐야 한다. frank에서 빈 목록은 Item-KNN **18명**, TF-IDF **4명**이다. 대부분 사용자는 추천을 받았지만 숨긴 정답을 못 찾았다. 인기순으로 빈자리만 채워서 해결할 수 있는 주된 실패는 아니다.

## 2. Item-KNN: 확인된 문제와 원인 가설

현재는 Linux 후보마다 전체 입력 게임 중 코사인이 높은 **100개 이웃**을 저장한다. 사용자별 추천 수는 **최대 10개**로, 이웃 수 100과 다른 설정이다. 공동 긍정 사용자 1명부터 연결을 인정하며, 신뢰도 감쇠는 없다. 모든 긍정 입력의 유사도 합을 전체 긍정 입력 수로 나눈다.

| 항목 | 확인된 사실 | 아직 확인되지 않은 원인·영향 |
|---|---|---|
| 정답까지 연결되지 않음 | frank 17,819명에서 정답 점수 0 | 이 중 원시 공동 리뷰 부재와 K=100 절단이 각각 몇 명인지 |
| 학습 지원 없는 게임 | Linux 후보 36개는 train 긍정 지원 0 | 지원 없는 게임만으로 정답 0점 대부분이 설명되는지: 그렇지 않음 |
| 이웃 없는 게임 | 후보 44개에 이웃 없음. 36개는 지원 0, 8개는 지원이 있지만 공동 이웃 없음. frank의 해당 정답은 63명 | 이 63명은 전체 0점 정답 17,819명보다 훨씬 적음. 전역 이웃 부재와 특정 사용자 입력의 연결 부재를 구분해야 함 |
| 약한 공동 리뷰 연결 | 최소 공동 등장 1, shrinkage 없음 | 소수 사용자에게만 의존하는 높은 코사인이 유용한 이웃을 밀어내는지 |
| 인기 구간 편중 | 검증 정답의 98.41%, frank 정답의 38.14%가 train 지원 상위 구간 | 두 집단 점수 차이가 어느 요인에서 얼마나 발생했는지. 현재 집계로 인과적 기여율을 확정할 수 없음 |
| 후보별 이웃 방향 | 후보(target)별로 입력 이웃을 보존하는 구조 | 입력(query)별 이웃 구조가 더 적합한지. 현재 방향은 구현 오류가 아닌 고정 설계 |

따라서 직전 설명의 **“이웃 100개 제한이 문제일 수 있다”는 가설**을 먼저 검증한다. 현재 자료로 73.20% 전체를 이웃 절단 탓이라고 단정할 수 없다. 저장 CSR의 행이 100개로 차 있으면 누락된 연결은 원래 0회였을 수도, 101위 이하였을 수도 있다.

### K0. 원인 분해 — 최우선 진단

train 긍정 이력에서 원시 공동 사용자 수를 다시 확인하고, 고정 validation의 사용자–정답을 다음 순서로 한 범주에만 배정한다.

| 순서 | 범주 | 판별 방법 | 의미 |
|---:|---|---|---|
| 1 | 정답의 train 지원 0 | 정답 긍정 사용자 수 0 | 이웃 수 확대만으로 해결 불가 |
| 2 | 긍정 입력 전부 train 지원 0 | 정답은 지원되지만 모든 긍정 입력의 지원 0 | 협업 신호 입력 자체 부족 |
| 3 | 원시 공동 긍정 연결 없음 | 앞선 범주가 아니고, 정답과 모든 긍정 입력의 공동 사용자 수 0 | K를 늘려도 직접 Item-KNN 점수는 0 |
| 4 | 이웃 절단으로 연결 소실 | 원시 연결은 있지만 K=100 저장 연결은 없음 | 이웃 수 확대가 직접 해결할 수 있는 손실 |
| 5 | 순위 실패 | 저장 연결·양수 점수는 있지만 정답 순위 11위 이하 | 유사도 신뢰도·순위 구분력 개선 대상 |
| 6 | 적중 | 정답 순위 1~10 | 유지할 성공 사례 |

공동 사용자 수는 **train만**으로 계산한다. validation 정답은 진단 라벨로 사용하며, 공동 선호 학습에 넣지 않는다. 사용자별 원인 범주와 지원 수·연결 수·원시 이웃 순위·저장 여부를 기록한다. 전체·train 지원 구간·긍정 입력 수 구간별 집계를 함께 만든다.

저장 이웃이 100개 미만인 후보는 양수 연결을 모두 남겼으므로 누락 입력과의 원시 공동 등장도 0이다. 100개로 찬 후보를 중심으로 절단 여부를 추가 확인해 진단 계산을 줄일 수 있다.

산출물 제안: `item_knn_failure_analysis_v2.json`과 Git 제외 경로의 사용자별 진단 Parquet. **완료 기준은 여섯 범주 합계가 전체 validation 사용자 수와 같고, v1 적중·0점 집계가 재현되는 것**이다.

### Item-KNN 실험 순서와 장단점

| ID·우선순위 | 제안 | 장점 | 단점·위험 | 채택 판단 |
|---|---|---|---|---|
| K1·1순위 | 같은 후보 방향에서 **K=100·200·500** 비교. 코사인·학습 범위·평균 집계 고정 | 절단으로 버린 유용한 연결을 회복하는지 직접 확인 가능 | 약한 연결도 늘어 잡음·추천 비용 증가. 원시 연결이 없으면 효과 없음 | 정답 양수 비율과 전체 NDCG@10을 함께 비교. 연결 수만 늘었다고 채택하지 않음 |
| K2·2순위 | K1에서 선택한 K를 고정하고 `cosine × cooc/(cooc+λ)`, **λ=0·10·50** 비교 | 1~몇 명에 의존하는 불안정한 연결 완화 | 실제 희소 게임의 유용한 연결도 낮출 수 있음 | 낮은 지원 구간의 성능·전체 순위·연결 지원을 함께 확인 |
| K3·조건부 후속 | K2 뒤에도 단발성 연결 잡음이 확인되면 최소 공동 사용자 **1·2·3** 비교 | 설명하기 쉬운 직접적인 잡음 제거 | 희소 게임·사용자의 연결을 아예 끊어 K1 목적과 충돌 가능 | 원인 진단이 뒷받침할 때만 별도 실험. blanket 필터로 먼저 적용하지 않음 |
| K4·후속 | 입력 게임별 Linux 이웃 또는 양방향 연결 합집합을 별도 구조로 비교 | 이웃 절단 방향에 따른 손실을 확인 | 현재 후보별 K와 저장량·모델 의미가 달라짐. 동일 K 숫자만으로 공정한 비용 비교 불가 | K1~K2와 분리한 새 모델 버전에서 평가 |

K1은 최대 K=500의 **같은 원시 코사인·같은 동점 규칙**으로 이웃 순위를 남겨 100·200·500을 도출할 수 있다. K=100 결과가 v1과 일치하는지 확인한다. K2는 감쇠로 이웃 순서 자체가 바뀌므로 원시 연결에서 감쇠 점수를 계산한 뒤 각 λ의 상위 K를 다시 선택해야 한다. v1의 상위 100개에만 감쇠를 적용하면 새 이웃을 놓친다.

K2·K3에서도 게임별 지원 수는 전체 고정 train 긍정 이력으로 계산한다. 약한 연결을 낮추거나 제외한다는 이유로 singleton 계정·희소 게임의 학습 행을 제거해 코사인 분모를 바꾸지 않는다.

전체 게임 쌍을 밀집 행렬로 저장하지 않고 후보 블록별로 처리한다. K=500의 저장 연결 상한은 6,630×500=3,315,000개다. float64 값·int32 열 번호 기준 약 40MB의 CSR 배열 상한이며, 압축 파일 크기와 학습 중 메모리는 별도 측정한다.

**평균 분모만 바꾸는 안은 순위 개선 실험에서 제외한다.** 한 사용자의 모든 후보 점수를 같은 양수 상수로 나누면 순위와 양수 여부가 같다. 합계로 교체하거나 사용자별로 동일한 지원 입력 수로 나누는 것만으로 Recall/NDCG는 개선되지 않는다. 입력별 가중치를 바꾸는 실험은 실제 상대 점수를 바꾸지만 기존의 별도 집계 백로그에서 관리한다.

## 3. TF-IDF: 확인된 문제와 원인 가설

현재는 A 소개글 우선·결측일 때 C 짧은 소개글을 사용한다. 단어 unigram, 불용어 제거 없음, 원래 빈도 TF, smoothed IDF와 게임별 L2 정규화를 적용한다. 남은 긍정 게임 벡터를 동일 가중 평균한 뒤 코사인으로 비교한다.

| 항목 | 확인된 사실 | 아직 확인되지 않은 원인·영향 |
|---|---|---|
| 순위 구분력 부족 | frank 정답 24,163명에 양수 점수, 그중 23,292명이 Top 10 밖 | 어떤 단어·특징이 오추천 후보를 정답보다 높게 만드는지 |
| 짧은 소개글·단어 일치 | A 소개글 길이 중앙값 211자. 단어 unigram만 사용 | 메커니즘·플레이 방식 정보 부족이나 표현 차이가 실패의 주원인인지 |
| 범용 단어·반복 빈도 | `stop_words=None`, `max_df=1.0`, `sublinear_tf=False` | 빈번한 단어가 실제 상위 점수에 얼마나 기여하는지. 설정 자체만으로 원인을 확정할 수 없음 |
| 소개글 결측 | Linux 17개 영벡터. 해당 정답은 검증 18,921명·5.81%, frank 34명·0.14% | 결측은 확정된 손실이지만 frank 미적중 대부분을 설명하지 못함 |
| 다국어 분절 | Unicode 단어 정규식으로 CJK 구문이 길게 묶일 수 있음 | 현재 평가 사용자에서 이 문제의 가중 영향이 얼마나 큰지 |
| 동일 소개글 | 전체 136그룹·342개 게임의 정리 텍스트가 같음 | 평가 후보·정답에서의 동점 및 손실 규모 |
| 여러 취향의 평균화 | 모든 긍정 입력을 같은 비중으로 평균 | 서로 다른 취향이 섞일 때 정답 순위가 낮아지는지 |

### T0. 순위 실패 진단 — 최우선 진단

고정 validation에서 성공·0점 실패·양수 순위 실패를 나누고, train 지원 구간과 긍정 입력 수 구간별로 사례를 추출한다. 사례 추출 seed와 규칙을 고정하고, 일부 성공 사례도 포함한다.

확인할 내용은 다음과 같다.

- 정답과 상위 오추천 후보에 기여한 단어별 `사용자 프로필 가중치 × 후보 가중치`, 문서 빈도·IDF, 공통 단어와 게임 특성 단어의 기여.
- 원문 출처, 토큰 수, 문자계열, 정확히 같은 소개글 여부, 입력 수와 정답 순위의 관계. 문자계열을 언어 판별 결과로 간주하지 않는다.
- 여러 장르를 좋아하는 사용자에서 평균 프로필이 범용 단어에 가까워지는지. 이 단계에서는 집계 방식을 바꾸지 않는다.
- 태그·장르를 보강했을 때 구분할 수 있을 만한 실패인지, 소개글 자체의 단어 정리로 해결할 여지가 있는지.

산출물 제안: `tfidf_ranking_analysis_v2.json`과 정답·오추천의 특징 기여 사례표. **완료 기준은 근거 단어와 실제 사례를 통해 원인 가설별 지지·반례·미확인을 구분하는 것**이다. 양수 점수 사용자만 남겨 새 공식 성능을 계산하지 않는다.

### TF-IDF 실험 순서와 장단점

| ID·우선순위 | 제안 | 장점 | 단점·위험 | 채택 판단 |
|---|---|---|---|---|
| T1·1순위 | 소개글·토큰·나머지 설정 유지, **`sublinear_tf=True`만 변경** | 반복된 단어의 빈도 영향 완화. 원인 비교가 단순 | 같은 표현의 반복이 유용한 특징이면 약화 가능 | 기존 소개글 모델 대비 전체 NDCG와 기여 단어 변화 확인 |
| T2·1순위 | 나머지 설정 유지, **단어 n-gram `(1,2)`만 변경** | `turn based` 등 구문 정보를 표현할 가능성 | 어휘·메모리 증가, 희귀 구문과 표기 차이로 더 희소해질 수 있음 | 성능과 어휘 수·nnz·평가 시간 함께 비교 |
| T3·조건부 | T0에서 범용 단어 지배가 관찰되면 **`max_df=0.5` 단독 비교** | 코퍼스에서 지나치게 흔한 단어를 데이터에 근거해 억제 | 도메인 핵심 단어도 삭제 가능. 임계값을 넘는 단어가 없으면 아무 변화 없음 | 제거 단어 목록·수와 성능을 함께 기록. 무조건적인 영문 불용어 일괄 삭제는 우선하지 않음 |
| T4·2순위·기존 백로그 | **소개글 + 별도 태그·장르 특징**의 점수 결합 | 소개글 표현이 달라도 게임 메커니즘·장르의 공통성을 전달 가능. 소개글 결측 게임도 메타데이터가 있으면 지원 가능 | 태그 결측·출처 차이·광범위한 장르·표기 정리가 새 품질 문제. 보강만으로 개선을 보장하지 않음 | T0~T2에서 선택한 소개글 모델을 고정한 뒤 보강 효과만 분리 |
| T5·조건부 후속 | CJK 분절 또는 문자 n-gram을 별도 특징으로 비교 | 공백 없는 텍스트·표기 변형의 일치 개선 가능 | 특징 수·연산량 증가, 문자 단위의 무관한 일치 | 문자계열별 실제 실패 기여가 확인되면 기존 다국어 백로그에서 수행 |

T1·T2는 각각 v1에서 한 요소만 바꾼다. 두 설정을 동시에 켜는 조합 실험은 단독 결과에서 둘 다 근거가 있을 때만 추가한다. T3는 선행 진단이 뒷받침될 때만 실행한다. 모든 어휘·IDF는 기존과 같은 고정 입력 카탈로그의 공개 메타데이터에서 계산하고, validation/test 리뷰 라벨은 특징 학습에 넣지 않는다.

### T4의 구체적인 보강 방식

**소개글과 태그·장르를 각각 벡터화하고 코사인 점수를 결합**한다. 소개글 뒤에 태그 문자열을 길게 붙이는 방식과 섞어 비교하지 않는다.

1. 태그·장르 원문을 pinned A/C 메타데이터에서 App ID로 연결한다. 현재 `content_catalog.parquet`에는 존재 여부만 있어 그대로 특징으로 쓸 수 없다.
2. **출처 규칙 제안:** 태그는 유효한 A 태그 우선·결측일 때 C 태그, 장르는 C의 유효한 장르 필드. 배열·딕셔너리·문자열 구조와 결측을 먼저 검증하고 출처별 원문·정규화 결과를 저장한다. 이 규칙은 이번 기획의 제안이며 소개글의 확정 출처 규칙과 구분한다.
3. 태그는 `tag::open_world`, 장르는 `genre::rpg`처럼 개념 단위를 보존한다. 투표 수가 아닌 존재 여부를 기본으로 하고, 고정 게임 카탈로그의 IDF와 L2 정규화를 적용한다. 두 필드의 중복 개념·광범위한 장르 영향도 점검한다.
4. 각 채널에서 같은 긍정 입력의 평균 프로필로 코사인을 구한다. `점수 = α × 소개글 코사인 + (1−α) × 메타데이터 코사인`. **α=1.0·0.75·0.5·0.25**를 제안한다. α=1.0은 선택한 소개글 모델과 일치해야 한다.
5. 채널이 지원되지 않으면 해당 기여는 0으로 둔다. 결측 여부에 따라 사용자·후보별로 가중치를 임의 재조정하지 않는다. 이는 고정 가중 결합의 보수적 초기 규칙이며 결측 조합별 손실을 따로 보고한다.

두 채널의 코사인은 값의 범위가 같아도 분포가 다를 수 있다. α는 고정 validation에서만 비교하고, 채널별 점수 분포와 결측 조합별 결과도 함께 남긴다.

태그·장르 가용성과 정답 가중 결측률은 **현재 split_v1으로 다시 확인**해야 한다. 레거시 B 평가에서 계산한 결측 영향 비율을 현재 frank 성능의 근거로 가져오지 않는다. 별개 App ID를 동일 소개글이라는 이유로 합치지 않는다.

### 우선순위를 낮출 변경

- **긴 소개글·새 설명 출처 보충:** 정보량 증가 가능성과 홍보 문구·길이 편향이 함께 있다. 현재 A 우선·C 짧은 소개글 규칙을 바꾸므로 별도 데이터 버전·비교안으로 다룬다. 결측 17개만 보충해 frank의 대부분 실패가 해결될 것이라고 기대하지 않는다.
- **사용자 입력의 최대 유사도·플레이타임 가중치:** 평균화 문제를 바꿀 수 있지만 기존 집계 백로그와 연결된 별도 실험이다. 최초 특징 개선에서는 동일 가중 평균을 유지한다.
- **전용 벡터DB 도입:** 현재는 6,630개 후보를 정확한 희소 내적으로 모두 비교한다. 같은 벡터·프로필·코사인을 저장소만 바꿔 검색해도 순위 구분력이 개선되지 않는다.

또한 현재 L2 정규화한 게임 벡터의 평균을 다시 정규화하는 방식은, 후보별 평균 코사인과 사용자 내 순위가 같다. 이 정규화 상수나 평균을 합계로 바꾸는 것만을 독립적인 순위 개선안으로 삼지 않는다.

## 4. 공통 평가 설계

### 유지할 조건

기존 train/validation/test 파일, 사용자 예약·격리, 37,610개 입력·6,630개 Linux 후보, 정답 1개, 숨김 후 전체 ≥5·긍정 ≥1, 긍정 입력 동일 가중 평균, 긍정·부정 관측 게임 제외, 양수 점수 최대 10개·빈자리 유지, 빈 목록도 전체 지표 분모에 남기는 규칙을 유지한다. 학습 singleton도 계속 지원 수·코사인 분모에 포함한다.

사용자나 어려운 정답을 제거하거나 입력 ≥3으로 모집단을 바꾸는 작업은 이번 모델 개선 비교와 합치지 않는다. 부정 신호·대체 추천·다중 정답 평가는 기존 별도 백로그다. 단일 정답 미적중을 사용자가 나머지 추천을 전부 싫어했다는 라벨로 해석하지 않는다.

### 설정 선택과 채택 기준 제안

| 항목 | 제안 |
|---|---|
| 선택 자료 | Kieran 고정 validation 325,639명. 학습은 기존 train 긍정만 사용 |
| 1차 기준 | 각 모델의 v1 대비 **전체 사용자 NDCG@10 개선** |
| 2차 기준 | Recall@10. NDCG만 높고 Recall이 낮아진 후보는 trade-off를 별도 보고하고 기본 채택을 유보 |
| 보호 지표 | 빈 목록·짧은 목록, 낮은 train 지원 구간의 Recall/NDCG, 후보 커버리지, 시간·메모리 |
| 원인 지표 | 정답 양수 점수 비율, 그중 적중률, 원시 연결과 절단 손실, 텍스트/메타데이터 영벡터 |
| 불확실성 | 같은 사용자의 v1·후보 차이로 paired bootstrap 신뢰구간을 보고. validation에서 후보를 선택한 편향까지 제거하는 독립 검증으로 해석하지 않음 |
| 단순성 | 차이가 불명확하면 더 적은 이웃·더 작은 특징·적은 출처의 설정 우선 |

지원이 늘었어도 전체 NDCG가 나빠지면 개선으로 자동 채택하지 않는다. 보호 지표가 나빠지는 경우에는 이득과 손실을 함께 적고 기존 모델을 유지할 수 있다. 구체적인 성능 향상 폭을 미리 보장하지 않는다.

### 검증 분포와 이미 본 테스트의 처리

검증 정답은 train 지원 상위 구간에 **98.41%** 집중되어 있어 전체 평균만으로 희소 게임의 개선을 충분히 판단하기 어렵다. 기존 train 지원 구간 경계 `[19, 67, 413.75]`를 유지하고 구간별 표본 수·지표를 함께 보고한다. 저지원 구간은 표본이 작으므로 작은 적중 수 변화도 함께 확인한다. validation에는 train 지원 0인 정답이 **0개**여서, 해당 조건의 개선은 현재 주평가만으로 검증할 수 없다. 필요하면 별도 cold-start 진단 프로토콜을 후속 설계한다.

**frank 테스트는 이미 확인한 자료다.** 이번 기획이 그 관측에서 출발했다는 사실도 기록한다. 이후 K·λ·텍스트·결합 비중은 train/validation에서만 선택하고, 후보별 frank 결과를 반복 조회해 설정을 고르지 않는다. 선택이 끝난 뒤 기존 frank에 재평가하더라도 **이미 관측된 참조 테스트 결과**로 구분한다. 새로운 독립 최종 성능 주장이 필요하면 모델·프로토콜을 고정한 뒤 아직 보지 않은 외부 평가 자료가 필요하다. 같은 frank 사용자를 다시 분할하는 것만으로 미열람 테스트가 생기는 것은 아니다.

frank 정답 인기도 비율에 맞춰 validation 가중치나 사용자 명단을 조절하지 않는다. train에서 정한 구간별 진단과 전체 평균을 함께 유지한다.

## 5. 실행 순서·산출물

| 단계 | 작업 | 산출물 | 완료 기준 |
|---:|---|---|---|
| 1 | v1 고정 및 두 진단 K0·T0 | 실행 지문, 실패 분류표, 특징 기여 사례표 | 기존 적중·0점 집계 재현, 가설과 사실 구분 |
| 2 | K1 이웃 100·200·500과 T1·T2 단독 실험 | 설정별 모델·validation 추천·지표·비용 | 동일 사용자·정답·후보로 비교, K=100 및 텍스트 기준점 재현 |
| 3 | K2 신뢰도 보정, 태그·장르 가용성 감사 후 T4 결합 | λ·α 비교표, 특징 출처 manifest, 결측 진단 | 단계 2의 모델을 고정한 대조 실험. 기여와 손실 구분 |
| 4 | 모델별 후보 선정과 비교 보고 | `model_improvement_v2` 설정 manifest·제안 모델·잔여 문제 | validation 선택 기준과 보호 지표를 기준으로 근거 제시 |
| 5 | 필요 시 고정 모델의 후속 평가 | 참조 테스트 또는 별도 독립 평가 보고서 | 평가 자료의 관측 여부·선택 이력 명시 |

K0와 T0, 이후 두 모델의 실험은 서로 독립적으로 진행할 수 있다. 모델 안에서는 진단 → 단독 변경 → 다음 변경 순서를 유지한다. K3·K4·T3·T5와 집계·출처 변경은 조건부 또는 후속 작업으로 두어 최초 실험 조합 수를 제한한다.

### 구현 시 변경 범위

- **v1 보존:** `baseline_protocol_v1.json`, `baseline_run_v1.json`, 분할·콘텐츠·Item-KNN·평가 산출물과 기존 재현 경로를 유지한다. 새 실험은 별도 코드·프로토콜·출력 디렉터리로 둔다.
- **Item-KNN:** 원시 공동 사용자 수·지원 수·이웃 순위 저장, 최대 K에서 부분 이웃 도출, 신뢰도 보정 후 재선택, 실패 분해 기능을 준비한다.
- **TF-IDF:** 소개글 설정을 명시적으로 버전 관리하고, 태그·장르 파서·출처·특징 사전·채널별 프로필·점수 결합을 별도로 구현한다.
- **공통 평가:** v1의 고정 K=100 검사나 코드 지문을 약화시켜 새 실험을 통과시키지 않는다. 새 실험용 프로토콜은 허용한 설정과 모델·평가 코드 지문을 기록하고 기존 마스크·분모·동점·점수 검사를 재사용한다.
- **보관:** 사용자별 진단·추천은 Git 제외 경로에 저장하고, 저장소에는 집계·설정·출처 지문·기획과 보고서를 남긴다.

## 6. 최초 제안한 착수 범위

**첫 작업 묶음은 K0·T0 진단과 K1·T1·T2의 작은 비교까지**로 제안한다. 원인을 구분한 뒤 K2와 기존 백로그의 태그·장르 보강 T4를 진행한다. CF의 연결 문제와 콘텐츠의 순위 문제를 각각 개선하고, 그 효과가 확인된 후 집계 방식·부정 신호 등 다음 실험으로 넘어간다.
