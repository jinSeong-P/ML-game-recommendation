# Item-KNN·TF-IDF 개선 기획안

작성일: **2026-11-08** · 상태: **v2 실행 완료·최초 기획 이력 보존** · 기준: `baseline_v1`, `split_v1`

2026-11-08 사용자는 **진단 수치 재현 → 성능 저하를 함께 확인하는 보조 지표 보완 → K0·T0 진단 → 개선 실험**의 실행을 승인했다. 단계별 목적, 절차, 통과 조건과 실제 후보값·채택 기준은 [실행 절차](model_improvement_execution.md)와 [고정 v2 프로토콜](../data/reference/improvement_protocol_v2.json)에 기록했다.

**아래에는 최초 기획 당시의 근거·가설·대안 비교를 이력으로 남긴다.** ‘아직 미분해’ 같은 표현은 당시 상태를 설명한다. 현재 진단·실험·선정 결과는 [v2 실행 결과](../reports/model_improvement_v2.md)에서 확인한다. 여기서 긍정 사용자 수란 학습에서 해당 게임을 긍정 평가한 사용자 수를 뜻한다.

K1과 K2의 상호작용을 확인하기 위해 K×λ 3×3 비교를 미리 정했다. 검증에서는 게임별 평균, 긍정 사용자 수 1–999, 빈 목록을 성능 저하를 함께 확인하는 보조 지표로 살피고 paired-bootstrap 채택 조건을 보완했다. T0 결과를 바탕으로 조건부 T3를 실행하기로 했다. 소개글만 사용하는 모델의 설정을 먼저 확정한 다음 T4를 비교했다. 기존 v1 설정과 결과는 그대로 보존한다.

## 1. 두 모델의 문제가 다른 이유

| 모델 | 확인된 핵심 문제 | 우선 확인할 원인 | 개선 방향 |
|---|---|---|---|
| Item-KNN | frank 정답 중 **73.20%의 점수는 0**이다. 입력 게임과 정답 게임 사이에 저장된 유사도 연결이 없다. | 원래 공동 긍정 리뷰가 없었는지, 후보별 이웃 100개 제한 때문에 연결이 빠졌는지 아직 나누어 확인하지 않았다. | 연결이 끊긴 원인을 구분한 뒤 이웃 수를 늘린다. 다음으로 약한 연결의 신뢰도를 보정한다. |
| TF-IDF | frank 정답 중 **99.26%에는 양수 점수**가 매겨졌지만, Top 10 적중률은 **3.58%**다. | 공통 단어, 짧은 소개글의 정보 부족, 구문 표현, 여러 취향의 평균화 가운데 어떤 요인이 순위를 흐리는지 확인하지 않았다. | 단어별 기여와 오추천 사례를 살피고, 소개글 표현을 개선하며, 태그·장르 점수를 별도 채널로 결합한다. |

Item-KNN에서는 정답에 점수가 전달되는지가 중요하다. TF-IDF에서는 정답에 다른 후보보다 높은 점수를 주는지가 중요하다. 두 모델의 낮은 점수를 같은 문제로 보지 않는다.

### 현재 성능과 실패 분해

아래 수치는 [기존 결과 JSON](../reports/baseline_v1.json)에 저장된 집계에서 계산했다. 새로운 모델이나 추가 평가 실행 결과가 아니다.

| 집단 | 모델 | Recall@10 | NDCG@10 | 정답 0점 | 정답 양수지만 Top 10 밖 | 정답 Top 10 적중 |
|---|---|---:|---:|---:|---:|---:|
| 검증 325,639명 | Item-KNN | 40.0757% | 0.244328 | 55,671명·17.10% | 139,466명 | 130,502명 |
| 검증 325,639명 | TF-IDF | 1.9251% | 0.012064 | 20,163명·6.19% | 299,207명 | 6,269명 |
| frank 24,342명 | Item-KNN | 11.1905% | 0.074859 | 17,819명·73.20% | 3,799명 | 2,724명 |
| frank 24,342명 | TF-IDF | 3.5782% | 0.024254 | 179명·0.74% | 23,292명 | 871명 |

세 실패·적중 열을 더하면 각 집단의 전체 사용자 수가 된다. 진단을 위해 `전체 적중률 = 정답 양수 점수 사용자 비율 × 그중 Top 10 적중 비율`로 나눠 볼 수 있다. frank에서 Item-KNN은 **26.80% × 41.76%**, TF-IDF는 **99.26% × 3.60%**다. 이 조건부 비율은 원인을 살필 때만 사용한다. 공식 Recall/NDCG는 계속 전체 사용자를 분모로 계산한다. 양수 점수만으로 유용한 선호를 찾았다고 볼 수는 없다.

추천 목록이 비는 문제도 별도로 확인한다. frank에서 빈 목록을 받은 사용자는 Item-KNN **18명**, TF-IDF **4명**이다. 대부분의 사용자는 추천을 받았지만 숨긴 정답은 찾지 못했다. 따라서 빈자리를 인기순으로 채우는 것만으로는 주된 실패를 해결할 수 없다.

## 2. Item-KNN: 확인된 문제와 원인 가설

현재는 Linux 후보마다 전체 입력 게임 가운데 코사인이 높은 게임 **100개를 이웃**으로 저장한다. 사용자에게 추천하는 게임 수는 **최대 10개**이며, 후보별 이웃 수 100과는 다른 설정이다. 두 게임을 함께 긍정 평가한 사용자가 1명만 있어도 연결로 인정한다. 연결 신뢰도를 낮추는 감쇠는 적용하지 않는다. 모든 긍정 입력과 후보 사이의 유사도 합을 전체 긍정 입력 수로 나눈다.

| 항목 | 확인된 사실 | 아직 확인되지 않은 원인·영향 |
|---|---|---|
| 정답까지 연결되지 않음 | frank 17,819명에서 정답 점수 0 | 이 가운데 원시 공동 리뷰가 없었던 사용자와 K=100 제한으로 연결이 빠진 사용자가 각각 몇 명인지 |
| 학습 데이터에서 긍정 평가자가 없는 게임 | Linux 후보 36개는 train에서 긍정 사용자 수 0 | 이런 게임만으로 정답 0점의 대부분을 설명할 수 있는가? 그렇지 않다. |
| 이웃이 없는 게임 | 후보 44개에 이웃이 없다. 36개는 긍정 사용자 수 0이고, 8개는 긍정 사용자 수가 있지만 공동 이웃이 없다. frank의 해당 정답은 63명이다. | 63명은 전체 0점 정답 17,819명보다 훨씬 적다. 어떤 후보에도 이웃이 없는 경우와 특정 사용자의 입력 게임에 연결된 이웃이 없는 경우를 구분해야 한다. |
| 약한 공동 리뷰 연결 | 최소 공동 등장 수는 1이고 shrinkage는 적용하지 않았다. | 소수 사용자에게만 의존하는 높은 코사인 점수가 더 유용한 이웃을 밀어내는지 |
| 인기 구간 편중 | 검증 정답의 98.41%, frank 정답의 38.14%가 train 긍정 사용자 수 상위 구간에 속한다. | 두 집단의 점수 차이가 어떤 요인에서 얼마나 발생하는지. 현재 집계만으로는 인과적 기여율을 확정할 수 없다. |
| 후보별 이웃 방향 | 각 정답 후보별로 입력 게임의 이웃을 저장한다. | 사용자의 입력 이력별로 이웃을 저장하는 편이 더 적합한지. 현재 방식은 구현 오류가 아니라 확정된 설계다. |

따라서 앞서 제기한 **“이웃 100개 제한이 문제일 수 있다”는 가설**부터 검증한다. 현재 자료만으로 73.20% 전체가 이웃 제한 때문에 발생했다고 단정할 수는 없다. 저장된 CSR 행에 이웃이 100개 있더라도 누락된 연결의 공동 리뷰 수가 원래 0이었는지, 순위가 101위 이하였는지는 알 수 없다.

### K0. 원인 분해 — 최우선 진단

train 긍정 이력에서 원시 공동 사용자 수를 다시 확인하고, 고정 validation의 사용자–정답을 다음 순서로 한 범주에만 배정한다.

| 순서 | 범주 | 판별 방법 | 의미 |
|---:|---|---|---|
| 1 | 정답의 train 긍정 사용자 수 0 | 정답을 긍정 평가한 train 사용자가 0명 | 이웃 수를 늘려도 해결할 수 없음 |
| 2 | 모든 긍정 입력의 train 긍정 사용자 수 0 | 정답에는 긍정 사용자 수가 있지만, 모든 긍정 입력의 수는 0 | 협업 신호를 제공할 입력 자체가 부족함 |
| 3 | 원시 공동 긍정 연결 없음 | 앞선 범주가 아니고, 정답과 모든 긍정 입력의 공동 사용자 수 0 | K를 늘려도 직접 Item-KNN 점수는 0 |
| 4 | 이웃 제한으로 연결 소실 | 원시 연결은 있지만 K=100 저장 연결은 없음 | 이웃 수를 늘려 직접 해결할 수 있는 손실 |
| 5 | 순위 실패 | 저장 연결·양수 점수는 있지만 정답 순위 11위 이하 | 유사도 신뢰도·순위 구분력 개선 대상 |
| 6 | 적중 | 정답 순위 1~10 | 유지할 성공 사례 |

공동 사용자 수는 **train 자료만**으로 계산한다. validation 정답은 원인 진단을 위한 표지로만 사용하며, 공동 선호 학습에는 넣지 않는다. 사용자별 원인 범주, 긍정 사용자 수, 연결 수, 원시 이웃 순위, 저장 여부를 기록한다. 전체 집계와 함께 train 긍정 사용자 수 구간 및 긍정 입력 수 구간별 집계도 만든다.

저장 이웃이 100개 미만인 후보는 양수인 모든 연결을 보존했다. 따라서 저장되지 않은 입력과는 원시 공동 등장이 0이다. 100개 이웃이 모두 저장된 후보를 우선 확인하면 진단 계산을 줄일 수 있다.

산출물 제안: `item_knn_failure_analysis_v2.json`과 Git 제외 경로의 사용자별 진단 Parquet. **완료 기준은 여섯 범주 합계가 전체 validation 사용자 수와 같고, v1 적중·0점 집계가 재현되는 것**이다.

### Item-KNN 실험 순서와 장단점

| ID·우선순위 | 제안 | 장점 | 단점·위험 | 채택 판단 |
|---|---|---|---|---|
| K1·1순위 | 같은 후보 기준으로 **K=100·200·500**을 비교한다. 코사인, 학습 범위, 평균 집계는 고정한다. | 이웃 제한으로 빠진 유용한 연결을 되찾는지 직접 확인할 수 있다. | 약한 연결도 늘어 잡음과 추천 비용이 커질 수 있다. 원시 연결이 없으면 효과가 없다. | 정답에 양수 점수가 매겨진 비율과 전체 NDCG@10을 함께 비교한다. 연결 수만 늘었다고 채택하지 않는다. |
| K2·2순위 | K1에서 선택한 K를 고정하고 `cosine × cooc/(cooc+λ)`, **λ=0·10·50**을 비교한다. | 1~몇 명에게만 의존하는 불안정한 연결의 점수를 낮출 수 있다. | 실제로 유용한 희소 게임 연결의 점수도 낮아질 수 있다. | 긍정 사용자 수가 적은 구간의 성능, 전체 순위, 연결의 공동 사용자 수를 함께 확인한다. |
| K3·조건부 후속 | K2 뒤에도 한두 번만 나타난 연결에서 잡음이 확인되면 최소 공동 사용자 수 **1·2·3**을 비교한다. | 이해하기 쉬운 기준으로 약한 연결을 제거할 수 있다. | 희소 게임이나 사용자의 연결을 끊어 K1의 목적과 충돌할 수 있다. | 원인 진단이 뒷받침할 때만 별도 실험한다. 모든 연결에 먼저 일괄 적용하지 않는다. |
| K4·후속 | 입력 게임별 Linux 이웃 또는 양방향 연결 합집합을 별도 구조로 비교 | 이웃 절단 방향에 따른 손실을 확인 | 현재 후보별 K와 저장량·모델 의미가 달라짐. 동일 K 숫자만으로 공정한 비용 비교 불가 | K1~K2와 분리한 새 모델 버전에서 평가 |

K1에서는 최대 K=500까지 **같은 원시 코사인 점수와 같은 동점 규칙**으로 이웃 순위를 저장하면 K=100·200·500 결과를 얻을 수 있다. K=100 결과가 v1과 일치하는지 확인한다. K2에서는 감쇠가 이웃 순서도 바꾼다. 따라서 원시 연결마다 감쇠 점수를 계산하고 각 λ에서 상위 K개를 다시 골라야 한다. v1에서 저장한 상위 100개에만 감쇠를 적용하면 새로 이웃에 들어올 게임을 놓친다.

K2·K3에서도 게임별 긍정 사용자 수는 고정된 전체 train 긍정 이력으로 계산한다. 약한 연결을 낮추거나 제외하더라도 긍정 리뷰가 하나뿐인 사용자의 학습 행이나 희소 게임을 제거해 코사인 분모를 바꾸지 않는다.

전체 게임 쌍을 밀집 행렬로 저장하지 않고 후보 블록별로 처리한다. K=500의 저장 연결 상한은 6,630×500=3,315,000개다. float64 값·int32 열 번호 기준 약 40MB의 CSR 배열 상한이며, 압축 파일 크기와 학습 중 메모리는 별도 측정한다.

**평균 분모만 바꾸는 안은 순위 개선 실험에서 제외한다.** 한 사용자의 모든 후보 점수를 같은 양수 상수로 나누면 후보 순위와 점수의 양수 여부가 바뀌지 않는다. 합계로 바꾸거나 사용자별로 점수를 낼 수 있는 입력 게임 수를 분모로 삼는 것만으로 Recall/NDCG는 개선되지 않는다. 입력별 가중치를 바꾸면 후보 간 점수 차이가 달라지므로, 이는 기존 입력 집계 백로그에서 별도로 다룬다.

## 3. TF-IDF: 확인된 문제와 원인 가설

현재는 A 소개글 우선·결측일 때 C 짧은 소개글을 사용한다. 단어 unigram, 불용어 제거 없음, 원래 빈도 TF, smoothed IDF와 게임별 L2 정규화를 적용한다. 남은 긍정 게임 벡터를 동일 가중 평균한 뒤 코사인으로 비교한다.

| 항목 | 확인된 사실 | 아직 확인되지 않은 원인·영향 |
|---|---|---|
| 순위 구분력 부족 | frank 정답 24,163명에 양수 점수, 그중 23,292명이 Top 10 밖 | 어떤 단어·특징이 오추천 후보를 정답보다 높게 만드는지 |
| 짧은 소개글·단어 일치 | A 소개글 길이 중앙값 211자. 단어 unigram만 사용 | 메커니즘·플레이 방식 정보 부족이나 표현 차이가 실패의 주원인인지 |
| 범용 단어·반복 빈도 | `stop_words=None`, `max_df=1.0`, `sublinear_tf=False` | 빈번한 단어가 실제 상위 점수에 얼마나 기여하는지. 설정 자체만으로 원인을 확정할 수 없음 |
| 소개글 결측 | Linux 17개 영벡터. 해당 정답은 검증 18,921명·5.81%, frank 34명·0.14% | 결측은 확정된 손실이지만 frank 미적중 대부분을 설명하지 못함 |
| 다국어 분절 | Unicode 단어 정규식으로 공백이 없는 중국어·일본어·한국어(CJK) 문장이 한 토큰으로 길게 묶일 수 있음 | 현재 평가 사용자에서 이 문제의 가중 영향이 얼마나 큰지 |
| 동일 소개글 | 전체 136그룹·342개 게임의 정리 텍스트가 같음 | 평가 후보·정답에서의 동점 및 손실 규모 |
| 여러 취향의 평균화 | 모든 긍정 입력에 같은 가중치를 주어 평균한다. | 서로 다른 취향이 섞일 때 정답 순위가 낮아지는지 |

### T0. 순위 실패 진단 — 최우선 진단

고정 validation에서 성공, 0점 실패, 양수 점수지만 순위가 낮은 실패를 구분한다. train 긍정 사용자 수 구간과 긍정 입력 수 구간별로 사례를 뽑는다. 사례를 고르는 seed와 규칙을 고정하고, 성공 사례도 일부 포함한다.

확인할 내용은 다음과 같다.

- 정답과 상위 오추천 후보의 점수에 기여한 단어를 확인한다. 단어별 `사용자 프로필 가중치 × 후보 가중치`, 문서 빈도와 IDF, 공통 단어와 게임별 특징 단어의 기여를 비교한다.
- 원문 출처, 토큰 수, 문자 종류, 소개글이 완전히 같은지, 입력 수와 정답 순위가 어떤 관계인지 확인한다. 문자 종류만으로 언어를 판별하지 않는다.
- 여러 장르를 선호하는 사용자의 평균 프로필이 흔한 단어 위주로 바뀌는지 확인한다. 이 단계에서는 집계 방식을 바꾸지 않는다.
- 태그·장르를 보강하면 구분할 수 있는 실패인지, 소개글의 단어 처리를 바꾸면 해결할 수 있는지 살핀다.

산출물 제안: `tfidf_ranking_analysis_v2.json`과 정답·오추천의 특징 기여 사례표. **완료 기준은 근거 단어와 실제 사례를 통해 원인 가설별 지지·반례·미확인을 구분하는 것**이다. 양수 점수 사용자만 남겨 새 공식 성능을 계산하지 않는다.

### TF-IDF 실험 순서와 장단점

| ID·우선순위 | 제안 | 장점 | 단점·위험 | 채택 판단 |
|---|---|---|---|---|
| T1·1순위 | 소개글·토큰·나머지 설정은 유지하고 **`sublinear_tf=True`만 변경**한다. | 반복 단어의 빈도 영향을 줄이고 원인을 쉽게 비교할 수 있다. | 같은 표현의 반복이 유용한 특징이면 그 영향도 약해질 수 있다. | 기존 소개글 모델과 전체 NDCG, 단어별 기여 변화를 비교한다. |
| T2·1순위 | 나머지 설정은 유지하고 **단어 n-gram `(1,2)`만 변경**한다. | `turn based`와 같은 구문 정보를 표현할 수 있다. | 어휘와 메모리가 늘며, 드문 구문과 표기 차이 때문에 더 희소해질 수 있다. | 성능, 어휘 수, nnz, 평가 시간을 함께 비교한다. |
| T3·조건부 | T0에서 흔한 단어가 점수를 좌우하는 것으로 관찰되면 **`max_df=0.5`만 변경해 비교**한다. | 자료에서 지나치게 흔한 단어를 찾아 억제할 수 있다. | 게임 분야의 핵심 단어도 제거될 수 있다. 기준을 넘는 단어가 없으면 결과가 바뀌지 않는다. | 제거한 단어 목록과 개수, 성능을 함께 기록한다. 모든 영문 불용어를 무조건 제거하는 방식은 우선하지 않는다. |
| T4·2순위·기존 백로그 | **소개글 + 별도 태그·장르 특징**의 점수를 결합한다. | 소개글 표현이 달라도 게임 메커니즘이나 장르의 공통점을 전달할 수 있다. 소개글이 없는 게임도 메타데이터가 있으면 점수를 받을 수 있다. | 태그 결측, 출처 차이, 범위가 넓은 장르, 표기 정리 등 새로운 품질 문제가 생길 수 있다. 보강만으로 성능이 나아진다고 보장할 수 없다. | T0~T2에서 선택한 소개글 모델을 확정한 뒤, 보강 효과만 따로 비교한다. |
| T5·조건부 후속 | 중국어·일본어·한국어(CJK) 단어 나누기 또는 문자 n-gram을 별도 특징으로 비교한다. | 띄어쓰기가 없는 텍스트나 표기 변형을 더 잘 맞출 수 있다. | 특징 수와 연산량이 늘고, 문자 단위의 무관한 일치가 생길 수 있다. | 문자 종류별 실패 기여가 실제로 확인되면 기존 다국어 백로그에서 수행한다. |

T1과 T2는 각각 v1의 설정 한 가지만 바꾼다. 두 설정을 함께 적용하는 실험은 각각의 단독 결과가 근거를 보일 때만 추가한다. T3도 앞선 진단이 근거를 제시할 때만 실행한다. 어휘와 IDF는 기존처럼 고정 입력 카탈로그의 공개 메타데이터로 계산한다. validation/test 리뷰의 긍정·부정 표시는 특징을 학습할 때 사용하지 않는다.

### T4의 구체적인 보강 방식

**소개글과 태그·장르를 각각 벡터로 만들고 코사인 점수를 결합**한다. 소개글 뒤에 태그 문자열을 이어 붙이는 방식은 이 비교에 포함하지 않는다.

1. 태그·장르 원문을 고정한 A/C 메타데이터에서 App ID로 연결한다. 현재 `content_catalog.parquet`에는 존재 여부만 있어 그대로 특징으로 사용할 수 없다.
2. **출처 규칙 제안:** 유효한 A 태그를 우선 사용하고, 없으면 C 태그를 쓴다. 장르는 C의 유효한 장르 필드를 사용한다. 배열·딕셔너리·문자열 구조와 결측을 먼저 확인한 뒤, 출처별 원문과 정규화 결과를 저장한다. 이 규칙은 이번 기획의 제안이며, 소개글에 확정한 출처 규칙과는 구분한다.
3. 태그는 `tag::open_world`, 장르는 `genre::rpg`처럼 각 개념을 별도 단위로 둔다. 투표 수가 아니라 해당 개념의 존재 여부를 기본값으로 삼고, 고정 게임 카탈로그의 IDF와 L2 정규화를 적용한다. 두 필드에서 같은 개념이 중복되거나 지나치게 넓은 장르가 미치는 영향도 확인한다.
4. 각 채널에서 같은 긍정 입력의 평균 프로필과 후보 사이의 코사인을 구한다. `점수 = α × 소개글 코사인 + (1−α) × 메타데이터 코사인`. 비교할 값은 **α=1.0·0.75·0.5·0.25**다. α=1.0은 선택한 소개글 모델과 같은 결과여야 한다.
5. 해당 채널의 정보를 구할 수 없으면 그 채널의 점수 기여를 0으로 둔다. 결측 여부에 따라 사용자나 후보마다 가중치를 임의로 바꾸지 않는다. 결측 조합별 손실도 별도로 보고한다.

두 채널의 코사인은 같은 범위의 값이어도 실제 점수 분포가 다를 수 있다. α는 고정 validation에서만 비교한다. 채널별 점수 분포와 결측 조합별 결과도 함께 기록한다.

태그·장르를 사용할 수 있는지와 정답 비중으로 계산한 결측률은 **현재 split_v1으로 다시 확인**해야 한다. 이전 B 평가에서 계산한 결측 영향 비율을 현재 frank 성능의 근거로 사용하지 않는다. 소개글이 같더라도 서로 다른 App ID를 하나로 합치지 않는다.

### 우선순위를 낮출 변경

- **긴 소개글·새 설명 출처 보충:** 정보가 늘 수 있지만 홍보 문구나 길이 편향도 생길 수 있다. 현재 A 우선·C 짧은 소개글 규칙을 바꾸게 되므로 별도 데이터 버전과 비교안으로 다룬다. 결측 17개를 보충해도 frank에서 발생한 실패 대부분이 해결된다고 기대하지 않는다.
- **사용자 입력의 최대 유사도·플레이타임 가중치:** 평균화 문제를 바꿀 수 있지만 기존 입력 집계 백로그에서 다루는 별도 실험이다. 첫 특징 개선에서는 동일 가중 평균을 유지한다.
- **전용 벡터DB 도입:** 현재는 6,630개 후보를 희소 벡터 내적으로 모두 비교해 정확한 코사인을 구한다. 같은 벡터·프로필·코사인을 다른 저장소에서 검색하는 것만으로 순위 구분력은 개선되지 않는다.

L2 정규화한 게임 벡터의 평균을 다시 정규화해도 후보별 평균 코사인 순위는 사용자 안에서 같다. 따라서 정규화 상수나 평균을 합계로 바꾸는 것만으로는 별도의 순위 개선안을 만들지 않는다.

## 4. 공통 평가 설계

### 유지할 조건

기존 train/validation/test 파일, 평가에서 제외할 사용자 명단, 모호한 리뷰를 분석에서 제외하는 정책, 37,610개 입력 게임, 6,630개 Linux 후보, 정답 1개, 숨긴 뒤 전체 리뷰 ≥5·긍정 리뷰 ≥1 조건, 긍정 입력의 동일 가중 평균, 긍정·부정 리뷰가 있는 게임 제외, 양수 점수 기준 최대 10개 추천, 부족한 자리와 빈 목록 유지 규칙을 그대로 적용한다. 학습에 긍정 리뷰가 하나뿐인 사용자도 게임별 긍정 사용자 수와 코사인 분모 계산에 계속 포함한다.

사용자나 어려운 정답을 제거하거나 입력 ≥3으로 모집단을 바꾸는 작업은 이번 모델 개선 비교와 합치지 않는다. 부정 신호·대체 추천·다중 정답 평가는 기존 별도 백로그다. 단일 정답 미적중을 사용자가 나머지 추천을 전부 싫어했다는 라벨로 해석하지 않는다.

### 설정 선택과 채택 기준 제안

| 항목 | 제안 |
|---|---|
| 선택 자료 | 고정된 Kieran validation 325,639명. 학습에는 기존 train의 긍정 리뷰만 사용한다. |
| 1차 기준 | 각 모델의 v1 대비 **전체 사용자 NDCG@10 개선** |
| 2차 기준 | Recall@10. NDCG만 높고 Recall은 낮아진 후보는 두 지표의 절충을 별도로 보고하고 기본 채택을 보류한다. |
| 성능 저하를 함께 확인하는 보조 지표 | 빈 목록·짧은 추천 목록, train 긍정 사용자 수가 적은 구간의 Recall/NDCG, 후보 커버리지, 시간·메모리 |
| 원인 지표 | 정답 양수 점수 비율, 그중 적중률, 원시 연결과 이웃 제한 손실, 텍스트/메타데이터 영벡터 |
| 불확실성 | 같은 사용자의 v1과 후보 모델 점수 차이로 paired bootstrap 신뢰구간을 보고한다. validation에서 후보를 고른 편향까지 제거한 독립 검증으로 해석하지 않는다. |
| 단순성 | 차이가 분명하지 않으면 이웃 수가 적고, 특징이 단순하며, 출처가 적은 설정을 우선한다. |

긍정 사용자 수가 늘어도 전체 NDCG가 나빠지면 개선으로 자동 채택하지 않는다. 성능 저하를 함께 확인하는 보조 지표가 나빠지면 이득과 손실을 함께 기록하고 기존 모델을 유지할 수 있다. 미리 정해 둔 성능 향상 폭은 없다.

### 검증 분포와 이미 본 테스트의 처리

검증 정답의 **98.41%**는 train 긍정 사용자 수가 많은 구간에 속하므로, 전체 평균만으로 희소 게임의 개선을 판단하기 어렵다. 기존 train 긍정 사용자 수 구간 경계 `[19, 67, 413.75]`를 유지하고, 구간별 표본 수와 지표를 함께 보고한다. 긍정 사용자 수가 적은 구간은 표본이 작으므로 적중 수 변화도 확인한다. validation에는 train 긍정 사용자 수가 0인 정답이 **0개**여서 현재 주평가만으로 해당 조건의 개선을 검증할 수 없다. 필요하면 별도 cold-start 진단 절차를 후속 설계한다.

**frank 테스트 결과는 이미 확인했다.** 이번 기획이 그 결과를 보고 시작됐다는 점도 기록한다. 이후 K·λ·텍스트·결합 비중은 train/validation에서만 선택한다. 후보별 frank 결과를 반복 확인해 설정을 고르지 않는다. 선택을 마친 뒤 frank를 다시 평가하더라도 결과는 **이미 관측된 참조 테스트 결과**로 구분한다. 새로운 독립 최종 성능을 주장하려면 모델과 절차를 확정한 뒤 아직 확인하지 않은 외부 평가 자료가 필요하다. frank 사용자를 다시 나누기만 해서는 미열람 테스트가 되지 않는다.

frank 정답의 인기도 비율에 맞춰 validation 가중치나 사용자 명단을 조절하지 않는다. train에서 정한 구간별 진단과 전체 평균을 함께 유지한다.

| 1 | v1 고정 및 두 진단 K0·T0 | 실행 해시값, 실패 분류표, 특징 기여 사례표 | 기존 적중·0점 집계 재현, 가설과 사실 구분 |
| 2 | K1 이웃 100·200·500과 T1·T2 단독 실험 | 설정별 모델·validation 추천·지표·비용 | 동일 사용자·정답·후보로 비교, K=100 및 텍스트 기준점 재현 |
| 3 | K2 신뢰도 보정, 태그·장르 가용성 확인 후 T4 결합 | λ·α 비교표, 특징 출처와 파일 목록·검증 정보(manifest), 결측 진단 | 단계 2에서 정한 모델을 기준으로 대조 실험을 한다. 기여와 손실을 구분한다. |
| 4 | 모델별 후보 선정과 비교 보고 | `model_improvement_v2` 설정 파일 목록·검증 정보(manifest), 제안 모델·남은 문제 | validation 선택 기준과 보조 지표를 근거로 결정을 설명한다. |
| 5 | 필요 시 고정 모델의 후속 평가 | 참조 테스트 또는 별도 독립 평가 보고서 | 평가 자료의 관측 여부·선택 이력 명시 |

K0, T0, 그리고 두 모델의 후속 실험은 서로 독립적으로 진행할 수 있다. 각 모델 안에서는 진단, 한 번에 한 설정 변경, 다음 변경 순서를 지킨다. K3·K4·T3·T5와 집계·출처 변경은 조건부 또는 후속 작업으로 두어 첫 실험의 조합 수를 제한한다.

### 구현 시 변경 범위

- **v1 보존:** `baseline_protocol_v1.json`, `baseline_run_v1.json`, 분할·콘텐츠·Item-KNN·평가 산출물과 기존 재현 경로를 유지한다. 새 실험은 별도 코드·프로토콜·출력 디렉터리로 둔다.
- **Item-KNN:** 원시 공동 사용자 수, 게임별 긍정 사용자 수, 이웃 순위를 저장한다. 최대 K에서 일부 이웃 결과를 만들고, 신뢰도를 보정한 뒤 이웃을 다시 선택하는 기능과 실패 원인 분류를 준비한다.
- **TF-IDF:** 소개글 설정을 명시적으로 버전 관리하고, 태그·장르 파서·출처·특징 사전·채널별 프로필·점수 결합을 별도로 구현한다.
- **공통 평가:** v1의 고정 K=100 검사나 코드 해시값을 느슨하게 만들어 새 실험을 통과시키지 않는다. 새 실험 절차에는 허용한 설정과 모델·평가 코드 해시값을 기록한다. 기존 마스크·분모·동점·점수 검사는 그대로 재사용한다.
- **보관:** 사용자별 진단·추천은 Git 제외 경로에 저장하고, 저장소에는 집계·설정·출처 해시값·기획과 보고서를 남긴다.

## 6. 최초 제안한 착수 범위

**첫 작업 묶음은 K0·T0 진단과 K1·T1·T2의 작은 비교까지**로 제안한다. 원인을 구분한 뒤 K2와 기존 백로그의 태그·장르 보강 T4를 진행한다. 협업 필터링(Item-KNN)의 연결 문제와 콘텐츠 모델의 순위 문제를 따로 개선한다. 효과를 확인한 다음 입력 집계 방식이나 부정 신호를 다루는 후속 실험으로 넘어간다.
