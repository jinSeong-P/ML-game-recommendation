# A · games_metadata.json — 게임별 설명 및 태그

## 1. 원본 구조
- **원본**: A/`games_metadata.json` (약 17.5 MB).
- **한 행**: 게임 App ID 하나에 연결된 설명과 태그.
- **형식**: `pd.read_json(..., lines=True)`로 읽는 **줄 단위 JSON(JSON Lines)**.
- **활용**: 콘텐츠 기반 추천의 **태그·설명 입력**, A `games.csv`와 1:1 결합.

## 2. 컬럼 사전 — 원본 3개
| 컬럼 | 분석용 형식 | 의미 |
|---|---|---|
| `app_id` | int64 | A 게임 ID (50,872개 모두 `games.csv`와 일치) |
| `description` | str | 게임 설명 문자열, 태그와 결합해 TF-IDF 입력 가능 |
| `tags` | object | 게임 태그의 목록 형태 데이터. 유효성·빈 목록을 별도 검사해야 함 |

## 4. 2026-11-06 추가 분석에서 드러난 문제
- 리뷰가 있는 Linux 후보 6,630개 중 **A 태그가 비어 있는 117개**가 B 평가 정답 **24,704쌍의 58.76%**를 차지한다. 게임 *개수 기준* 결측률이 낮아도 성능 영향은 매우 클 수 있다.
- 인기 상위 50개 Linux 후보 중 **39개**가 A 태그를 갖고 있지 않다.
- 해당 117개 중 **107개는 C 태그로 보강 가능**, **10개는 A와 C의 태그/장르가 없음**.
- 보강해도 태그·장르·설명이 모두 비어 있는 후보 10개가 B 정답 1,392쌍(5.63%)을 차지한다.
- 설명·태그의 완전 중복/반복 문구, 언어 혼합이 코사인 유사도에 영향을 줄 수 있다. 설명을 무조건 길게 합친다고 품질이 오르는 것은 아니다(제안).

## 5. 베이스라인 전처리 제안 (미구현)
1. `tags`를 리스트로 정규화하고 **빈 문자열/빈 리스트/공백 설명**을 실질 결측으로 표시.
2. `app_id` 기준 A 우선, 비어 있는 태그는 C의 태그(없으면 장르), 비어 있는 설명은 C의 `short_description`/`about_the_game`으로 보충.
3. TF-IDF는 태그 단독 및 태그+설명 버전을 분리해 검증. 태그 결합·중복 단어 처리·설명 템플릿 제거를 실험 옵션으로 관리.
4. 텍스트를 만들 수 없는 게임은 **영벡터**, 게임 ID 매칭 실패와 별도 상태로 기록. 무작정 0으로 채우고 유효한 유사도인 것처럼 보고하지 않기.
5. C로 충분하지 않은 후보에 B의 `steam_games.json` 메타데이터를 쓸지는 외부 평가 독립성을 고려해 **실험 전에** 명시적 정책으로 확정.
