# A · recommendations.csv — 사용자 추천 리뷰

## 1. 역할과 데이터 단위
- **원본**: [Game Recommendations on Steam](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam) v28, A/`recommendations.csv` (약 2.02 GB).
- **한 행**: 사용자가 특정 Steam 게임에 남긴 **하나의 리뷰**. 구매·보유 이력 전체가 아님.
- **핵심 용도**: 학습용 사용자–게임 선호 신호, 협업 필터링(Item-KNN) 공동 긍정 기록, 내부 검증셋 구성.
- **연결 키**: `app_id` → A `games.csv` / `games_metadata.json`. `user_id` → A `users.csv`. B의 `user_id`와는 연결 금지.

## 3. 컬럼 사전 — 원본 8개
아래 자료형은 `scripts/preprocess.py`를 거친 **분석용 Parquet** 기준이며 원본 CSV 문자 표현과 다를 수 있다.

| 컬럼 | 변환 후 형식 | 의미와 주의점 |
|---|---|---|
| `app_id` | int32 | Steam 게임 ID. A/B/C 공통 게임 연결 기준 |
| `helpful` | int32 | 리뷰에 붙은 '도움됨' 반응 수. **게임 선호 라벨 아님** |
| `funny` | int32 | 리뷰에 붙은 '재미있음' 반응 수. **게임 선호 라벨 아님** |
| `date` | datetime | 리뷰 작성 날짜. 시간순 분할 후보 |
| `is_recommended` | bool | 사용자의 해당 게임 **긍정/부정 리뷰** 여부. 기본 학습 라벨 |
| `hours` | float32 | 리뷰 작성 시점 누적 플레이 시간(시간) |
| `user_id` | int32 | **A 내부 사용자** ID. 다른 데이터셋 사용자 ID와 합치지 않기 |
| `review_id` | int32 | 리뷰 식별자. 유일성/이력 중복 정책은 별도 확인 |

Parquet에서 8개 컬럼 모두 형식상 null 0건. 다만 null이 없다고 해서 라벨 편향이나 활동량 불균형까지 해결된 것은 아니다.

## 4. 데이터의 구조적 특징
- `is_recommended=True`가 85.78%여서 **긍정 라벨 우세**. 관측되지 않은 사용자–게임 조합은 부정이 아니라 **미관측**으로 다뤄야 한다.
- 사용자 과반은 리뷰 1건뿐이라 사용자 기반 CF에는 희소하며, 인기 게임으로 활동이 집중된다.
- `hours`의 0시간 기록은 약 0.43%, 최대 1,000시간으로 제한된 값이 보인다. 실제 전체 플레이 시간을 나타낸다고 단정하지 않는다.
- `helpful`는 78.88%, `funny`는 93.67%가 0. 노출 시기·인기도 영향 가능성이 있어 첫 베이스라인의 선호 라벨에서 제외하는 편이 적절하다(제안).
- Linux 게임에 대한 **긍정 리뷰는 10,428,788건**. 다만 Linux가 아닌 게임의 리뷰도 사용자 취향 추정에 활용할 수 있다.
- 긍정 기록에 사용자≥5·게임≥10을 반복 적용한 k-core: **1,621,480 사용자 / 26,064 게임 / 17,986,052 쌍**. 이것은 가능한 필터 결과이지 확정된 학습셋이 아니다.

## 5. 베이스라인 전처리 제안 (미구현)
1. `(user_id, app_id)` 중복 21건을 검사하고 라벨·날짜 충돌 여부를 확인한 뒤 중복 처리 방침을 고정.
2. 첫 Item-KNN에서는 긍정 리뷰를 이진 상호작용 1로 사용. 부정 리뷰와 미관측을 동일한 0으로 취급하는 것은 피하기.
3. 사용자·게임 최소 활동 기준을 적용한 버전과 원본 긍정 전체 버전을 별도로 보관해 커버리지 손실 비교.
4. 학습/검증 분할을 **사용자 단위로** 설계하고 추천 입력에 정답 게임이 들어가지 않게 검사. 시간순 검증은 날짜 범위를 별도로 활용.
5. A 전체 기간(2022년까지)으로 학습한 모델을 B의 2010~2015년 리뷰로 평가하면 시간 역전 가능성이 있음. 이를 엄격한 미래 예측이라고 표기하지 않기.
6. 인기도 집계와 모델 피처는 같은 학습 분할 안에서만 계산해 타깃 정보 누출 방지.
