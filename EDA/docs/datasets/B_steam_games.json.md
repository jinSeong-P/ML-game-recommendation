# B · steam_games.json — B 수집 시점 게임 메타데이터

## 1. 역할
- **원본**: B/`steam_games.json` (약 21.2 MB).
- **한 줄**: 게임·상품 관련 메타데이터 1개. 사용자 구매/리뷰 행이 아니다.
- **형식**: 줄 단위 Python 딕셔너리 리터럴; `ast.literal_eval`로 읽음.
- **목적**: B 내부의 상품명·게임 종류·태그·장르 확인, A 미매칭 App ID 조사, 메타데이터 누락 원인 점검.
- **메인 학습 추천**: 기본 TF-IDF는 **A + C의 미리 정한 메타데이터**를 사용. B 메타데이터를 쓰려면 외부 평가 독립성에 관한 규칙을 먼저 정할 것.

## 2. 전처리 후 14개 컬럼
원본을 그대로 덤프한 것이 아니라 `scripts/preprocess.py`가 선별한 필드다.

| 영역 | Parquet 열 | 정보 |
|---|---|---|
| 식별자 | `id_raw, id` | 원본 ID 문자열과 정수형 변환 App ID(`id` 파생) |
| 이름 | `app_name, title` | 서로 다른 게임 이름 표기 |
| 상품 시점 | `release_date, price, early_access` | 출시일 문자열, 가격 문자열, 얼리액세스 여부 |
| 장르/특징 | `genres, tags, specs` | 리스트·딕셔너리 등 중첩 가능 |
| 제작/유통 | `developer, publisher` | 개발사와 발행사 |
| 평판·주소 | `sentiment, url` | 상점 요약 감성 문자열/URL |

`price`는 숫자가 아닌 문자열로 보존되며, 가격 문자열이 숫자일 것으로 단정하면 안 된다. `genres`, `tags`, `specs`도 중첩 객체로 남는다.

## 4. A/C와의 관계
- B `steam_games` 고유 ID 32,132개 중 A 게임 ID와 공통인 것은 **16,214개(50.46%)**.
- A와 공통인 게임의 제목은 **약 96.2%**가 일치하지만 동명 게임이 있을 수 있어, 게임 이름 대신 **App ID로 연결**.
- A에 없는 B 보유 항목의 경우 B·C 메타데이터로 게임인지 DLC·소프트웨어·테스트 앱인지 확인하는 참고자료가 된다. A에 없게 된 이유를 자동으로 확정할 수는 없다.
- A/C 메타데이터만으로 단어가 없는 Linux 후보 10개 중 B에서 태그/장르 정보를 가진 게임은 **4개**(B 정답 1,335쌍). B 메타데이터 사용 여부는 평가 전에 확정해야 한다.

## 5. 베이스라인 전처리 제안 (미구현)
1. `id_raw`의 숫자 변환 실패와 공백/중복 App ID를 추적하고 단일 레코드 채택 기준 설정.
2. `app_name`, `title`, `genres`/`tags`의 형식을 정규화하되 값이 불명확한 경우 원문을 유지.
3. 게임 유형 구분은 확실한 메타데이터만 사용; **이름만 보고 DLC·베타 등을 단정하지 않기**.
4. `sentiment`나 게임 평판을 B 외부 평가의 정답 대리변수로 학습하지 않도록 구분.
5. B의 `user_id`와 A의 사용자 ID는 결합하지 않는다. 이 파일의 연결은 게임 ID 중심이다.
