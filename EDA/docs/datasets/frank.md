# frank 리뷰 — 외부 테스트

[frankjc2022/steam-dataset](https://huggingface.co/datasets/frankjc2022/steam-dataset/tree/75694cc07a6cdc69f48f9c316ca1e3e38a3f0f89) 저장소의 특정 시점 commit **`75694cc07a6cdc69f48f9c316ca1e3e38a3f0f89`**를 고정했습니다. `data/v1/reviews.parquet`에서 필요한 6개 열에 해당하는 **2,631,430행**을 HTTP Range 요청(파일의 필요한 구간만 읽는 방식)으로 가져왔습니다. 리뷰 본문이나 원본 파일에서 가져오지 않은 열·데이터까지 검증한 것은 아닙니다.

| 추출한 열 | 의미 |
|---|---|
| `author_steamid` | 문자열로 저장된 원 Steam 계정 ID |
| `appid` | Steam 게임 식별자 |
| `recommendationid` | 문자열로 저장된 원 리뷰 ID |
| `voted_up` | 긍정·부정 리뷰 |
| `timestamp_created` | 최초 작성 Unix 시각 |
| `timestamp_updated` | 갱신 Unix 시각 |

사용자–게임 조합에서 긍정·부정 라벨이 서로 충돌하는 경우를 제거한 뒤 합친 전체 리뷰는 **2,631,416쌍·1,336,109계정·44,517개 App ID**입니다. 이 규모는 알려진 모호한 리뷰–게임 연결 296개 ID를 평가에서 제외하기 **전** 수치입니다. 게임당 리뷰가 최대 100개로 제한되어 있고 사용자별 이력도 짧으므로 전체 Steam 이용자를 대표하는 자료로 보지 않습니다.

고정 입력 카탈로그에서 리뷰가 2개 이상이고 긍정 Linux 리뷰가 하나 이상인 **87,573계정**을 학습 제외용으로 미리 예약했습니다. 최종 평가 대상이 줄어도 이 계정은 모두 Kieran 학습에서 제외합니다. 기본 평가 방식은 사용자마다 조건을 만족하는 긍정 Linux 게임 하나를 같은 확률로 무작위 선택해 숨기는 것입니다. seed와 사용자별 정답 파일 목록·검증 정보(manifest)를 저장하도록 정했습니다. seed **20261107**로 최종 사용자·입력·정답·제외 목록과 파일 목록·검증 정보를 만들었고 저장된 전체 데이터를 검증했습니다. 2026-11-08 두 기준 모델의 공통 검증·frank 테스트도 완료했습니다. [실제 성능 보고서](../../reports/baseline_v1.md)와 [분할 파일 안내](../modeling_splits.md)를 참고하세요. 아래 사용자 수는 모호한 리뷰–게임 연결을 가진 사용자–게임 조합을 평가에서 제외한 뒤, 긍정 Linux 정답 하나를 숨겼을 때 남는 전체·긍정 입력 게임 수로 계산한 EDA 잠재 규모입니다.

| 정답 숨김 뒤 최소 전체 입력 게임 | 전체 입력 조건을 만족하는 후보 | 그중 긍정 입력 ≥1인 잠재 후보 |
|---|---:|---:|
| 1 | 87,557 | 78,228 |
| 3 | 39,450 | 38,549 |
| 5 | 24,571 | 24,342 |
| 10 | 11,647 | 11,609 |

기본 평가 조건은 정답을 숨긴 뒤 **전체 입력 게임 ≥5, 긍정 입력 게임 ≥1**입니다. 전체 입력 ≥5인 후보 24,571명 중 긍정 입력이 남지 않는 229명은 두 모델에서 함께 제외합니다. 따라서 확정 조건의 **EDA 잠재 규모는 24,342명**입니다. 이 24,342명을 실제 평가 명단에 저장하고, 입력 이력 461,599쌍과 정답 24,342쌍을 만들었습니다. 위 표의 다른 입력 조건은 EDA 잠재 규모로 남겨 둡니다. 전체 입력 ≥3·긍정 입력 ≥1 조건은 후속 실험이며 잠재 규모는 38,549명입니다.

정답을 숨긴 뒤 나머지 적격 리뷰 이력을 전부 입력으로 둡니다. 두 모델은 사용자의 취향과 추천 점수를 계산할 때 남은 긍정 리뷰만 사용합니다. 입력에 남은 긍정·부정 게임은 모두 다시 추천하지 않도록 제외 목록에 넣고, 숨긴 정답은 입력 이력과 제외 목록에서 빼 추천할 수 있게 둡니다. 두 모델은 같은 사용자·입력 이력·정답·고정 Linux 후보 6,630개를 사용합니다. 긍정 입력은 모두 같은 비중으로 집계합니다. TF-IDF는 각 게임 소개글 벡터를 L2 정규화해 평균한 뒤 후보와 코사인 유사도를 계산합니다. Item-KNN은 후보와 긍정 입력 게임 사이 유사도의 합을 전체 긍정 입력 수로 나누며 연결이 없는 경우에는 0으로 계산합니다. 개인화 점수가 양수인 후보만 최대 10개 추천하고, 부족한 자리는 인기도순이나 무작위 게임으로 채우지 않습니다. 조건을 만족하는 사용자의 빈 목록도 Recall@10·NDCG@10 계산에 포함합니다.

소개글 기준 모델은 A `description`을 먼저 사용하고, 값이 없거나 비어 있거나 공백만 있으면 C `short_description`으로 보충합니다. TF-IDF에는 태그·장르를 넣지 않습니다. 두 모델은 점수를 계산할 때 긍정 입력만 사용하지만, 부정 리뷰한 게임도 추천에서 제외합니다. [정답 숨김 방식](../holdout_options.md)에는 기본 규칙, 시간순·반복 숨김 참고 방식, 여러 정답을 동시에 숨기는 향후 실험을 정리했습니다. 입력 집계 방식 변경(플레이타임 가중 포함)과 모델 개선 후 인기도순 빈자리 채우기도 후속 백로그입니다.

로컬 자료는 `EDA/data/processed/frank/`에 있습니다. `user_games`에 있는 보유·플레이 열도 포함해 필요한 모든 행을 별도로 저장했지만, **현재 확정한 테스트 입력은 리뷰**입니다. 플레이타임 가중 집계는 후속 실험입니다. 보유 게임 이력을 더하는 실험은 별도이며, 이 자료를 추가해도 테스트 계정의 다른 이력을 학습에 쓸 수 없습니다.
