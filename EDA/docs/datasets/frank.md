# frank 리뷰 — 외부 테스트

[frankjc2022/steam-dataset](https://huggingface.co/datasets/frankjc2022/steam-dataset/tree/75694cc07a6cdc69f48f9c316ca1e3e38a3f0f89) commit **`75694cc07a6cdc69f48f9c316ca1e3e38a3f0f89`**를 고정했습니다. `data/v1/reviews.parquet`에서 필요한 6개 열의 전체 **2,631,430행**을 HTTP Range로 읽었습니다. 리뷰 본문·원본 파일의 읽지 않은 열과 바이트까지 검증한 것은 아닙니다.

| 투영 열 | 의미 |
|---|---|
| `author_steamid` | 문자열로 저장된 원 Steam 계정 |
| `appid` | Steam 게임 식별자 |
| `recommendationid` | 문자열로 저장된 원 리뷰 식별자 |
| `voted_up` | 긍정·부정 리뷰 |
| `timestamp_created` | 최초 작성 Unix 시각 |
| `timestamp_updated` | 갱신 Unix 시각 |

사용자–게임 라벨 충돌을 제거하고 합친 전체 리뷰는 **2,631,416쌍·1,336,109계정·44,517개 App ID**입니다. 이 수치는 알려진 리뷰–게임 연결 모호성 296개 ID를 평가 범위에서 제거하기 **전** 전체 규모입니다. 앱당 최대 100리뷰 제한과 짧은 사용자 이력이 있어 전체 Steam 이용자를 대표하는 자료로 해석하지 않습니다.

고정 입력 카탈로그에서 리뷰가 2개 이상이고 Linux 긍정 리뷰가 하나 이상인 **87,573계정**을 학습 제외용 예비 집단으로 예약했습니다. 최종 평가 집단이 줄어도 이 계정은 전부 Kieran 학습에서 제외합니다. 기본 평가 프로토콜은 사용자별 적격 긍정 Linux 게임 하나를 균등 무작위로 숨기고, 실제 seed와 사용자별 정답 manifest를 저장하는 방법으로 확정했습니다. seed **20261107**로 최종 사용자·입력·정답·제외 목록과 manifest를 생성하고 저장 파일 전수 검증을 완료했습니다. 2026-11-08 두 베이스라인의 공통 검증·frank 테스트도 완료했습니다. [실제 성능 보고서](../../reports/baseline_v1.md)를 참고하세요. [분할 파일 안내](../modeling_splits.md)를 참고하세요. 아래 후보 수는 알려진 리뷰–게임 연결 모호성이 있는 사용자–게임 쌍을 평가에서 제외한 뒤 긍정 Linux 정답 하나를 숨겼을 때 남는 전체·긍정 입력 게임 수로 계산한 EDA 잠재 수치입니다.

| 정답 숨김 뒤 최소 전체 입력 게임 | 전체 입력 조건을 만족하는 후보 | 그중 긍정 입력 ≥1인 잠재 후보 |
|---|---:|---:|
| 1 | 87,557 | 78,228 |
| 3 | 39,450 | 38,549 |
| 5 | 24,571 | 24,342 |
| 10 | 11,647 | 11,609 |

기본 평가 적격 조건은 정답을 숨긴 뒤 **전체 입력 게임 ≥5, 긍정 입력 게임 ≥1**입니다. 따라서 전체 입력 ≥5인 후보 24,571명 중 긍정 입력이 남지 않는 229명을 공통 제외하며, 확정 조건의 **EDA 잠재 규모는 24,342명**입니다. 이 24,342명을 실제 적격 명단에 저장했고, query 461,599쌍·정답 24,342쌍을 생성했습니다. 위 표의 다른 입력 기준은 EDA 잠재 규모로 유지합니다. 전체 입력 ≥3·긍정 입력 ≥1 조건은 후속 실험이며 EDA 잠재 규모는 38,549명입니다.

정답을 숨긴 뒤 나머지 적격 리뷰 이력을 모두 입력으로 남깁니다. 두 모델의 사용자 취향·추천 점수에는 남은 긍정 리뷰만 사용하고, 입력에 남은 긍정·부정 게임은 모두 재추천 제외 마스크에 넣습니다. 숨긴 정답은 입력과 제외 마스크에서 제거해 추천 가능하게 둡니다. 두 모델은 같은 사용자·입력·정답·고정 Linux 후보 6,630개를 사용합니다. 긍정 입력은 동일 가중 평균으로 집계합니다. TF-IDF는 게임별 L2 정규화 소개글 벡터를 평균한 뒤 후보와 코사인 유사도를 계산하고, Item-KNN은 후보별 긍정 입력 유사도 합을 전체 긍정 입력 수로 나누며 빠진 유사도는 0으로 취급합니다. 양수 개인화 점수 후보만 최대 10개 추천하고, 부족한 슬롯은 인기순이나 무작위로 채우지 않고 비웁니다. 적격 사용자의 빈 추천 목록도 Recall@10·NDCG@10 분모에 유지합니다.

소개글 베이스라인은 A `description`을 우선 사용하고 결측·빈 문자열·공백뿐인 경우 C `short_description`으로 보충합니다. TF-IDF에 태그·장르는 사용하지 않습니다. 두 모델의 점수는 긍정 입력만 사용하지만 부정 리뷰도 제외 마스크에 보존합니다. [정답 숨김 방법](../holdout_options.md)에는 선택한 기본 프로토콜과 시간순·반복 숨김 참고 대안, 여러 정답 동시 숨김 향후 백로그 실험을 정리했습니다. 대안 입력 집계(플레이타임 가중 포함)와 모델 개선 후 인기순 빈자리 보완도 후속 백로그입니다.

로컬 위치는 `EDA/data/processed/frank/`입니다. `user_games`의 보유·플레이 열 전체 행 투영도 보존했지만 **현재 확정 테스트의 입력은 리뷰**입니다. 플레이타임을 포함한 가중 집계는 후속 실험입니다. 보유 이력을 추가하는 실험은 별도이며, 추가해도 테스트 계정의 다른 이력을 학습에 사용할 수 없습니다.
