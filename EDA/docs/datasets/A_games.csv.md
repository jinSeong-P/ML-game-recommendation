# A · games.csv — 게임 카탈로그 및 공식 Linux 조건

## 1. 역할과 데이터 단위
- **원본**: A/`games.csv` (약 4.86 MB).
- **한 행**: Steam App ID 하나의 게임 정보. 리뷰 데이터가 아니라 **카탈로그 스냅샷**.
- **핵심 용도**: 원본 게임 ID 매핑, 공식 Linux 지원 후보 필터, 가격·출시일·리뷰 수 등 보조 분석.
- **연결**: `app_id`를 `recommendations.csv`, `games_metadata.json`, C `appid`, B `item_id`와 조인.

## 2. EDA에서 확인한 특징
| 항목 | 결과 |
|---|---:|
| 전체 게임 수 | **50,872** (App ID 중복 0) |
| `linux=True` | **9,041개 (17.77%)** |
| Linux 게임 중 A 리뷰가 있는 게임 | **6,630개** |
| Linux 게임 중 긍정 리뷰 ≥10건 | **5,497개** |
| Linux 게임 긍정률(리뷰 행 기준) | **90.02%** |
| 게임 출시일 범위 | **1997-06-30 ~ 2023-10-24** |
| C와 공통 게임 Linux 표시 일치 | **99.38%** (공통 35,876개) |

`linux=True`는 **A에 표시된 공식 Linux 지원**을 뜻하며 Proton이나 Steam Deck에서의 실행 가능성과 동일하지 않다. **전체 50,872개 게임의 정보와 리뷰는 학습·사용자 입력에 활용할 수 있고, 공식 Linux 9,041개는 추천 출력 후보의 상한**이다. 실제 추천 범위(예: 리뷰가 있는 Linux 6,630개)는 모델별로 사전 정의해야 한다.

## 3. 컬럼 사전 — 원본 13개
| 컬럼 | Parquet 형식 | 해석·사용 시 주의 |
|---|---|---|
| `app_id` | int64 | 게임의 고유 키 |
| `title` | str | 표시 제목, 이름만으로 조인하지 않기 |
| `date_release` | datetime | A 스냅샷 출시일. B 리뷰 날짜와의 시간 일치 보장 없음 |
| `win` | bool | 공식 Windows 지원 여부 |
| `mac` | bool | 공식 macOS 지원 여부 |
| `linux` | bool | **공식 Linux 지원**, 추천 출력 조건 |
| `rating` | str | 게임에 대한 집계 평가 등급(문자열) |
| `positive_ratio` | int64 | 상점의 긍정 리뷰 비율로 해석되는 집계 필드 |
| `user_reviews` | int64 | 상점에 표시된 리뷰 수 계열 집계 |
| `price_final` | float64 | 수집 시점 최종 가격. 통화·현재 가격 재검증 필요 |
| `price_original` | float64 | 수집 시점 할인 전 가격 |
| `discount` | float64 | 수집 시점 할인 정도 |
| `steam_deck` | bool | 원본의 Deck 플래그. **실제 호환성 판정에 사용 주의** |

분석용 Parquet 13개 컬럼 모두 `isna()` 기준 결측 0. 값의 신뢰성은 별개이며 시점 차이를 고려해야 한다.

## 4. 핵심 제약과 함정
- 2026-11-06 추가 분석에서 `steam_deck`는 **50,872개 중 50,870개가 True**였다. 게임별 Deck 적합성 분류에 거의 쓰기 어려운 값이므로 `linux`를 대체하지 않는다.
- `user_reviews`와 수집된 `recommendations.csv` 행 수는 같은 모집단이 아니다. 수집 리뷰 수/상점 리뷰 수의 단순 비율이 1을 넘는 게임도 **4,993개**. 정확한 표집률로 해석하면 안 된다.
- B의 리뷰는 주로 ~2015년이지만, A 출시일이 2016년 이후인 B 긍정 정답은 **2,660쌍(10.8%)** 존재. 출시일만으로 B 평가 후보를 거르면 정답을 잘못 배제할 수 있다.
- 게임 수가 아니라 **정답 쌍 기준의 편향**도 함께 살핀다. Linux 인기 상위 1% 게임에 Linux 긍정 리뷰의 약 51.2%가 집중된다.
- 상점 집계 피처 `positive_ratio`, `user_reviews` 등은 평가 시점보다 미래 정보이거나 정답의 대체 신호가 될 수 있다. 베이스라인 학습 피처로 무조건 섞지 않는다(제안).

## 5. 베이스라인 전처리 제안 (미구현)
1. `app_id` 기준 A·C 정보를 연결하고 `linux`를 **최종 추천 후보·평가 정답 필터**로 정의. **학습 시 비Linux 게임의 리뷰·메타데이터도 유지**하여 신규 사용자의 이력을 표현한다.
2. `date_release`/가격/집계 통계는 우선 참고만 하고 첫 TF-IDF·Item-KNN의 핵심 입력에서 제외.
3. 공식 Linux 후보 집합을 실험마다 고정(전체 9,041 vs 리뷰 존재 6,630 등)하고 두 모델에 동일 적용.
4. C에만 존재하는 게임을 합칠 경우 A 리뷰를 바탕으로 한 협업 추천이 해당 게임을 직접 학습할 수 없다는 점을 구분.
5. `steam_deck`는 의미·수집 스키마를 별도 검증하기 전 평가 조건에 사용하지 않기.
