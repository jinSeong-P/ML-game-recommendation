# 레포트 작성 가이드라인
## Steam 리뷰 기반 Linux 게임 추천 — 중간 과정 보고서

- 독자: 머신러닝 기초는 알지만 이 프로젝트는 모르는 강사와 동기
- 목표: 최종 점수 자랑이 아니라, 어떤 문제를 어떤 근거로 어떻게 풀었는지 설명하는 보고서
- 적용: 본문 10개 장, 부록 1개 장. 3절의 장별 지침을 목차 순서대로 쓰고, 4~7절 규칙을 모든 장에 적용한다.

---

## 1. 목적·독자·분량·형식

### 1.1 목적
이 보고서는 프로젝트의 중간 과정을 기록한다. 완성된 모델 소개가 아니라, 문제를 정의하고 데이터를 고르고 평가 방법을 바꾸고 모델을 개선한 판단 과정을 남긴다. 채택하지 않은 후보와 실패한 시도도 결과만큼 중요하다. 독자가 "왜 이 모델을 최종으로 골랐는가"를 보고서만 읽고 설명할 수 있어야 한다.

### 1.2 독자
독자는 지도 학습, 검증, 과적합, Recall 같은 개념을 안다. 그러나 Steam 리뷰 데이터의 구조, 이 프로젝트의 데이터 이름, 내부 실험 코드는 모른다. 모든 데이터 이름과 평가 집단은 처음 나올 때 정의한다. 내부 파일명·브랜치명·실험 코드는 본문에 쓰지 않는다.

### 1.3 분량
아래 분량과 형식은 팀 권장값이다. 강의 공지에 기준이 있으면 공지를 따른다.

- 본문 12~16쪽(A4, 그림·표 포함). 부록 2~3쪽.
- 장별 권장 분량은 2절의 표를 따른다. 한 장에 메시지 하나를 둔다.
- 그림과 표는 본문 분량에 포함한다. 부록에 밀어 넣어 본문의 논리를 끊지 않는다.

### 1.4 파일 형식
- 제출본: `.docx` 원본과 `.pdf` 사본을 함께 낸다. PDF는 글꼴·그림 배치를 고정하기 위한 사본이다.
- A4, 본문 11pt, 줄간격 1.4, 여백 2.5cm. 그림은 300dpi PNG.
- 표 제목은 표 위, 그림 제목은 그림 아래에 둔다. 번호는 `표 1`, `그림 1`로 통일한다.
- 파일명 예: `ML_game_recommendation_report_팀명.docx`. 정확한 제출 기한·제출처·쪽수 제한은 강의 공지에서 **확인 필요**.

## 2. 권장 목차

| 장 | 권장 쪽 | 핵심 질문 |
|---|---:|---|
| 1. 서론 — 문제 정의 | 1 | 무엇을 왜 추천하는가? |
| 2. 데이터 소개 | 1.5 | 어떤 데이터를 어떤 역할로 썼는가? |
| 3. 시간 분할 시도와 한계 | 2 | 날짜로 나누면 왜 평가셋이 부족했는가? |
| 4. 계정 분할 설계와 전처리 | 2 | 같은 사용자가 학습·평가에 섞이지 않게 어떻게 나눴는가? |
| 5. 평가 방법 | 1.5 | 무엇을 정답으로 숨기고 어떻게 채점했는가? |
| 6. 베이스라인 | 1 | TF-IDF와 Item-KNN의 첫 결과는 어땠는가? |
| 7. 개선 과정(1차~4차) | 3.5 | 각 개선의 문제·가설·실험·판정은 무엇인가? |
| 8. 최종 결과와 해석 | 1.5 | 최종 모델은 어느 집단에서 얼마나 나았고, 왜 그 모델인가? |
| 9. 한계와 향후 과제 | 1.5 | 이 결과를 어디까지 믿을 수 있는가? |
| 10. 역할 분담 | 0.5 | 누가 무엇을 맡았는가? |
| 11. 부록 — 재현 방법, 용어 | 2~3 | 독자가 같은 표를 다시 만들 수 있는가? |

초록은 선택이다. 넣을 경우 1쪽 이내로 서론 앞에 두고, 본문 12~16쪽 안에 포함한다.

**서술 순서 고정:** 시간 분할 시도 → 평가셋 부족 → 계정 분할 전환 → 베이스라인 → 1차~4차 개선 → 최종 모델 → 외부 평가 → 한계. 최종 모델을 1장에 먼저 소개하지 않는다.

## 3. 장별 작성 지침

각 장은 **내용 → 수치·근거 → 그림·표 → 흔한 실수** 순서로 적는다.

### 3.1 서론 — 문제 정의

- **내용:** Linux 사용자가 취향에 맞는 게임을 찾기 어렵다는 문제를 제시한다. 목표는 "아직 하지 않은 Linux 게임 10개 추천"이다. 두 접근(소개글·태그 기반 TF-IDF, 공동 긍정 리뷰 기반 Item-KNN)을 한 문단씩 소개한다. 이 보고서가 답할 두 질문을 밝힌다. ① 특정 날짜 이후에 좋아할 게임을 맞히는가(시간 분할), ② 처음 보는 사용자에게도 잘 추천하는가(계정 분할). 마지막에 보고서 구성을 한 문단으로 안내한다.
- **수치·근거:** Steam 게임 50,872개 중 Linux 지원 9,041개(17.8%). 근거 `README.md`, `EDA/reports/eda_summary.md`. 모델 입력 게임 37,610개, Linux 추천 후보 6,630개. 근거 `EDA/docs/modeling_splits.md`. 리뷰 41,154,794행·사용자 13,781,059명은 필요할 때만 쓴다.
- **그림·표:** Linux 지원 비율 막대그래프(50,872/9,041, `EDA/reports/eda_summary.md` §2). 데이터→분할→모델→평가 흐름도(직접 작성). 두 평가 질문 비교표(시간 분할/계정 분할).
- **흔한 실수:** "Linux 게임이 Steam 전체의 17.8%"라고 일반화한다. 17.8%는 이 데이터 스냅샷의 50,872개 기준이다. 모델 이름부터 쓰고 문제를 나중에 설명한다. "최고 성능", "획기적" 같은 표현으로 시작한다.

### 3.2 데이터 소개

- **내용:** 데이터를 두 묶음으로 나눠 설명한다. 첫째, 시간 분할에 쓴 익명 리뷰·호주 리뷰·게임 정보. 둘째, 계정 분할에 쓴 학습 데이터·100개 제한 평가셋·대규모 평가셋. 각 데이터의 역할, 수집 시점, 계정 ID 유무, 라벨 정의(긍정·부정)를 적는다. "왜 중간에 데이터를 바꿨는가"를 이 장에서 예고하고 3장(시간 분할)과 4장(계정 분할)에서 설명한다. 정식 이름 표는 4절을 따른다.
- **수치·근거:** 아래 표를 기본으로 하고, 원자료 수치를 모두 나열하지 않는다.

| 데이터 | 원본 규모 | 정리·사용 규모 | 역할 |

### 3.3 시간 분할 시도와 한계

- **내용:** 날짜 기준 분할을 먼저 시도한 이유를 설명한다. 1안은 익명 리뷰를 2022-01-01로 나눈다. 학습은 2021년까지, 평가는 2022년 리뷰다. 2안은 익명 리뷰 2014년까지로 학습하고 호주 리뷰 2015년으로 평가한다. 2안의 2014년 경계는 모델 점수를 보기 전에 정했다. 각 안의 학습·평가 규모, 평가 대상, 결과를 적는다. 마지막에 "두 안 모두 모델을 고를 만한 평가셋을 만들기 어려웠다"는 판단과 계정 분할 전환을 적는다. 이 장의 결과는 **참고용**임을 명시한다.
- **수치·근거:** 1안 Train 31,565,267행 / Test 9,589,527행, Linux 긍정 Train 2,474,413행 / Test 1,813,755행. 근거 `SM/ML3.ipynb`. 표본 200명 중 학습 이력이 남은 7명만 점수 계산에 포함됐다(발표 덱 기준). 1안 Recall@10 Item-KNN 35.61%, TF-IDF 1.43%, NDCG@10 0.204/0.014. 같은 파일. 2안 익명 리뷰 2014년까지 학습 1,499,584리뷰·777,005명, 익명 리뷰 내부 검증 17,065명, 호주 2015 평가 1,536명·정답 1,546개·Linux 후보 858개. Recall@10 인기순 48.96%, Item-KNN 29.52%, TF-IDF 11.65%, NDCG@10 0.257/0.150/0.057. 근거 `JY/Model_Experiments/README.md` §2~§5. 연도 집중: 익명 리뷰 2020–22년 62.9%, 2014년까지 4.0%; 호주 리뷰 날짜 있는 리뷰의 2014–15년 82.5%, 연도 미상 17.1%. 근거 `EDA/reports/tables/02_reviews_by_year.csv`(직접 계산), `EDA/reports/eda_summary.md`.
- **그림·표:** 연도별 리뷰 비중 그래프(위 CSV). 두 안의 분할 설계 비교표(학습 기간/평가 기간/사용자/후보/모델/Recall@10). 2안 결과 막대그래프(인기순 48.96, Item-KNN 29.52, TF-IDF 11.65). 연도 경계 후보 표(`JY/Model_Experiments/README.md` §2): 2012년 경계는 평가 2,794명·후보 196개, 2013년은 3,589명·412개, 2014년은 1,536명·858개.
- **흔한 실수:** 200명을 평가했다고 쓴다. 실제 점수는 학습 이력이 남은 7명 기준이다. 1안과 2안의 Recall 정의가 다른데(1안은 미래 긍정 게임 여러 개, 2안은 사용자별 20% 숨김) 한 표에서 순위를 매긴다. 2안 Item-KNN 29.52%와 최종 대규모 평가 29.49%를 "거의 같다"고 비교한다. 인기순이 48.96%로 개인화 모델보다 높았다는 사실을 빼고 "시간 분할은 실패"라고만 쓴다. 호주 리뷰가 이미 여러 번 확인한 자료라 독립 시험이 아니라는 점을 빠뜨린다.

### 3.4 계정 분할 설계와 전처리

- **내용:** 계정 단위로 학습·검증·평가 사용자를 분리하는 원칙을 설명한다. 학습 데이터에서 평가 대상 계정의 리뷰를 미리 제외한다. 100개 제한 평가셋과 대규모 평가셋의 예약 계정을 학습에서 모두 뺀다. 해시 기반 검증 분리, 정답 1개 숨기기, 최소 입력 조건을 순서대로 적는다. 전처리(중복·라벨 충돌 제거, 긍정 리뷰만 점수에 사용, 리뷰한 게임은 모두 추천 제외)를 표로 정리한다.
- **수치·근거:** 100개 제한 평가셋 예약 계정 87,573명. 내부 검증 325,639명, 100개 제한 평가셋 평가 24,342명. 입력 게임 37,610개, Linux 후보 6,630개. seed 20261107. 근거 `EDA/docs/modeling_splits.md`, `EDA/docs/datasets/frank.md`. 대규모 평가셋 395,421명, 학습에서 제외한 계정 451,959명, 재학습 긍정 72,292,011쌍·29,513,014계정, 학습·평가 계정 중복 0. 근거 `EDA/reports/forgemaster_model_evaluation.md`. 4차 확인 평가 10,000명, 예약 60,000명, 비교 조건 145개. 근거 `EDA/reports/model_improvement_v4.md`.
- **그림·표:** 계정 분할 흐름도(`EDA/docs/datasets/README.md` mermaid). 평가 집단 크기 표(내부 검증 325,639 / 100개 제한 24,342 / 대규모 395,421 / 4차 확인 10,000). 정답 숨김 전후 사용자 수 표. 전처리 규칙 표(중복 제거, 라벨 충돌, 긍정만 점수, 리뷰 게임 제외, 빈 목록 유지).
- **흔한 실수:** 예약 계정 87,573명과 실제 평가 24,342명을 바꿔 쓴다. 100개 제한(게임당 리뷰 수)과 K=100(이웃 수)을 같은 값으로 설명한다. "계정 분할"이라고 쓰면서 같은 사용자를 학습과 평가에 넣는다. 395,421명과 4차 확인 10,000명을 같은 집단처럼 비교한다. 테스트 계정을 학습에서 빼지 않았다고 쓰거나, 반대로 모든 과거 실험에서 완전히 분리됐다고 쓴다.

### 3.5 평가 방법

- **내용:** 사용자별로 긍정 평가한 Linux 게임 1개를 균등 무작위로 숨긴다. 숨긴 뒤 전체 입력 5개 이상, 긍정 입력 1개 이상인 사용자를 평가한다. 남은 긍정 리뷰로 점수를 계산하고, 리뷰한 긍정·부정 게임은 모두 추천에서 제외한다. 양수 점수 게임을 최대 10개 추천하고, 빈자리는 인기순으로 채우지 않는다. 빈 목록도 분모에 남긴다. 동점은 App ID 오름차순이다. 지표 정의와 인기순 기준선을 함께 적는다.
- **수치·근거:** 후보 6,630개. 균등 무작위 기대 Recall@10 0.1509%. 내부 검증 인기순은 Recall@10 31.9344%, NDCG@10 0.201961이고, 대규모 평가셋 인기순은 Recall@10 21.24%, NDCG@10 0.12993이다. 근거 `EDA/reports/baseline_v1.md`, `EDA/reports/forgemaster_model_evaluation.md`. 100개 제한 평가셋 인기순은 Recall@10 0.0657%, NDCG@10 0.000288로 내부 검증과 크게 다르다. 이 차이를 모델 성능으로 해석하지 않고 집단·정답 분포 차이로 설명한다.
- **그림·표:** 평가 절차 도식(리뷰 기록→정답 숨김→Top 10→채점). 지표 정의 표(Recall@10, NDCG@10, 인기순, 무작위). 평가 집단 표(이름·사용자 수·용도). NDCG 계산식 `1/log2(순위+1)`.
- **흔한 실수:** Recall@10을 "정확도"라고 부른다. NDCG@10 0.172를 "17.2%"로 쓴다. 인기순 기준선을 빼고 개인화 모델 점수만 보고한다. 빈 추천 사용자를 분모에서 제외한다. 테스트 결과를 보고 모델 설정을 다시 고른다.

### 3.6 베이스라인

- **내용:** 두 모델을 같은 사용자·같은 정답·같은 후보 6,630개에서 비교한다. TF-IDF는 게임 소개글을 단어 벡터로 만들고, 사용자의 긍정 게임 벡터 평균과 후보의 코사인 유사도를 계산한다. Item-KNN은 함께 긍정 평가된 사용자 수로 게임 간 유사도를 만들고, 후보마다 유사한 이웃 100개를 저장한다. K=100은 검증 성능에 맞춰 고른 값이 아니라 처음 고정한 설정이다. 두 모델의 점수 범위가 달라 직접 크기를 비교하지 않고 순위 지표로 비교한다.
- **수치·근거:** 내부 검증 325,639명에서 소개글 TF-IDF는 Recall@10 1.9251%, NDCG@10 0.012064이고, Item-KNN K=100은 Recall@10 40.0757%, NDCG@10 0.244328이다. 100개 제한 평가셋 24,342명에서 TF-IDF는 Recall@10 3.5782%, NDCG@10 0.024254이고, Item-KNN은 Recall@10 11.1905%, NDCG@10 0.074859다. 근거 `EDA/reports/baseline_v1.md`. Item-KNN은 긍정 78,315,268쌍·29,836,980명으로 학습했고, 6,630×37,610 행렬에 634,820개 연결을 저장했다. 이웃이 있는 후보는 6,586개, 없는 후보는 44개다.
- **그림·표:** 베이스라인 성능 표(평가 집단·모델·사용자·Recall@10·NDCG@10·빈 목록). 두 모델의 입력·점수 계산 비교표. 인기순 기준선을 같은 표에 넣는다.
- **흔한 실수:** 40.08%를 "좋은 성능"이라고만 쓰고 집단을 빼놓는다. TF-IDF 1.93%와 Item-KNN 40.08%를 "TF-IDF는 쓸모없다"로 결론 낸다. 이후 개선에서 TF-IDF가 14.51%까지 오른 사실을 무시한다. 인기순 기준선을 빼고 Item-KNN만 강조한다.

### 3.7 개선 과정 — 1차~4차

- **내용:** 각 개선을 **문제→가설→실험→판정** 네 문장으로 쓴다. 문제에는 근거 수치를 붙인다. 가설은 "왜 그 변경이 문제를 줄이는가"를 한 문장으로 쓴다. 실험은 같은 평가 집단·같은 정답·같은 후보를 유지했는지 밝힌다. 판정은 채택·미채택과 그 이유를 적는다. 좋아진 지표만 쓰지 말고, 나빠진 지표와 통과하지 못한 기준을 함께 쓴다. 개선 단계는 **1차~4차 개선**으로만 부른다.
- **1차 개선(콘텐츠):** 문제 — 소개글만 쓴 TF-IDF가 내부 검증 Recall@10 1.9251%, 100개 제한 평가셋 3.5782%에 그쳤다. 가설 — 태그·장르를 50% 결합하면 소개글에 없는 장르 신호를 보완한다. 실험 — 소개글+태그·장르 50:50, α 0.25/0.5/0.75/1.0 비교, 같은 내부 검증 325,639명·100개 제한 24,342명. 판정 — 내부 검증 Recall@10 9.5102%, NDCG@10 0.052997; 100개 제한 Recall@10 6.7004%, NDCG@10 0.041211로 채택. 근거 `EDA/reports/model_improvement_v2.md`.
- **2차 개선(협업):** 문제 — 리뷰 25개 이상 계정 0.64%가 공동 리뷰 쌍의 62.6%를 차지해 소수 활동 계정이 유사도를 지배했다. 가설 — 사용자 활동량의 역수로 기여를 줄이면 취향이 넓은 사용자의 영향을 완화한다. 실험 — 활동량 역수 가중 코사인, K=100, 같은 집단. 판정 — 내부 검증 Recall@10 40.0757%→40.9285%(+0.8528%p), NDCG@10 0.244328→0.251506으로 채택. 100개 제한 평가셋은 Recall@10 11.1905%→10.8578%(-0.3327%p), NDCG@10 0.074859→0.070161로 낮아졌다. 이 하락을 숨기지 않는다. 근거 `EDA/reports/model_improvement_v3.md`, `EDA/docs/modeling_backlog.md`.
- **3차 개선(콘텐츠 확장):** 문제 — 소개글·태그·장르만으로는 개발사·기능 분류·유통사 정보를 쓰지 못했다. 가설 — 확장 메타데이터를 별도 채널로 50% 결합하면 콘텐츠 성능이 오른다. 실험 — 소개글 50% + 태그·장르·기능 분류·개발사·유통사 50%, 같은 집단. 판정 — 내부 검증 Recall@10 9.5102%→14.5075%(+4.9973%p), NDCG@10 0.052997→0.083372; 100개 제한 Recall@10 6.7004%→9.6418%(+2.9414%p), NDCG@10 0.041211→0.061489로 채택. 근거 `EDA/reports/model_improvement_v3.md`.
- **4차 개선(선형 모델):** 문제 — 전체 평균이 높아도 비인기 게임 성능이 낮았다. 이전 실험에서 EASE는 내부 검증 Recall@10 45.5870%였지만 게임별 평균 NDCG와 학습 긍정 사용자 1–999명 게임의 NDCG 기준을 통과하지 못했다. 가설 — 인기 게임 쏠림을 줄이는 선형 모델(DAN 등)이 전체 성능과 비인기 게임 성능을 함께 높인다. 실험 — 145개 조건 비교, 사전에 고정한 DAN 1개를 4차 확인 평가 10,000명에서 확인. 판정 — DAN은 Recall@10 45.58%, NDCG@10 0.288이고, 대조군 활동량 보정 KNN은 Recall@10 40.51%, NDCG@10 0.251이다. 전체 점수는 높았지만 희귀 게임 NDCG가 0.038799로 대조군 0.045054보다 13.9% 낮아 **미채택**. 기존 활동량 보정 KNN을 유지했다. 근거 `EDA/reports/model_improvement_v4.md`, `EDA/reports/confirmation_v4.json`.
- **수치·근거:** 1차 9.5102%/6.7004%, 2차 40.9285%/10.8578%, 3차 14.5075%/9.6418%(내부 검증/100개 제한 평가셋 Recall@10). 4차 확인 평가는 DAN 45.58%, 활동량 보정 40.51%. 근거 `EDA/reports/model_improvement_v2.md`, `EDA/reports/model_improvement_v3.md`, `EDA/reports/model_improvement_v4.md`.
- **그림·표:** 개선 단계 요약표(단계·변경·내부 검증·100개 제한·판정). `EDA/figures/model_improvement_v3.png`(현재 모델 대비 선택 모델). 4차 후보 비교표(`EDA/reports/tables/model_improvement_v4.csv`). 각 단계의 문제·가설·실험·판정 4행 표.
- **흔한 실수:** v1·v2·v3·v4 파일명을 본문에 쓴다. 1차 내부 검증 9.51%와 3차 100개 제한 9.64%를 비교한다. 2차 개선을 "좋아졌다"고만 쓰고 100개 제한 평가셋 하락을 뺀다. 4차를 "실패"라고만 쓰고 전체 점수는 더 높았다는 사실과 희귀 게임 기준을 빠뜨린다. 145개 조건을 모두 나열해 본문을 실험 로그로 만든다.

### 3.8 최종 결과와 해석

- **내용:** 최종 모델은 활동량 보정 Item-KNN이다. 선택 이유를 세 문장으로 적는다. ① 내부 검증에서 사전 기준을 통과했다. ② 4차 DAN은 전체 점수가 높았지만 희귀 게임 NDCG가 낮아 교체하지 않았다. ③ 같은 설정을 유지한 채 100개 제한 평가셋과 대규모 평가셋에서 평가했고, 대규모 평가셋은 평가 계정을 학습에서 제외해 다시 학습했다. 평가 집단별 결과를 한 표에 모으되, 집단이 다른 값을 한 줄에서 비교하지 않는다. 마지막에 "이 점수가 실제 서비스 만족도나 구매 전환율이 아니다"를 밝힌다.
- **수치·근거:** 내부 검증 325,639명에서 Recall@10 40.93%, NDCG@10 0.252. 100개 제한 평가셋 24,342명에서 Recall@10 10.86%, NDCG@10 0.070. 대규모 평가셋 395,421명에서 Recall@10 29.49%, NDCG@10 0.17218이고, 같은 집단 인기순은 Recall@10 21.24%, NDCG@10 0.12993; 기본 Item-KNN은 Recall@10 29.05%, NDCG@10 0.17003; 확장 메타데이터 TF-IDF는 Recall@10 13.09%, NDCG@10 0.07338이다. 근거 `EDA/reports/model_improvement_v3.md`, `EDA/reports/forgemaster_model_evaluation.md`. 대규모 평가셋 자료의 100개 제한 영향: 같은 사용자·정답 5개 표본에서 기본 Item-KNN -1.34%p, 활동량 보정 -1.77%p, 평가 가능 사용자 5,969–6,130명. 근거 같은 보고서. 4차 확인 평가의 입력 1–2개 5,000명 39.66%. 근거 `EDA/reports/model_improvement_v4.md`. 정답 2개 내부 검증 217,720명: 1개 이상 58.83%, 2개 모두 17.05%. 근거 `EDA/reports/multi_target_hit_rates_v3.md`.
- **그림·표:** 최종 성능 표(평가 집단·사용자·모델·Recall@10·NDCG@10·비교). 대규모 평가셋 막대그래프(활동량 보정 29.49, 기본 29.05, 인기순 21.24, TF-IDF 13.09). 100개 제한 영향 그림 `EDA/figures/forgemaster_models/01_model_cap_effect.png`. 정답 2개·짧은 이력 보조 결과 표.
- **흔한 실수:** 내부 검증 40.93%와 대규모 29.49%를 "성능이 떨어졌다"고 비교한다. 29.49%를 "낮다"고만 쓰고 인기순 21.24%보다 8.25%p 높다는 사실을 뺀다. 최종 모델이 모든 지표에서 최고라고 쓴다. 실제로 대규모 평가셋의 게임별 평균 Recall은 활동량 보정 7.21%로 기본 7.46%보다 낮다. 이 사실을 한계에 쓴다.

### 3.9 한계와 향후 과제

- **내용:** 한계를 "데이터", "평가", "모델", "해석" 네 범주로 나눈다. 각 한계에 근거 수치와 영향을 붙인다. 점수는 긍정 리뷰만 사용하고, 부정 리뷰는 추천 제외와 일부 보조 평가에만 썼다는 점도 적는다. 향후 과제는 "무엇을 어떤 조건으로 다시 실험할지"까지 쓴다. "데이터가 부족했다" 같은 일반론은 쓰지 않는다.
- **수치·근거:** 무작위 숨김은 시간순 미래 예측이 아니다. 4차 개선의 시간 노출 진단에서 기존 무작위 검증 입력의 57.60%가 정답보다 나중에 작성됐다. 근거 `EDA/reports/model_improvement_v4.md`. 대규모 평가셋은 2021년 4월까지 자료이고, Linux 후보 6,630개 중 2,210개(33.33%)만 관측된다. 근거 `EDA/reports/forgemaster_eda.md`. 콘텐츠 특징은 평가 대상 게임의 공개 정보까지 사용하는 transductive 설정이다. 근거 `EDA/reports/model_improvement_v3.md`. 100개 제한은 평가 가능 사용자를 5,969–6,130명으로 줄인다(평균 98.47% 감소). 근거 `EDA/reports/forgemaster_eda.md`. 4차 확인 계정은 과거 모델 개발 과정의 학습에 쓰였으므로 프로젝트 전체에서 미사용된 최종 테스트가 아니다. 근거 `EDA/reports/model_improvement_v4.md`. 대규모 평가셋의 게임별 평균 Recall은 활동량 보정 7.21%, 기본 7.46%로 최종 모델이 더 낮다. 100개 제한 평가셋 14,819명의 정답 2개 평가에서는 기본 Item-KNN이 11.15%, 활동량 보정이 10.74%로 기본 모델이 근소하게 높다. 근거 `EDA/reports/forgemaster_model_evaluation.md`, `EDA/reports/multi_target_hit_rates_v3.md`. 시간 분할은 7명·1,536명 규모이고, 익명 리뷰와 호주 리뷰의 동일인 여부를 확인할 수 없다. 근거 `SM/ML3.ipynb`, `JY/Model_Experiments/README.md`.
- **그림·표:** 한계 표(한계·근거 수치·영향 범위·다음 실험). 향후 과제 표(과제·필요 데이터·평가 지표). "이 결과를 적용할 수 있는 범위" 상자.
- **흔한 실수:** 한계를 한 문단으로 뭉뚱그린다. "데이터를 더 모으면 해결된다"로 끝낸다. 시간 누수·100개 제한·transductive 설정 중 하나만 쓰고 나머지를 뺀다. 4차 확인 평가를 "완전히 새로운 최종 테스트"라고 쓴다. 대규모 평가셋의 게임별 평균 Recall 하락과 100개 제한 평가셋의 정답 2개 평가에서 기본 Item-KNN이 근소 우위였다는 사실을 숨긴다.

## 5. 용어 규칙

### 5.1 첫 사용 때 한 줄 정의
표준 ML 용어는 독자가 안다고 가정하지 않고, 첫 사용 때 한 줄로 정의한다.

| 용어 | 첫 사용 때 쓸 정의 |
|---|---|
| Recall@10 | 정답 게임을 추천 10개 안에서 찾은 사용자의 비율 |
| NDCG@10 | 정답을 더 높은 순위로 추천할수록 높은 점수(0~1) |
| TF-IDF | 게임 소개글·태그의 단어 빈도와 역문서 빈도로 만든 벡터 |
| Item-KNN | 함께 긍정 평가된 게임 관계로 점수를 내는 이웃 기반 협업 필터링 |
| K | 각 추천 후보가 참고하는 유사 게임 수 |
| 인기순 추천 | 학습 데이터에서 긍정 사용자가 많은 게임부터 추천하는 기준선 |
| 정답 게임 | 평가를 위해 입력에서 숨긴, 사용자가 긍정 평가한 Linux 게임 |
| 추천 후보 | 모델이 추천할 수 있는 Linux 게임 6,630개 |
| 평가 집단 | 정답을 숨긴 뒤 조건을 만족해 실제 평가에 포함된 사용자 |
| 게임당 리뷰 100개 제한 | 데이터 수집·추출에서 게임별로 남기는 리뷰 수를 100개로 줄인 조건 |
| transductive 설정 | 평가 대상 게임의 공개 정보까지 특징 생성에 사용하는 조건 |
| 매크로 평균 | 게임마다 지표를 계산한 뒤 게임에 같은 가중치를 준 평균 |

### 5.2 내부 약칭 금지
- 본문에 `v1`, `v2`, `v3`, `v4` 파일명을 쓰지 않는다. 개선 단계는 **1차~4차 개선**으로 쓴다. 데이터 정식 이름에 붙은 배포 버전(`Kieran Steam Reviews v2`, `Forgemaster Steam Reviews v1`)은 4절 표에서만 허용한다. 저장소 문서의 `v4 확인 평가`는 본문에서 `4차 확인 평가`로 쓴다.
- `split_v1`, `EXP-*`, `knn_k100_l0`, `metadata_alpha_0_5`, `dan_ease_lambda100_a200_b000_p300_raw`, `activity_inverse_degree_cosine_k100`, `binary_item_knn_k100` 같은 설정 ID를 본문에 쓰지 않는다.
- 브랜치 이름(`JS`, `SM`, `JY`, `EJ`)을 본문에 쓰지 않는다.
- 설정 ID가 꼭 필요하면 부록에 "본문 표기 ↔ 설정 ID" 대응표를 둔다.
- 모델 이름은 다음으로 통일한다: `기본 Item-KNN`, `활동량 보정 Item-KNN`, `소개글 TF-IDF`, `소개글·태그·장르 TF-IDF`, `확장 메타데이터 TF-IDF`, `인기순 추천`, `DAN`.
- EASE·DAN은 첫 사용 때 "선형 모델"로만 풀고, 수식과 설정은 부록으로 보낸다.

## 6. 수치 규칙

### 6.1 한 문장에 평가 집단을 붙인다
형식: **[평가 집단] + [조건] + [모델] + [지표] + [값]**.
- 나쁜 예: "Recall@10은 40.93%였다."
- 좋은 예: "내부 검증 325,639명에서 활동량 보정 Item-KNN의 Recall@10은 40.93%였다."
- 좋은 예: "대규모 평가셋 395,421명에서 같은 모델의 Recall@10은 29.49%였고, 인기순 추천은 21.24%였다."

### 6.2 평가 집단 이름과 크기
| 표기 | 사용자 수 | 용도 |
|---|---:|---|
| 내부 검증 | 325,639 | 모델 선택 |
| 100개 제한 평가셋 | 24,342 | 외부 평가, 게임당 최대 100개 |
| 대규모 평가셋 | 395,421 | 외부 평가, 게임당 제한 없음 |
| 4차 확인 평가 | 10,000 | 4차 후보 확인 |
| 4차 짧은 이력 | 5,000 | 입력 1–2개 보조 평가 |
| 100개 제한 영향 분석 | 5,969–6,130 | 같은 사용자·정답 비교(5개 표본) |

### 6.3 집단이 다른 값은 직접 비교하지 않는다
아래 조합은 비교 금지다. 필요하면 "집단이 달라 직접 비교하지 않는다"고 먼저 쓴다.

| 값 A | 값 B | 금지 이유 |
|---|---|---|
| 내부 검증 40.93% | 대규모 29.49% | 평가 집단·정답 분포·후보 관측률이 다르다 |
| 시간 분할 29.52%(1,536명) | 대규모 29.49%(395,421명) | 과제·집단·지표 정의가 다르다 |
| 100개 제한 10.86%(24,342명) | 제한 영향 8.22%(약 6,065명) | 데이터와 평가 집단이 다르다 |
| 4차 DAN 45.58%(10,000명) | 내부 검증 40.93%(325,639명) | 재학습·집단·정답이 다르다 |
| 내부 인기순 31.93% | 대규모 인기순 21.24% | 집단·정답 분포가 다르다 |

### 6.4 반올림과 단위
- Recall@10과 비율: 소수점 둘째 자리(`29.49%`).
- NDCG@10: 셋째 자리(`0.172`).
- 비율 차이: 둘째 자리와 `%p`(`8.25%p`). `%`와 `%p`를 섞지 않는다.
- 원자료의 넷째 자리 값(`40.9285%`)은 부록의 재현표에만 쓴다.
- 반올림한 값으로 다시 계산하지 않는다. `48.96 − 29.52 = 19.44%p`는 원자료 `0.4896 − 0.2952`로 계산한다.
- 같은 표 안에서는 자릿수를 통일한다. `40.93%`와 `40.9285%`를 한 표에 섞지 않는다.
- 이 가이드라인의 `수치·근거` 줄은 출처 값을 그대로 인용했다. 보고서 본문·표에서는 위 규칙으로 반올림한다.

### 6.5 시간 분할 결과와 보조 평가
- 시간 분할 결과는 **참고용**이라고 표 제목에 쓴다. 최종 모델 선택 근거로 쓰지 않는다.
- 정답 2개, 짧은 이력, 숨긴 부정 게임, 시간순 대조 평가는 **보조 평가**라고 표제에 쓴다. 주평가와 같은 표에서 순위를 매기지 않는다.
- 100개 제한 평가셋 24,342명의 10.86%와 100개 제한 영향 분석 약 6,065명의 8.22%를 같은 값처럼 쓰지 않는다.

## 7. 문체 규칙

### 7.1 기본 원칙
- 평서문 `~했다/~이다`로 쓴다. 실험 결과는 과거형, 데이터 사실은 현재형으로 통일한다.
- 한 문장에 한 가지 내용만 쓴다. 문장이 60자 안팎을 넘으면 나눌 수 있는지 본다.
- 결과를 먼저 쓰고 근거를 붙인다. "A는 B였다. 근거는 C다." 순서다.
- 주어를 생략하지 않는다. "평가했다"만 쓰지 말고 "두 모델을 같은 후보에서 평가했다"라고 쓴다.
- 과장·홍보성 표현을 쓰지 않는다. `획기적`, `압도적`, `완벽한`, `최적의`, `매우 뛰어난`을 금지한다.
- AI가 쓴 듯한 상투 표현을 쓰지 않는다. `~를 통해`, `다양한`, `효과적으로`, `중요한 역할을 한다`, `이를 통해 ~할 수 있었다`, `시사하는 바가 크다`, `결론적으로`를 반복하지 않는다.
- 같은 내용을 요약해 반복하지 않는다. 장 끝의 "정리"는 새 정보가 있을 때만 쓴다.
- 근거 없는 인과 표현을 쓰지 않는다. "~ 때문에 성능이 올랐다" 대신 "~ 조건에서 성능이 올랐다. 원인은 추가 실험이 필요하다"라고 쓴다.

### 7.2 나쁜 예와 좋은 예

| 나쁜 예 | 좋은 예 |
|---|---|
| 다양한 모델을 통해 효과적으로 성능을 개선할 수 있었다. | 활동량 보정 Item-KNN은 내부 검증 325,639명에서 Recall@10을 40.08%에서 40.93%로 올렸다. |
| 시간 분할은 데이터가 부족해 실패했지만, 계정 분할을 통해 획기적인 성과를 얻었다. | 시간 분할 2안은 평가 대상이 1,536명이었고 인기순 추천이 48.96%로 Item-KNN 29.52%보다 높았다. 최종 평가는 계정 분할로 바꿨다. |
| 최종 모델은 29.49%의 높은 성능을 보였다. | 대규모 평가셋 395,421명에서 활동량 보정 Item-KNN의 Recall@10은 29.49%였고, 같은 집단의 인기순 추천 21.24%보다 8.25%p 높았다. |

### 7.3 문단 구성
- 한 문단은 3~5문장. 첫 문장에 결론, 나머지에 근거와 조건을 쓴다.
- 표를 문단으로 다시 읽지 않는다. 표는 수치를, 문단은 해석을 맡는다.
- 장 첫머리에 "이 장에서 답할 질문"을 한 문장으로 쓴다. 장 끝에는 "다음 장으로 넘길 판단"을 한 문장으로 쓴다.
