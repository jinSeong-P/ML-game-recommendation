# v4 백로그 실행 절차

2026-11-08 추가 아이디어의 실행 기록이다. 기존 v1–v3와 Forgemaster 보고서는 보존한다. 대용량 파일은 `data/processed/modeling/experiments_v4/`에 저장한다.

## 이번 실험의 평가 분리

기존 Kieran 학습 계정 중 과거 평가 계정을 피한 계정을 새로 예약한다. 기초 모델 학습, 결합 모델 학습(`fusion_fit`), 설정 선택(`selection`), 선택 후 확인(`confirmation`)을 분리한다. 세 예약 집단의 모든 리뷰를 새 기초 모델 학습에서 뺀다. 기존 검증 계정을 다시 나눠 새 독립 테스트라고 부르지 않는다.

예약 계정의 리뷰는 과거 v1–v3 학습에 쓰였다. 따라서 **v4 재학습 이후의 계정 분리 확인**이며, 프로젝트 전체 개발 이력까지 완전히 독립인 최종 테스트는 아니다. Forgemaster 계정 전체를 확인할 로컬 원자료도 현재 없다. 이 자료와 겹치지 않는다는 주장도 하지 않는다.

주 평가는 정답을 숨긴 뒤 전체 입력 5개 이상·긍정 입력 1개 이상이다. 입력 1–2개, 3–4개 집단은 따로 보고한다. 길이별로 같은 수를 추출한 전체 표본 평균을 실제 사용자 평균으로 해석하지 않는다. 후보 6,630개, 양수 점수만 추천, 관측 게임 제외, 빈 추천 분모 유지는 같다.

## 실행 순서

1. 새 계정 명단과 실험 프로토콜을 고정하고 학습·평가 중복을 검사한다.
2. 현재 채택 Item-KNN과 콘텐츠 TF-IDF를 같은 조건에서 준비한다. 콘텐츠는 리뷰 라벨을 학습하지 않으므로 고정 공개 메타데이터 표현을 재사용한다.
3. 두 모델의 적중 교집합과 후보 포함률을 측정한다. 후보 50+50, 100+100, 학습 사용자 수 구간을 확보한 최대 200개를 비교한다(V4-4).
4. 고정 가산 비중, 기존 특징으로 학습한 비중, 추천 근거 특징을 더한 비중을 순서대로 비교한다(V4-3). 결합 학습 계정과 선택 계정을 분리한다.
5. EASE 대조군과 RLAE/RDLAE, DAN을 비교한다(V4-2/V4-1). 먼저 공식을 저자 구현 및 작은 행렬의 직접해와 대조한다. 분해 결과를 재사용하되 학습 분할이 다른 결과는 섞지 않는다.
6. 고정 인코더 비교와 KNN 관계 학습을 진행한다(V4-6/V4-5). 동결 인코더의 표현과 학습 선호에 정렬한 표현을 구분한다.
7. 전체 NDCG와 기존 보호 조건으로 선택한 후보만 고정한 뒤 확인 집단을 연다. 조건을 통과한 후보가 없으면 현 모델을 유지한다. 확인 결과를 보고 설정을 다시 고르지 않는다.

## 지표와 해석

- Recall@10은 숨긴 긍정 게임 1개가 추천 10개 안에 있는 사용자 비율이다. 추천 정확도·만족도·전환율이 아니다.
- 같은 사용자에서 모델 간 차이를 비교하고 신뢰구간을 계산한다. 게임별 평균은 게임 집합을 고정한 채 게임 안 사용자를 재표집한다.
- 후보 포함률은 재정렬 성능의 상한이다. 정답이 후보 밖에 있어도 분모에 남긴다.
- 커버리지·노출 집중·새로움·태그 다양성·평균 목록 길이는 정확도와 함께 보고한다. 역인기도 가중은 민감도 확인이며 IPS 추정치가 아니다.
- 시간순 평가, 신규 게임 평가, 부정 정답 숨김에는 별도 표본과 규칙이 필요하다. 기존 무작위 숨김 결과에 이런 의미를 덧붙이지 않는다.

## 자원과 재현

기본 Python은 `EDA/.venv/Scripts/python.exe`다. GPU 실험은 기존 환경을 바꾸지 않고 `EDA/data/processed/modeling/v4_gpu_env/`에 PyTorch CUDA를 설치했다. GPU 메모리를 쓰는 콘텐츠 작업과 큰 선형 분해는 동시에 실행하지 않도록 조정한다. 메모리와 디스크 한계, 중단·재시도, 미실행 항목은 결과 보고서에 남긴다.

## 진행 범위와 아직 남은 작업

이번 실행은 백로그의 선행 평가와 높은 우선순위 V4-4·3·2·1·5·6을 먼저 비교한다. 첫 단계 DAN은 처음부터 모든 조합을 곱하지 않는 백로그 원칙을 따른다. 구체적인 실행 설정과 실제 완료 여부는 모델별 receipt 및 결과 표를 기준으로 기록한다. 구현된 설정 목록은 실행 완료 목록과 다르다.

후보 생성·조건부 결합·고정 Qwen·KNN 관계 학습·선형 모델·fSLIM·계정 기여량 조절의 예정 **145개 조건**을 모두 평가하고 저장 추천 목록을 검사했다. 시간순 대조군도 재학습·평가와 추천 목록 검사를 마쳤다. [시간순 보조 결과](../reports/temporal_controls_v4.md). 주평가 설정을 고정한 뒤 [정답 시드 반복·숨긴 부정 게임](../reports/supplemental_evaluation_v4.md)을 계산하고, 고정한 한 후보만 확인용 집단에서 비교했다.

V4-7·11은 후보 생성 이후의 다음 학습 단계로 남겼다. V4-9는 원본 리뷰를 다시 읽고 큰 텍스트 학습을 해야 하며, V4-12는 원문 근거 추출과 별도 생성 모델 대조군이 필요한 마지막 단계다. 신규 게임 성능은 해당 게임의 학습 상호작용을 제거하고 교사와 통계를 재학습하기 전에는 주장하지 않는다. 기존 저지원 게임 결과를 신규 게임 결과로 바꿔 부르지 않는다. 모든 백로그를 완료했다는 뜻은 아니다.

## 첫 단계 실행 범위의 확장 기록

처음 정한 실행 일정은 97개 조건이다. [원본 일정](../data/reference/primary_execution_plan_v4_initial.json)을 보존했다. 선택용 결과 69개를 확인한 뒤, CPU와 GPU의 전체 EASE 계수 비교가 통과해 이미 백로그에 있던 DAN의 α=.1/.3과 RDLAE의 λ=1000도 이번 단계에서 계산하기로 했다. [확장 일정](../data/reference/primary_execution_plan_v4.json)은 123개 조건이다. 매개변수의 출발 범위와 성능 저하를 막는 조건은 바꾸지 않았다. 확장 시점에 확인용 결과는 열지 않았다. 부분 결과를 본 뒤 일정을 넓힌 사실을 선택 불확실성의 한계로 남긴다.

GPU 검증에서는 TF32를 끄고, 전체 37,610개 게임 행렬을 분해해 후보 6,630개의 계수를 계산했다. CPU 대비 상대 Frobenius 오차는 약 0.000173%, 표본 역행렬 방정식의 상대 잔차는 사전 허용치 아래였다. 분해와 후보 해 계산은 9.54초, 최대 GPU 할당은 약 5.70GB였다. 이는 계산 장치의 검증이며 추천 성능 개선 실험 한 개로 세지 않는다. 원자료로 가중 Gram을 만드는 시간과 파일 검사·저장 시간은 이 9.54초에 포함되지 않는다. [검증 수치](../reports/linear_gpu_validation_v4.json)

이어 79개 조건의 추천 목록 검사를 마친 시점에 V4-8도 일정에 넣었다. 원본 학습의 공동 리뷰 행렬에서 같은 이웃과 회귀 통계를 정확히 가져올 수 있어, 원본 7,788만 쌍을 다시 곱하는 비용을 줄였다. fSLIM 12개와 같은 이웃의 코사인 대조군 2개를 더해 예정 조건은 **137개**다. 컴파일된 좌표 하강법의 결과를 작은 자료의 독립적인 비음수 최소제곱·제약 최적화 해와 대조했으며, 실제 학습에서는 수렴 상태와 KKT 잔차를 함께 기록한다. 이 확장 때 fSLIM 추천 결과와 확인용 결과는 보지 않았다.

94개 조건을 점검한 뒤 V4-10의 8개 조건도 일정에 넣어 예정 조건은 **145개**다. 활동량 역수와 공동 리뷰 쌍 수 보정의 두 통계를 선형 결합해 네 ρ를 비교하고, 이웃 고정·재선택을 구분한다. ρ=0이 새 활동량 보정 KNN의 이웃과 계수를 재현해야 모델을 저장하도록 했다. 이때 V4-10 추천 결과와 확인용 결과는 보지 않았다.

## 계산 변경과 재실행

가중 Gram의 첫 시도에서는 오른쪽 희소행렬을 CSC에서 CSR로 매 블록마다 바꾸는 비용이 컸다. β=.5 계산을 4,848행 로그 뒤 중단하고, 검증 영수증이 없는 부분 파일을 다시 만들었다. 이후에는 같은 변환을 한 번만 수행한다. 작은 행렬에서 기존 곱셈과 원소 단위로 일치하는지 검사했으며, 전체 학습 자료의 완전한 행 일부도 별도로 검증한다. 설정이나 학습 자료를 줄여 빠르게 만든 실험이 아니다. 중단 로그는 대용량 산출물 폴더에 보존했다.

전체 학습 자료를 사용한 두 β의 완전한 게임 행 5개씩, 총 376,100개 원소를 기존 곱셈과 다시 계산해 **모두 정확히 일치**함을 확인했다. 모든 행을 독립적으로 재계산한 검증은 아니며, 추천 실험의 반복으로 세지 않는다. 이 행렬을 참조한 DAN 32개 모델의 학습 기록도 확인했다. [검증 근거](../reports/weighted_gram_validation_v4.json)

다음은 v4 분할·대조군·후보·콘텐츠 비교를 준비한 뒤 남은 실험을 이어가는 명령이다. 저장소 루트의 PowerShell로 실행한다. 해시가 맞는 완료 모델은 재사용한다. GPU는 별도 Python 환경을 사용한다.

```powershell
& EDA/data/processed/modeling/v4_gpu_env/Scripts/python.exe EDA/scripts/run_pending_linear_v4.py
& EDA/.venv/Scripts/python.exe EDA/scripts/build_fslim_from_gram_v4.py
& EDA/.venv/Scripts/python.exe EDA/scripts/build_pair_contribution_v4.py
& EDA/.venv/Scripts/python.exe EDA/scripts/verify_weighted_grams_v4.py
$v4Names = (Get-Content EDA/data/reference/primary_execution_plan_v4.json -Raw | ConvertFrom-Json).required_evaluations
& EDA/.venv/Scripts/python.exe EDA/scripts/evaluate_models_v4.py --names $v4Names
& EDA/.venv/Scripts/python.exe EDA/scripts/audit_experiments_v4.py
& EDA/.venv/Scripts/python.exe EDA/scripts/summarize_experiments_v4.py
```

설정 고정은 `summarize_experiments_v4.py --freeze`로 한 번만 수행한다. 예정 조건과 실제 추천 목록 검사가 빠져 있으면 거절하며, 이미 고정한 기록도 덮어쓰지 않는다. 고정 뒤 `evaluate_supplemental_v4.py --run`으로 시드 반복·숨긴 부정 게임을 보고하고, `evaluate_confirmation_v4.py`는 고정한 한 후보와 대조군만 확인한다. 확인용 결과에 따라 설정을 다시 고르지 않는다. 보조 결과도 설정 선택에 되돌려 쓰지 않는다.

시간순 대조군은 `run_temporal_models_v4.py --stage train`, `--stage evaluate`, `summarize_temporal_controls_v4.py` 순서로 실행한다. 이 경로는 무작위 숨김 모델·사용자·확인용 파일과 분리돼 있다.

## 첫 단계의 최종 판정

2026-11-08 12:29:37 UTC에 설정을 고정한 뒤 보고용 보조 평가를 수행하고, 확인용 계정을 열었다. 선택용과 확인용 주평가는 각각 10,000명이며, 짧은 이력 집단은 따로 기록했다. [고정 기록](../data/reference/improvement_selection_v4.json)과 [확인 결과](../reports/confirmation_v4.json)는 보존한다.

확인용에서 DAN은 전체 Recall을 **40.51% → 45.58%**, NDCG를 **0.250669 → 0.288294**로 높였다. 같은 사용자의 NDCG 차이 95% 구간은 **[0.034172, 0.040906]**다. 게임별 평균 NDCG도 높아졌지만, 희귀 게임 NDCG는 **0.045054 → 0.038799**로 낮아져 기존 KNN을 유지한다. 이 구간은 322명·291개 게임이며 적중 사용자는 두 모델 모두 22명이다. 작은 구간의 순위 점수 차이이며 실제 서비스에서 같은 감소폭이 발생한다는 증거로 해석하지 않는다.
