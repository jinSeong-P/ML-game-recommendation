# 평가 정답을 숨기는 방법 비교

기본 평가 방식은 사용자마다 조건을 만족하는 긍정 Linux 게임 1개를 같은 확률로 무작위 선택해 한 번 숨기고, 난수 seed와 저장한 정답 목록을 바탕으로 평가하는 방법이다. 2026-11-07 다음 조건도 확정했다. 정답을 숨긴 뒤 전체 입력 게임은 5개 이상이고 긍정 입력 게임은 1개 이상이어야 한다. 긍정 입력은 같은 비중으로 집계하며, 개인화 점수가 양수인 게임만 추천하고 남는 자리는 비워 둔다. 실제 분할 파일, 파일 목록·검증 정보(manifest), 입력 이력(`query`)을 생성하고 저장 파일을 확인했다. 난수 시드는 **20261107**이다. 2026-11-08 두 모델의 공통 내부 검증과 frank 테스트도 완료했다. [베이스라인 결과](../reports/baseline_v1.md)에 실제 성능과 지원 진단을 기록했다. [분할 파일 안내](modeling_splits.md)에 실제 규모와 검증 결과가 있다.

기본 평가는 사용자마다 정답 1개를 숨긴다.

## 공통 원칙

- 정답은 알려진 모호 리뷰 연결을 정리한 frank의 **공식 Linux 게임에 대한 긍정 리뷰**에서 고른다. 비Linux 긍정 게임도 남은 이력 입력으로 사용할 수 있다.
- 정답 게임은 입력 이력과 추천 제외 목록에서 빼 추천 후보로 남긴다. 정답 외에 관측된 적격 이력은 모두 입력 이력(`query`)에 남긴다. 남은 긍정 리뷰만 취향 점수에 쓰고, 남은 긍정·부정 게임은 모두 재추천 제외 목록에 넣는다. 게임 소개글과 후보 카탈로그는 모델끼리 공유할 수 있다.
- frank의 예약 테스트 계정 87,573명은 선택 방법과 무관하게 Kieran 학습·검증에서 계속 제외한다. 게임별 인기도와 Item-KNN 이웃은 학습에서만 계산한다.
- 두 모델에 같은 사용자·정답·입력 이력·후보를 준다. 파일 목록·검증 정보(manifest)에 seed와 사용자별 정답을 저장하고, 테스트 점수를 보고 유리한 설정을 고르지 않는다.
- 확정한 최소 조건은 정답 숨김 후 **긍정·부정 전체 리뷰 게임 ≥5, 긍정 리뷰 게임 ≥1**이다. 긍정 입력이 5개 이상이라는 뜻은 아니다.
- 정답을 숨긴 뒤 남은 적격 이력은 전부 사용한다. 입력 개수를 줄이는 별도 제한은 두지 않는다.
- 정답을 숨긴 뒤 긍정 입력이 하나도 남지 않는 사용자(전체 입력 ≥5인 잠재 후보 중 229명)는 두 모델의 기본 평가에서 함께 제외한다. 이들 계정도 기존 테스트 예약 범위에 두고 학습·검증에 되돌리지 않는다.
- 긍정 입력은 동일 가중 평균으로 집계한다. TF-IDF는 게임별 L2 정규화 벡터를 평균한 뒤 후보와 코사인을 계산하고, Item-KNN은 유사도 합을 전체 긍정 입력 수로 나눈다. 이웃 연결이 없는 기여는 0이다.
- 개인화 점수가 양수인 후보를 최대 10개 추천하고 부족한 자리는 비운다. 조건을 만족하는 사용자에게 추천 목록이 없어도 평가 분모에 남기며, 정답을 찾지 못한 사용자의 Recall@10·NDCG@10은 0이다. 인기도순·무작위로 목록을 채우지 않는다.

## 방법

| 방법 | 정답과 입력 구성 | 확인하는 것 | 상태와 한계 |
|---|---|---|---|
| 무작위 1개 고정 | 사용자별 조건을 만족하는 긍정 Linux 게임 중 1개를 같은 확률로 무작위 선택하고, seed와 결과 명단을 저장. 나머지 적격 이력은 모두 입력 이력(`query`)에 남김 | 이미 알고 있는 취향으로 다른 선호 게임을 찾는 사용자 평가 | **기본 방식으로 선택됨.** 정답 1개를 무작위로 선택하므로 결과가 달라질 수 있고 시간순 미래 예측은 아님. seed 20261107, 정답 목록과 입력 이력 생성·검증 완료. 모델 평가는 설계 당시 미완료였으며 이후 [v1에서 완료](../reports/baseline_v1.md) |
| 최근 긍정 Linux 게임 1개 | 가장 최근에 작성한 조건에 맞는 긍정 Linux 리뷰를 정답으로 고르고 그보다 일찍 작성된 리뷰만 입력으로 사용 | 과거 이력으로 이후 선호를 찾는 상황에 가까운 평가 | 참고 대안. 이후 입력을 막으면 사용 가능한 이력이 줄어 조건을 만족하는 사용자 수를 다시 계산해야 한다. 학습 리뷰 전체·라벨 갱신·메타데이터 시점까지 맞추지 않으면 완전한 과거 시점 예측이라고 할 수 없음 |
| 여러 개 동시 숨김 | 조건에 맞는 긍정 Linux 게임 중 정해진 개수 또는 비율을 숨기고, 나머지 리뷰를 입력으로 사용 | 여러 선호 게임을 한 번에 찾는 성능 | 설계 당시의 대안. 이후 [v3](../reports/model_improvement_v3.md)에서 정답 2개와 별도 입력 조건으로 평가했다. 정답 수에 따라 입력과 평가 사용자 구성이 달라짐 |
| 1개씩 반복 숨김 | 사용자마다 미리 정한 여러 정답 선택 중 하나씩 숨기거나, 조건에 맞는 모든 정답을 돌아가며 평가한다. 각 회차에는 그 회차의 정답만 입력에서 뺀다 | 한 번 무작위 선택했을 때 결과가 얼마나 달라지는지, 사용자별 여러 정답을 얼마나 찾는지 확인 | 참고 대안. 별도 백로그 일정은 없다. 반복 결과는 서로 독립된 사용자 표본이 아니므로 사용자별 평균을 구한 뒤 전체 평균을 내고, 신뢰구간도 사용자 단위로 계산 |

기본 방식에서는 긍정 입력이 없는 사용자를 두 모델에서 함께 제외한다. 긍정 입력이 있더라도 특정 모델이 충분히 활용하지 못하는 사용자나 정답을 임의로 빼지 않는다. 추천 목록이 비어도 평가에 포함한다.

## 같은 가상 이력으로 보는 예시

게임 1~6을 모두 긍정 Linux 리뷰라고 가정한다. 게임 1→6 순으로 리뷰를 작성했다. 이 예시는 정답 숨김 방식만 보여주며 실제 데이터 규모나 최소 입력 조건을 만족한다는 뜻은 아니다. 부정 리뷰한 게임도 추천에서 제외하지만, 아래 취향 입력 표에는 표시하지 않는다.

| 방법 | 긍정 취향 입력 | 평가 정답 |
|---|---|---|
| 무작위 1개 | 1·2·4·5·6 | 3 |
| 가장 최근 1개 | 1·2·3·4·5 | 6 |
| 무작위 2개 동시 | 1·2·4·6 | 3·5 |
| 1개씩 반복 | 회차 1: 1·2·4·5·6 / 회차 2: 1·2·3·4·6 | 회차 1: 3 / 회차 2: 5 |

## EDA 수치와 지표 해석

현재 정리한 EDA 자료에서 전체 입력 ≥5인 사용자는 **24,571명**이다. 확정 조건인 정답을 숨긴 뒤 전체 입력 ≥5·긍정 입력 ≥1을 만족하는 사용자는 **24,342명**이다. 긍정 입력이 남지 않는 229명은 두 모델의 기본 평가에서 함께 제외한다. 이 수치는 처음에는 잠재 규모였으며, seed **20261107**로 같은 24,342명의 실제 입력과 정답 명단을 만들어 검증했다. 최근 리뷰만 입력에 남기는 방식, 여러 정답 동시 숨김, 긍정 입력 최소 5개 등 다른 조건에는 이 수치를 그대로 적용할 수 없다.

정답이 1개면 Recall@10은 추천 상위 10개에서 정답을 찾은 사용자 비율이며 Hit Rate@10과 같다. NDCG@10은 정답이 몇 번째로 추천됐는지를 반영한다. 여러 정답을 숨기면 Recall@10은 사용자별 숨긴 정답 가운데 찾은 비율이며, 숨긴 정답 개수에 따라 도달 가능한 최대 Recall도 달라진다. 정답 개수나 입력 조건이 다른 평가의 지표를 모델 성능 차이로 바로 비교하지 않는다.

기본 숨김 방식은 **사용자마다 같은 확률로 게임 1개를 무작위 선택하고 seed와 저장된 정답 명단을 고정하는 것**이다. 여러 정답을 한 번에 숨기는 방식은 이후 v3에서 별도 조건으로 평가했다. 시간순으로 정답 1개를 고르는 방식과 정답을 바꿔가며 반복하는 방식은 참고 대안으로 남겼다. **전체 입력 ≥3·긍정 입력 ≥1** 조건(EDA 잠재 38,549명), 플레이타임 가중 집계, 모델 개선 후 인기도순 빈자리 보완의 이후 실행 상태는 [실험 기록](modeling_backlog.md)에서 확인할 수 있다.
