# 평가 정답을 숨기는 방법 비교

기본 평가 프로토콜은 **사용자별 적격 긍정 Linux 게임 하나를 균등 무작위로 고르고, 고정 seed와 저장된 정답 manifest로 평가하는 방법**으로 선택했다. 2026-11-07 추가 확정한 조건은 **숨김 후 전체 입력 ≥5·긍정 입력 ≥1, 긍정 입력의 동일 가중 평균, 개인화 점수만 사용·부족한 추천 자리 비움**이다. 실제 분할·manifest·query 파일 생성과 저장 파일 검증을 완료했으며 seed는 **20261107**이다. 2026-11-08 두 모델의 공통 내부 검증·frank 테스트도 완료했다. [베이스라인 결과](../reports/baseline_v1.md)에 실제 성능과 지원 진단을 기록했다. [분할 파일 안내](modeling_splits.md)에 실제 규모와 검증 결과를 기록했다.

## 공통 원칙

- 정답은 알려진 모호 리뷰 연결을 정리한 frank의 **공식 Linux 게임에 대한 긍정 리뷰**에서 고른다. 비Linux 긍정 게임도 남은 이력 입력으로 사용할 수 있다.
- 정답 게임은 사용자 취향 입력과 추천 제외 마스크에서 제거해 추천 후보로 남긴다. 정답 외에 관측된 적격 이력은 모두 query에 남긴다. 남은 긍정 리뷰만 취향 점수에 쓰고, 남은 긍정·부정 리뷰의 게임은 재추천 제외 마스크에 쓴다. 게임 소개글과 후보 카탈로그는 공유할 수 있다.
- frank의 예약 테스트 계정 87,573명은 선택 방법과 무관하게 Kieran 학습·검증에서 계속 제외한다. 게임별 인기도와 Item-KNN 이웃은 학습에서만 계산한다.
- 두 모델에 같은 사용자·같은 정답·같은 입력·같은 후보를 준다. manifest에 seed와 사용자별 정답을 저장하고, 테스트 점수를 보고 유리한 선택을 고르지 않는다.
- 확정한 최소 조건은 정답 숨김 후 **긍정·부정 전체 리뷰 게임 ≥5, 긍정 리뷰 게임 ≥1**이다. 긍정 입력이 5개 이상이라는 뜻은 아니다.
- 정답을 숨긴 뒤 남은 적격 이력은 모두 사용한다. 입력 개수를 줄이는 별도 제한은 두지 않는다.
- 정답을 숨긴 뒤 긍정 입력이 하나도 남지 않는 사용자(전체 입력 ≥5 잠재 후보 중 229명)는 두 모델의 기본 평가에서 공통 제외한다. 이들 계정도 기존 테스트 예약 범위에 남겨 학습·검증에 되돌리지 않는다.
- 긍정 입력은 동일 가중 평균으로 집계한다. TF-IDF는 게임별 L2 정규화 벡터를 평균한 뒤 후보와 코사인을 계산하고, Item-KNN은 유사도 합을 전체 긍정 입력 수로 나눈다. 이웃 연결이 없는 기여는 0이다.
- 양수 개인화 점수 후보를 최대 10개 추천하고 부족한 자리는 비운다. 적격 사용자에게 빈 목록이 나와도 지표 분모에 유지하며 정답 미회수의 Recall@10·NDCG@10은 0이다. 인기순·무작위 보완은 적용하지 않는다.

## 방법

| 방법 | 정답과 입력 구성 | 확인하는 것 | 상태와 한계 |
|---|---|---|---|
| 무작위 1개 고정 | 사용자별 적격 긍정 Linux 게임 중 1개를 균등 무작위로 고르고 seed와 결과 명단을 저장. 나머지 적격 이력은 모두 query에 남김 | 알려진 취향으로 다른 선호 게임을 찾는 신규 사용자 평가 | **기본 프로토콜로 선택됨.** 1회 선택의 변동이 있으며 시간순 미래 예측은 아님. seed 20261107·실제 manifest·query 생성과 검증 완료, 모델 평가는 미완료 |
| 최근 긍정 Linux 게임 1개 | 가장 최근 작성된 적격 긍정 Linux 리뷰를 정답으로 고르고 그보다 이른 리뷰만 입력으로 사용 | 과거 이력으로 이후 선호를 찾는 순서에 가까운 평가 | 참고 대안. 미래 입력 차단으로 이력이 줄어 적격 사용자 수 재집계 필요. 전역 학습 리뷰·라벨 갱신·메타데이터 시점까지 맞추지 않으면 완전한 과거 시점 예측을 주장할 수 없음 |
| 여러 개 동시 숨김 | 적격 긍정 Linux 게임 중 고정 개수 또는 고정 비율을 숨기고 나머지 리뷰를 입력으로 사용 | 여러 선호 게임을 동시에 회수하는 성능 | **향후 백로그 실험.** 정답 개수 또는 비율은 나중에 정한다. 정답 수에 따라 입력과 사용자별 난도가 달라져 EDA 재집계가 필요 |
| 1개씩 반복 숨김 | 사용자마다 미리 정한 여러 정답 선택으로 1개씩 따로 숨기거나 모든 적격 정답에 대해 번갈아 평가. 각 회차에는 그 회차의 정답만 입력에서 제외 | 한 번의 무작위 선택에 대한 민감도와 사용자별 여러 목표에서의 성능 | 참고 대안. 별도 백로그 일정은 없다. 반복 결과는 독립 사용자 표본이 아니므로 사용자별 평균 후 전체 평균을 내고 신뢰구간도 사용자 단위로 계산 |

기본 프로토콜은 긍정 입력이 없는 사용자를 공통 제외한다. 긍정 입력이 있어도 특정 모델의 지원이 부족한 사용자·정답은 임의로 제거하지 않고, 빈 목록을 포함해 평가한다.

## 같은 가상 이력으로 보는 예시

게임 1~6을 모두 긍정 Linux 리뷰라고 가정한다. 게임 1→6 순으로 작성했다. 이 예시는 숨김 방식만 보여주며 실제 데이터 규모나 입력 최소 수를 충족한다는 뜻은 아니다. 부정 리뷰 게임 자체는 재추천 제외에만 쓰고 아래 취향 입력 표시에서는 생략한다.

| 방법 | 긍정 취향 입력 | 평가 정답 |
|---|---|---|
| 무작위 1개 | 1·2·4·5·6 | 3 |
| 가장 최근 1개 | 1·2·3·4·5 | 6 |
| 무작위 2개 동시 | 1·2·4·6 | 3·5 |
| 1개씩 반복 | 회차 1: 1·2·4·5·6 / 회차 2: 1·2·3·4·6 | 회차 1: 3 / 회차 2: 5 |

## EDA 수치와 지표 해석

현재 정리된 EDA의 전체 입력 ≥5 후보는 **24,571명**, 확정 조건인 정답 숨김 후 전체 입력 ≥5·긍정 입력 ≥1 후보는 **24,342명**이다. 긍정 입력이 남지 않는 229명은 기본 평가에서 공통 제외한다. 당시에는 잠재 규모였으며, 현재 seed **20261107**로 같은 24,342명의 실제 입력·정답 명단을 생성·검증했다. 최근 시점 제한·여러 정답 동시 숨김·긍정 입력 최소 5개 같은 조건에는 이 수치를 그대로 적용할 수 없다.

정답이 1개면 Recall@10은 Hit Rate@10과 같고 NDCG@10은 정답의 순위를 반영한다. 여러 정답을 숨기면 Recall@10은 사용자별 정답 중 찾은 비율이며 정답 개수에 따라 최대 달성 가능한 Recall도 달라진다. 서로 다른 정답 수·입력 조건에서 나온 지표를 모델 성능 차이로 바로 비교하지 않는다.

기본 숨김 방식은 **사용자별 균등 무작위 1개 + 고정 seed·저장 manifest**다. 여러 정답 동시 숨김은 향후 백로그 실험이며, 시간순 1개와 반복 1개 숨김은 참고 대안이다. 추가로 **전체 입력 ≥3·긍정 입력 ≥1** 조건(EDA 잠재 38,549명), 플레이타임 등 가중 집계, 모델 개선 후 인기순 빈자리 보완을 [백로그](modeling_backlog.md)에 남겼다.
