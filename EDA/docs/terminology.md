# 용어와 문장 작성 기준

머신러닝 기초를 아는 동료가 이 프로젝트를 처음 읽어도 평가 대상과 결과를 이해할 수 있도록 씁니다. TF-IDF, 코사인 유사도, Recall, NDCG처럼 널리 쓰이는 기술 용어는 유지하고, 프로젝트에서 정한 구체적인 의미를 설명합니다.

## 용어의 의미

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| 입력 이력 (`query`) | 정답 게임을 숨긴 뒤 사용자에게 남은 리뷰. 점수에는 긍정 리뷰를 쓰고, 추천 제외에는 긍정·부정 리뷰를 모두 씁니다. |
| 정답 게임 (`target`, holdout item) | 사용자가 긍정 평가한 Linux 게임 중 평가를 위해 숨긴 게임입니다. |
| 추천 후보 | 모델이 추천할 수 있는 게임 목록입니다. 현재 고정 목록에서 Linux 게임 6,630개를 사용합니다. |
| 추천 제외 목록 (`mask`, exclusions) | 이미 리뷰한 게임을 다시 추천하지 않기 위한 목록입니다. 숨긴 정답 게임은 이 목록에서 뺍니다. |
| 학습 사용자 수 (`support`) | 해당 게임을 긍정 평가한 학습 사용자 수입니다. 소프트웨어의 OS 지원 여부와 구분합니다. |
| 모델이 활용할 수 있는 게임 | TF-IDF에서는 유효한 설명 벡터가 있는지, Item-KNN에서는 저장된 이웃과 연결되는지 등을 뜻합니다. 과거 문서의 ‘지원 상태’는 이 기준을 가리키기도 하므로 해당 표의 정의를 확인합니다. |
| 게임별 평균 지표 (macro average) | 게임마다 지표를 계산한 뒤 게임에 같은 가중치를 주어 평균합니다. 전체 사용자 평균과 다를 수 있습니다. |
| 평가 대상 사용자 (`cohort`) | 명시한 조건을 만족해 실제 평가에 포함된 사용자들입니다. |
| 추가 확인 지표 | 주 지표가 좋아져도 특정 게임이나 사용자 집단의 성능이 나빠지는지 확인하는 지표입니다. 문서에서는 대상 지표를 구체적으로 적습니다. |
| 기존 데이터 재평가 (참조 평가) | 개발 중 이미 확인한 데이터로 다시 평가한 결과입니다. 새 독립 테스트와 구분합니다. |
| 실험 설정 기록 (`protocol`) | 성능을 계산하기 전에 정한 모델, 데이터 분할, 평가 방법과 모델 선택 기준입니다. |
| 파일 목록·검증 정보 (`manifest`) | 파일 경로, 행 수, 크기, 해시값과 처리 상태를 기록한 파일입니다. 파일마다 들어 있는 항목은 다를 수 있습니다. |
| 해시값 (`SHA256`) | 파일 내용이 바뀌었는지 확인하기 위한 값입니다. |
| 평가용 계정 사전 분리 | 최종 평가에 들어갈 가능성이 있는 계정의 모든 리뷰를 학습에서 미리 제외하는 절차입니다. |
| 충돌 리뷰 제외 | 같은 리뷰 ID가 서로 다른 게임에 연결되는 등 신뢰하기 어려운 행을 분석·학습에서 제외하는 처리입니다. |
| 민감도 분석 | 리뷰 수 제한처럼 한 조건을 바꿨을 때 결과가 얼마나 달라지는지 확인하는 분석입니다. |
| 짝지은 비교 (paired comparison) | 같은 사용자와 같은 정답을 유지한 채 두 조건의 결과를 비교합니다. |
| 부트스트랩 신뢰구간 | 사용자를 복원 추출해 점수 차이를 반복 계산한 뒤 얻는 불확실성 구간입니다. 이 프로젝트의 짝지은 비교는 같은 사용자의 두 결과를 함께 추출합니다. |
| 난수 시드 (`seed`) | 같은 무작위 표본을 다시 만들기 위한 초기값입니다. |
| 단일 리뷰 사용자 (`singleton`) | 분석 범위에서 리뷰가 한 개뿐인 사용자입니다. 긍정 학습 행을 다룰 때는 긍정 리뷰가 한 개뿐인 사용자를 뜻합니다. |

## 과거 문서의 데이터 A·B·C

이 이름은 초기 분석에서 쓰던 데이터셋 약칭입니다. 현재 Kieran 학습·Forgemaster 평가와 구분해서 읽습니다.

| 약칭 | 데이터셋과 용도 |
|---|---|
| A | `Game Recommendations on Steam`. 초기 리뷰 분석에 사용했으며, 현재는 공통 게임 목록과 게임 소개글의 출처입니다. |
| B | `Australian users/items/reviews`. 초기 외부 평가 자료입니다. 현재의 frank 데이터와 다릅니다. |
| C | `Steam Games 2025`. 게임 설명과 메타데이터를 보충하는 자료입니다. |

## 혼동하기 쉬운 두 가지 100개 제한

**게임당 리뷰 100개 제한**은 데이터 수집·추출 과정에서 게임별로 남기는 리뷰 수를 제한합니다. 사용자의 관측 이력과 평가 가능한 사용자 구성이 달라집니다.

**Item-KNN의 K=100**은 각 추천 후보에 대해 유사한 입력 게임을 최대 100개 저장하는 모델 설정입니다. 게임당 리뷰 수 제한과 별개의 값입니다.

## 문장 작성 방법

대상과 행동을 먼저 적습니다. 예를 들어 ‘잠금 후 참조를 재사용한다’는 문장 대신 ‘내부 검증으로 모델을 선택한 뒤 설정을 고정하고, 같은 모델을 frank 데이터로 다시 평가한다’고 씁니다.

| 기존 표현 | 더 구체적인 표현 |
|---|---|
| 낮은 지원 보호 구간 | 긍정 학습 사용자가 1–999명인 게임의 평가 결과 |
| 선택 잠금·동결 | 모델을 선택한 뒤 설정과 파일 해시값을 기록하고 변경하지 않음 |
| 학습안 | 실제 파일이면 ‘학습 데이터’, 설계 중이면 ‘학습 데이터 구성 계획’ |
| 미지원 후보 | 학습 리뷰가 없는 후보인지, 유효한 설명 벡터가 없는 후보인지 명시 |
| 격리 복구 | 제외했던 리뷰를 다시 사용하는 조건 검토 |
| 전수 감사 | 전체 행 검사, 전체 추천 결과 검사 등 검사 대상을 명시 |
| 빈 슬롯 유지 | 추천할 게임이 10개보다 적으면 남은 자리를 채우지 않음 |

숫자에는 평가 집단과 조건을 붙입니다. ‘Recall 29.49%’보다 ‘100개 제한 없는 Forgemaster 평가 395,421명에서 Recall@10 29.49%’가 명확합니다. `%`는 비율, `%p`는 비율의 차이에 사용합니다.

과거 보고서는 작성 당시의 결과임을 밝힙니다. 데이터나 모델을 새로 평가했을 때는 이전 결과를 덮어쓰기보다 새 조건과 결과를 구분합니다. ‘전체 이력’은 데이터셋에서 관측한 이력 전체를 뜻하며, 사용자의 모든 Steam 활동을 수집했다는 뜻은 아닙니다.

파일 경로, 함수명, JSON 키와 CSV 열 이름은 실행 코드와 맞춰 유지합니다. 본문에서는 쉬운 설명을 사용하고 필요한 경우 정확한 식별자를 괄호나 코드 표기로 덧붙입니다.
