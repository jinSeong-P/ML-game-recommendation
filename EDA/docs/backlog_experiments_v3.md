RP3β는 사용자와 게임이 서로 연결된 그래프에서 경로를 따라 계산한 점수에 게임 인기도 감점을 적용하는 협업 필터링 방법이다. 표준 RP3β가 사용하는 사용자→게임→사용자→게임 경로는 게임끼리 직접 연결하는 경로와 다르다. 두 게임을 함께 긍정 평가한 학습 사용자가 없으면 이 방법만으로 해당 게임 쌍 사이에 직접 연결이 생기지는 않는다. 따라서 정답에 양수 점수를 매긴 사용자 수와 실제 추천 적중을 각각 측정한다.

EASE는 게임 간 관계를 선형 회귀로 한 번에 학습하는 모델이다. iALS(implicit alternating least squares)는 실제로 관측한 선호와 미관측 항목의 낮은 신뢰도를 함께 다루는 잠재요인 모델이다. EASE는 전체 37,610개 게임을 대상으로 해를 구한다. 계산량을 줄이기 위해 게임 수를 줄인 결과는 전체 EASE로 기록하지 않는다. iALS에서는 학습한 게임 벡터를 고정한 채 평가 사용자의 보이는 입력만으로 사용자 벡터를 계산한다. 이 과정을 **fold-in(기존 게임 벡터를 고정한 상태에서 사용자 벡터를 계산하는 단계)**이라고 한다.

## 공통 평가와 선택

기본 비교는 같은 검증 사용자 **325,639명**, 같은 정답 하나·입력 이력·제외 목록과 같은 Linux 후보 **6,630개**를 사용한다. 이미 입력한 긍정·부정 게임은 모두 추천에서 제외하고, 숨긴 정답은 입력이나 제외 목록에 넣지 않는다. 점수가 양수인 후보를 최대 10개 추천하며, 추천 목록이 빈 사용자도 평가 분모에 남긴다. 인기도로 빈자리를 채우는 방식은 해당 정책을 켠 실험에서만 사용한다.

**Recall@10**은 숨긴 긍정 게임을 추천 상위 10개 안에서 찾은 사용자 비율이다. 정답이 하나일 때는 Hit Rate@10과 같다. **NDCG@10**(정규화 할인 누적 이득)은 정답이 추천 목록의 앞에 있을수록 높은 점수를 준다. 두 지표 모두 추천 10개 전체의 정확도나 구매 전환율을 나타내지 않는다.

전체 검증 NDCG@10을 우선하고 Recall@10을 보조로 본다. 현재 선택된 같은 계열 모델과 비교해 다음 조건을 모두 만족한 설정만 자동 교체 후보가 된다.

- 같은 사용자끼리 결과를 짝지어 표본을 복원 추출하는 bootstrap 2,000회에서 NDCG 변화의 95% 구간 하한이 0보다 크다.
- 전체 Recall, 정답 게임별 평균 NDCG, 학습에서 긍정 평가한 사용자가 1–999명인 정답의 NDCG가 낮아지지 않는다.
- 빈 목록 사용자가 늘지 않는다.

협업 모델과 두 모델 결합은 현재 Item-KNN과 비교하고, 콘텐츠 모델은 v2에서 선정한 소개글 50%·태그/장르 50% 모델과 비교한다. 인기도로 빈자리를 채운 결과는 별도 추천 정책으로 표시한다. 전체 평균이 가장 높은 설정과 모든 조건을 통과한 설정을 구분한다. 여러 검증 후보를 비교한 뒤 계산한 bootstrap 구간은 독립 확인이 아니며, 여러 비교에 따른 편향을 보정하지 않는다.

frank 자료는 이미 여러 차례 확인했다. 모델 설정을 고르는 데 사용하지 않는다. 검증에서 설정을 선택하고 모델·파일 해시값을 확정한 뒤, 선택한 모델을 확인하는 **참조 평가**에만 쓴다. 이를 새 독립 테스트라고 부르지 않는다.

## 재정렬과 새 특징의 누수 방지

LambdaMART는 여러 특징을 이용해 추천 순서를 학습하는 순위 모델이다. 현재 두 모델의 추천에서 이미 관측한 게임을 제외하고 각각 상위 50개를 뽑은 뒤, 두 목록을 합쳐 재정렬한다. 정답이 후보에 없다는 이유로 후보 목록에 추가하지 않는다. 사용자 ID로 검증 사용자를 세 집단으로 나눈다. 각 집단의 예측은 해당 사용자를 학습에서 제외한 모델로 생성한다. 이 방식을 **교차 적합(cross-fitting)**이라고 하며, 각 사용자의 평가 정보가 그 사용자를 평가하는 모델의 학습에 들어가지 않게 한다. 각 모델은 나머지 집단에서 정해진 방식으로 선택한 최대 50,000명을 사용해 학습하고, 평가 분모는 전체 검증 사용자다. 상세 계산 한도는 별도의 재정렬 실행 규칙에 확정한다.

관측하지 않은 후보의 관련성을 0으로 둔 값은 이 평가에서 사용하는 약한 학습 신호다. 이를 실제 부정 리뷰로 해석하지 않는다. 후보 목록에 정답이 없는 사용자의 손실도 평가에 남긴다. 정답을 후보에 추가해 학습·평가를 쉽게 만드는 오류를 막는다.

리뷰 본문·플레이타임·작성 시점은 허용된 학습 계정과 사용을 승인한 원 리뷰 ID에 연결한다. 평가 사용자의 특징은 보이는 입력에서만 만든다. 숨긴 정답 리뷰의 작성 시점·플레이타임·언어는 사용자 프로필 특징으로 사용하지 않는다. 플레이타임 누적 스냅샷과 리뷰 작성 당시 플레이타임은 서로 다른 값으로 기록한다. frank의 추가 열은 고정한 기존 커밋에서 가져온다. 추가 열을 붙인 뒤 기존 리뷰 ID·계정·게임·라벨이 중복 수를 포함해 완전히 일치하는지 대조한다.

## 보조 평가의 해석

최소 입력 수·정답 개수·입력 이력·후보 제외 목록을 바꾸면 평가 과제 자체가 달라진다. 같은 보조 평가 안에서는 모델끼리 비교할 수 있지만, 기본 결과인 40.08% 또는 11.19%와의 차이를 곧바로 모델 개선량으로 계산하지 않는다. 정답을 여러 개 숨긴 평가에서 Recall은 `찾은 정답 수 / 숨긴 정답 수`로 계산한다. NDCG도 숨긴 정답 수에 맞춘 이상적인 순위 점수로 나눈다.

Kieran 이력을 보태도 예약 계정을 학습에 다시 넣지 않는다. 추가 자료는 추천을 생성할 때 사용자 입력으로만 사용하고, 숨긴 정답은 반드시 제거한다. 정답 작성 시각 이전의 이력도 별도로 만들지만, 정답 시각은 해당 보조 평가에서 입력 이력을 고르는 기준일 뿐 모델 특징으로 쓰지 않는다. 남은 frank 입력이 모두 시간상 정답보다 앞서 있다는 뜻은 아니다.

시간순으로 정렬하기만 한 평가와 미래 시점의 결과를 예측하는 평가는 다르다. 미래를 예측하려면 학습 리뷰·사용자 입력·정답 사이의 전체 시간 경계와 라벨 업데이트 시점을 함께 확인해야 한다. 나중에 수집한 카탈로그 정보나 누적 플레이타임은 자동으로 과거 시점의 정보가 되지 않는다.

소개글이나 제목이 같으면 중복일 가능성이 있다. 그렇다고 후속작·에디션·데모가 같은 게임이라고 자동 판단하지 않는다. 코사인 유사도가 높다는 이유로 사용자를 기본 평가에서 빼지 않는다. 집단 간 차이는 연관성이 있다고 보고하고, 원인이라고 단정하지 않는다.

## 저장과 확인

각 실험의 모델 설정·학습 자료 출처·파일 SHA256·실행 시간·전체 사용자 결과·추천 목록을 남긴다. 저장한 추천을 SQL로 다시 읽어 중복 추천, 이미 관측한 게임의 재추천, 정답 순위, 추천 개수와 정렬, 후보 누락, 사용자 누락을 확인한다. 다시 계산할 수 없는 항목이나 실행 실패를 성능 0 또는 완료로 기록하지 않는다.
