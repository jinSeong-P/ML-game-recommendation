RP3β는 사용자–아이템 그래프의 경로 확률과 인기도 감점을 쓰는 협업 필터링 방법이다. 표준 RP3β의 경로를 늘어난 게임–게임 경로로 잘못 해석하지 않는다. 두 게임 사이에 공동 학습 사용자가 없다면 이 방법만으로 그 게임 쌍의 연결이 생기지는 않는다. 실제로 양수 정답 점수 사용자와 추천 적중을 별도로 측정한다.

EASE는 아이템 간 선형 회귀를 한 번에 학습하는 모델이고, iALS는 미관측 상호작용의 낮은 신뢰도를 포함하는 잠재요인 모델이다. EASE는 전체 37,610개 게임의 해를 구한다. 계산 때문에 게임 수를 줄인 결과를 전체 EASE로 기록하지 않는다. iALS 평가 사용자의 벡터는 이미 학습한 게임 벡터를 고정하고 보이는 입력만으로 계산한다. 이를 **fold-in**이라고 부른다.

## 공통 평가와 선택

기본 비교는 같은 검증 사용자 **325,639명**, 같은 정답 하나·입력·제외 목록과 같은 Linux 후보 **6,630개**를 사용한다. 이미 입력한 긍정·부정 게임을 모두 제외하며, 숨긴 정답은 입력이나 제외 목록에 넣지 않는다. 점수가 양수인 후보를 최대 10개 추천한다. 빈 목록 사용자도 분모에 남긴다. 인기도 보완은 그 정책을 켠 실험에서만 사용한다.

**Recall@10**은 숨긴 긍정 게임을 추천 10개 안에서 찾은 사용자 비율이다. 정답 하나일 때 Hit Rate@10과 같다. **NDCG@10**은 정답이 위쪽에 있을수록 더 높은 점수를 준다. 추천 10개 전체의 정확도나 구매 전환율을 뜻하지 않는다.

전체 검증 NDCG@10을 우선하고 Recall@10을 보조로 본다. 현재 프로젝트에서 선택한 같은 계열 모델과 비교하여 다음 조건을 모두 만족해야 자동 교체 후보가 된다.

- 같은 사용자를 짝지은 bootstrap 2,000회의 NDCG 변화 95% 구간 하한이 0보다 크다.
- 전체 Recall, 정답 게임별 평균 NDCG, 학습 긍정 사용자 수 1–999명인 정답의 NDCG가 낮아지지 않는다.
- 빈 목록 사용자가 늘지 않는다.

협업 모델·두 모델 결합은 현재 Item-KNN과, 콘텐츠 모델은 v2의 소개글 50%·태그/장르 50% 모델과 비교한다. 인기도 보완은 별도 추천 정책으로 표시한다. 전체 평균 최고 설정과 모든 조건을 통과한 설정을 구분한다. 검증 후보를 여러 번 비교한 뒤 얻은 bootstrap 구간은 독립 확인이나 다중 비교 보정이 아니다.

frank는 이미 여러 차례 관측한 자료다. 설정을 고를 때 사용하지 않고, 검증 선택과 모델·파일 지문을 고정한 뒤 선택 모델의 **참조 평가**에만 사용한다. 새 독립 테스트라고 표현하지 않는다.

## 재정렬과 새 특징의 누수 방지

LambdaMART는 여러 특징으로 추천 순서를 학습하는 순위 모델이다. 현재 두 모델에서 관측 게임을 먼저 제외하고 각각 상위 50개를 뽑아 합친 후보에 적용한다. 정답이 없다고 후보에 끼워 넣지 않는다. 사용자 ID를 기준으로 검증 사용자를 세 집단으로 나눠, 각 사용자의 예측은 그 사용자를 학습에 넣지 않은 모델로 생성한다. 이를 **교차 적합(cross-fitting)**이라고 부른다. 각 학습은 다른 집단에서 결정론적으로 뽑은 최대 50,000명을 사용하며 평가 분모는 전체 검증 사용자다. 상세 계산 한도는 별도의 재정렬 실행 규칙에 고정한다.

미관측 후보의 관련성 0은 이 평가 과제에서 사용하는 약한 학습 신호이며, 실제 부정 리뷰라는 뜻이 아니다. 후보에 정답이 없는 사용자의 손실도 평가에 남긴다. 정답을 후보에 추가해 학습·평가가 쉬워지는 오류를 막는다.

리뷰 본문·플레이타임·시점은 허용된 학습 계정과 수용된 원 리뷰 ID에 연결한다. 평가 입력 특징은 보이는 입력에서만 만든다. 평가 정답의 작성 시점·플레이타임·언어를 프로필 특징으로 사용하지 않는다. 플레이타임 누적 스냅샷과 리뷰 작성 당시 플레이타임은 다른 값으로 기록한다. frank의 추가 열은 기존 고정 커밋에서 가져오고, 기존 리뷰 식별자·계정·게임·라벨의 다중집합과 완전히 일치하는지 대조한다.

## 보조 평가의 해석

최소 입력 수·정답 개수·입력 이력·후보 제외 목록을 바꾸면 과제가 바뀐다. 같은 보조 평가 안에서는 모델끼리 비교할 수 있지만, 기본 40.08% 또는 11.19%와 차이를 곧바로 모델 개선량으로 계산하지 않는다. 여러 정답에서는 Recall이 `찾은 정답 수 / 숨긴 정답 수`이고, NDCG도 숨긴 정답 수에 맞는 이상적 순위 점수로 나눈다.

Kieran 이력 보강은 예약 계정을 학습에 되돌리는 작업이 아니다. 추론 입력에만 더하며 숨긴 정답을 반드시 제거한다. 정답 작성 이전 이력도 생성하지만, 정답 시각은 그 보조 평가의 이력 선택 기준일 뿐 모델 특징이 아니다. 남아 있는 frank 입력 전체가 시간순으로 과거라는 뜻은 아니다.

시간 순서만 정렬한 평가와 미래 시점을 예측하는 평가는 구분한다. 후자는 학습 리뷰·입력·정답 사이의 전역 시간 경계와 라벨 업데이트 시점을 함께 검증해야 한다. 미래에 수집한 카탈로그나 누적 플레이타임까지 자동으로 과거 자료가 되는 것은 아니다.

같은 소개글이나 같은 제목은 중복 가능성의 근거다. 후속작·에디션·데모가 같은 게임인지 자동 확정하지 않으며, 높은 코사인 유사도를 이유로 사용자를 기본 평가에서 제거하지 않는다. 집단 간 차이는 연관성을 보고하며 원인으로 단정하지 않는다.

## 저장과 확인

실험마다 모델 설정, 학습 출처, 파일 SHA256, 실행 시간, 전체 사용자 결과와 추천 결과를 남긴다. 저장한 추천을 SQL로 다시 읽어 중복·관측 게임 재추천·정답 순위·추천 개수·정렬·후보·사용자 누락을 검사한다. 재현하지 못한 항목과 실행 실패를 성능 0이나 완료로 바꾸지 않는다.
