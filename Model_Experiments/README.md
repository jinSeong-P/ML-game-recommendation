# Steam 게임 추천: v1–v3 실험 결과

이 프로젝트는 A의 사용자 리뷰와 A·B의 게임 정보를 이용해 추천을 만들고, C 리뷰로 Linux 게임 추천을 확인합니다. **v2와 v3는 2014년까지의 A와 2015년의 C로 같은 사용자·정답·후보에서 비교했습니다.** C를 이전에도 확인했으므로 아래 C 점수는 독립적인 최종 시험 점수가 아니라 참고 결과입니다.

바로 실행해 볼 파일은 [공유용 v3 노트북](Baseline_V3.ipynb)입니다. VS Code에서 열어 Python 커널을 선택하고 위에서부터 실행하면 표·그래프·실제 예측 예시를 볼 수 있습니다. 기존 EDA는 이 브랜치의 EDA 폴더를 확인하세요.

## 1. 데이터와 실험 목적

| 데이터 | 사용한 정보 | 역할 |
|---|---|---|
| A | 사용자 ID, 게임 ID, 리뷰 날짜, 추천 여부, 게임 설명·태그 | 긍정·부정 리뷰로 게임 간 관계 학습, 게임 콘텐츠 보강 |
| B | 게임 ID, 설명, 태그·장르 등 게임 메타데이터 | A 게임의 콘텐츠 보강. 사용자 리뷰 학습 데이터가 아님 |
| C | 사용자별 게임 리뷰, 날짜와 긍정·부정 여부 | A에서 ID를 연결하지 않는 사용자 입력과 숨긴 정답으로 참고 평가 |

Linux와 다른 OS를 구분하지 않고 A 전체 게임의 관계를 학습합니다. 추천 시에는 A 카탈로그의 Linux 지원 게임만 후보로 사용합니다. A의 긍정 리뷰는 +1, 부정 리뷰는 -1로 게임 간 유사도 학습에 사용합니다.

## 2. 연도를 선택한 이유

처음 v1은 C의 날짜가 주로 2015년까지인 점을 고려해 **A 2012년까지 / C 2013–2015년**으로 정했습니다. 이는 앞서 합의한 시범 기준이며, 분포 비교로 최적임이 증명된 연도는 아니었습니다. A는 익명 ID라 C와 동일 인물 여부를 확인할 수 없기에 날짜 분리는 그 위험을 없애지는 못합니다.

이번에는 **모델 점수를 보기 전에**, 비교 가능한 C 사용자 500명 이상과 Linux 후보 50개 이상이 남는 경계 중 가장 늦은 연도를 선택했습니다. 500명과 50개는 실험이 지나치게 작아지는 것을 피하기 위한 실용적인 최소 기준이며, 통계적으로 충분하다는 보장은 아닙니다. A에서 사용자·게임별 해당 시점까지 마지막 리뷰를 남겼습니다.

| A 마지막 연도 | C 평가 연도 | A 리뷰 쌍 | A 사용자 | Linux 후보 | 평가 가능한 C 사용자 |
|---:|---:|---:|---:|---:|---:|
| 2012 | 2013–2015 | 185,473 | 90,085 | 196 | 2,794 |
| 2013 | 2014–2015 | 520,808 | 275,763 | 412 | 3,589 |
| 2014 | 2015–2015 | 1,663,964 | 863,310 | 860 | 1,536 |


세 후보가 모두 최소 기준을 통과하여 가장 늦은 **2014년**을 확정했습니다. 2012년보다 A 리뷰 쌍은 약 9배로 늘고 Linux 후보도 늘지만 C 평가 사용자는 2,794명에서 1,536명으로 줄며 2015년만 평가합니다. 이는 학습 이력 확보를 우선한 선택이지, 2014년이 유일하게 옳다거나 성능이 최고라는 뜻은 아닙니다. 위 표는 A 검증 사용자 분리 전 규모입니다.

## 3. 데이터 준비와 평가 방법

1. A 전체 **41,154,794행**을 나누어 읽어 날짜·ID·긍정/부정이 유효한 리뷰를 추립니다. 해당 연도 이전 동일 사용자·게임 리뷰는 최신 것만 남깁니다.
2. A 사용자 ID를 해시로 나눠 약 10%를 내부 검증으로 예약하고, 그 사용자의 모든 A 리뷰를 모델 학습에서 제외합니다. 실제 예약은 86,305명이며, 이 중 평가 조건을 만족한 사용자는 **17,065명**입니다. 검증은 시간 순 미래 예측이 아닌 사용자 분리 검증입니다.
3. 남은 A 학습에는 리뷰 **1,499,584개**, 사용자 **777,005명**이 있습니다. 긍정 1,347,920개, 부정 151,664개입니다. 5개 이상 A 리뷰와 콘텐츠가 있는 게임만 후보 카탈로그에 포함해 전체 3,055개 중 Linux 858개를 추천 대상으로 둡니다.
4. C는 2015년 리뷰를 사용합니다. 각 사용자의 카탈로그에 속한 Linux 긍정 게임 중 20%를 올림해 최소 1개를 숨긴 정답으로 두고 나머지 긍정·부정 게임을 입력으로 사용합니다. 입력과 정답은 겹치지 않고 이미 입력된 게임은 추천하지 않습니다. 긍정 입력과 카탈로그에 있는 Linux 긍정 정답을 가진 사용자만 평가합니다. 실제 C 사용자는 **1,536명**, 숨긴 정답은 1,546개입니다. 사용자별 정답 숨기기는 연도 내부에서 무작위이므로 정답이 입력보다 시간상 나중이라는 보장은 없습니다.
5. C는 별도 데이터셋이므로 A와 C의 전체 행을 억지로 8:2로 맞추지 않았습니다. 내부 검증용 A 사용자 10%와 사용자별 정답 숨김 비율 20%는 별개의 목적입니다.

## 4. 버전별 변경과 검증

**v1**은 이전에 실행해 저장된 결과를 보존했습니다. A 2012년까지, C 2013–2015년, K=50, 부정 입력 감점 1, 설명과 태그 결합입니다. 이 공유본에는 v1의 집계 결과만 포함되어 있습니다. 저장된 노트북 출력은 당시 결과이나, 보존 코드는 실행 후 확보한 파일이므로 당시 커널에서 사용된 코드와 완전히 동일하다고 증명할 수는 없습니다. 당시 학습된 모델 파일은 별도로 저장돼 있지 않아 v1의 즉시 추론 모델은 복원하지 못했습니다.

**v2**는 선택한 2014년 경계를 적용하고, A 내부 검증 사용자를 분리했습니다. 모델의 기본 설정은 K=50, 부정 입력 감점 1, 설명·태그 결합입니다. v1과는 날짜와 학습·평가 집단이 달라 점수 차이를 모델 개선 효과로 해석할 수 없습니다.

**v3**는 v2와 같은 날짜·학습 데이터·평가 집단에서 각각 부정 입력 감점 0/0.3/1, K=20/50/100, 콘텐츠 결합 또는 설명·태그 각각 TF-IDF 후 50:50 결합을 비교했습니다. 각 항목을 A 내부 검증 NDCG@10으로 고르고 선택 조합을 다시 검증했습니다. 조합이 기본값보다 낮으면 해당 모델은 기본값으로 돌아갑니다. 선택된 설정은 **K=20, 부정 입력 감점 콘텐츠 0.0·KNN 0.0, 텍스트 결합**입니다. 같은 검증 집합에서 여러 설정을 시험했으므로 선택 점수는 낙관적일 수 있습니다.

| A 내부 검증 설정 | 콘텐츠 NDCG@10 | KNN NDCG@10 |
|---|---:|---:|
| 기본값: 감점 1, K=50, 텍스트 결합 | 0.0461 | 0.1104 |
| 부정 입력 감점 0 | 0.0496 | 0.1124 |
| 부정 입력 감점 0.3 | 0.0485 | 0.1117 |
| K=20 | 0.0461 | 0.1171 |
| K=100 | 0.0461 | 0.1099 |
| 설명·태그 분리 50:50 | 0.0456 | 0.1104 |

| A 내부 검증 최종 조합 | Recall@10 | NDCG@10 | Coverage@10 |
|---|---:|---:|---:|
| 콘텐츠 | 0.0912 | 0.0496 | 0.9347 |
| Item-KNN | 0.2235 | 0.1189 | 0.9371 |

**부정 입력 감점이 0이라는 의미:** 사용자가 싫어한 게임과 비슷하다는 이유로 점수를 별도로 깎지 않는다는 뜻입니다. A의 부정 리뷰는 여전히 -1로 KNN 학습에 들어가고, 입력한 부정 게임 자체는 추천 목록에서 제외합니다. 따라서 부정 리뷰를 전부 버린 것은 아닙니다. 감점 0이 모든 데이터에서 최선이라는 의미도 아닙니다.

### 최종 후보를 고른 이유와 가중치·K의 의미

개인화 모델의 **최종 발표 후보는 v3 Item-KNN**입니다. 같은 A 내부 검증 사용자 17,065명에서 v3 KNN의 NDCG@10은 **0.1189**, v3 콘텐츠는 **0.0496**이었습니다. 인기순은 **0.1185**로 KNN과 거의 비슷했습니다. 이 선택은 개인화 모델 중 검증 NDCG가 높다는 근거이며, 모델 종류별 설정은 각각 검증으로 고른 것입니다. 별도 통계 검정이나 새로운 데이터에서의 우월성을 증명한 것은 아닙니다. 특히 C 참고 평가에서는 인기순이 KNN보다 정확도가 높았으므로 **인기순까지 포함한 절대적인 최고 모델이라고 발표하면 안 됩니다.**

부정 입력 감점은 `최종 점수 = 긍정 입력 점수 - α × 부정 입력 점수`입니다. 이 코드에서 α=1은 부정 점수에 **-1을 곱해 더하는 것**, 즉 전부 감점한다는 뜻입니다. α=0은 부정 입력으로 추가 감점하지 않습니다. 아래는 나머지 설정을 v2 기본값(K=50, 텍스트 결합)으로 고정하고 α만 바꾼 A 내부 검증 결과입니다.

| 부정 입력 계수 | 콘텐츠 NDCG@10 | KNN NDCG@10 | 의미 |
|---|---:|---:|---|
| -1 (α=1) | 0.0461 | 0.1104 | 부정 유사도를 전부 빼기 |
| -0.3 (α=0.3) | 0.0485 | 0.1117 | 부정 유사도를 일부 빼기 |
| 0 (α=0) | **0.0496** | **0.1124** | 부정 유사도로 추가 감점하지 않기 |

**관찰:** 이번 검증에서는 감점을 줄일수록 두 모델의 NDCG가 높았습니다. **가능한 해석:** 한 게임을 싫어한 이유가 장르 전체에 대한 거부가 아닐 수 있는데, 감점이 크면 실제로 좋아할 다른 게임까지 순위가 내려갈 수 있습니다. 다만 검증 결과만으로 이것이 실제 원인이라고 증명하지는 못했으며, 부정 입력이 없는 사용자는 가중치를 바꿔도 그 부분의 점수가 달라지지 않습니다. `α=-1`은 수식상 부정 유사도를 더해 주므로 위의 **계수 -1**과 다르고, 이번에는 실험하지 않았습니다.

K는 입력 게임 하나마다 유사 게임을 최대 몇 개 반영할지 정하는 숫자입니다. 모든 게임에 항상 K개가 있는 것은 아니고 양의 유사도 이웃만 사용합니다. 아래는 α=1, 텍스트 결합을 유지하고 K만 바꾼 결과입니다.

| K | KNN Recall@10 | KNN NDCG@10 |
|---:|---:|---:|
| 20 | **0.2199** | **0.1171** |
| 50 | 0.2012 | 0.1104 |
| 100 | 0.1982 | 0.1099 |

K가 작으면 더 가까운 게임의 관계에 집중하지만 점수가 있는 후보가 부족해질 수 있습니다. K가 크면 더 넓게 반영하지만 약한 관련성도 더 많이 섞입니다. 이번에는 K=20이 가장 높았습니다. **약한 이웃이 잡음을 늘렸을 가능성은 있지만 원인으로 입증된 것은 아닙니다.** 감점 0과 K=20을 함께 적용한 v3 KNN은 A 검증 NDCG **0.1189**, Recall **0.2235**였습니다.

설명·태그를 각각 TF-IDF로 만든 뒤 50:50으로 합친 방식은 A 검증 콘텐츠 NDCG 0.0456으로 기존 결합 방식 0.0461보다 낮아 선택하지 않았습니다. 이것은 실험한 **하나의 분리 방식**에 대한 결과이며, 다른 비율이나 처리법도 모두 나쁘다는 뜻은 아닙니다.

## 5. 실제 결과

지표는 모두 높을수록 좋습니다. **Recall@10**은 사용자별 숨긴 정답 중 10개 추천에 들어간 비율의 평균, **NDCG@10**은 정답을 더 높은 순위에 놓을수록 높은 점수, **Coverage@10**은 전체 사용자에게 한 번 이상 추천된 Linux 후보의 비율입니다. 사용자마다 정답 수가 적어 소수의 인기 게임이 높은 점수를 얻을 수도 있습니다.

이전 v1의 C 결과입니다. 아래 v2·v3와 기간 및 대상이 다릅니다.

| v1 모델 | Recall@10 | NDCG@10 | Coverage@10 |
|---|---:|---:|---:|
| 콘텐츠 | 0.2785 | 0.1239 | 0.9847 |
| Item-KNN | 0.2344 | 0.1380 | 1.0000 |
| 인기순 | 0.4909 | 0.2510 | 0.0714 |

같은 C 사용자와 후보를 사용한 v2·v3 참고 결과입니다.

| 버전 | 모델 | Recall@10 | NDCG@10 | Coverage@10 |
|---|---|---:|---:|---:|
| V2 | 콘텐츠 | 0.1130 | 0.0546 | 0.7774 |
| V2 | Item-KNN | 0.2305 | 0.1271 | 0.8193 |
| V2 | 인기순 | 0.4896 | 0.2566 | 0.0163 |
| V3 | 콘텐츠 | 0.1165 | 0.0573 | 0.7063 |
| V3 | Item-KNN | 0.2952 | 0.1497 | 0.7051 |
| V3 | 인기순 | 0.4896 | 0.2566 | 0.0163 |


같은 C 사용자 기준 v2에서 v3로 바뀌었을 때 NDCG@10 차이는 **콘텐츠 +0.0027 / KNN +0.0225**입니다. v3 비교에서 NDCG@10이 가장 높은 방법은 **인기순**입니다. 이는 이번 C 평가 조건에서 관찰한 값이며, 새로운 데이터에서도 같은 차이가 난다는 증거는 아닙니다.

인기순은 개인 취향과 무관하게 A에서 긍정 리뷰가 많은 게임을 우선하는 비교 기준입니다. 개인화 모델이 인기순보다 항상 좋다는 보장은 없으며, 정확도와 추천 다양성·편중을 함께 살펴봐야 합니다. 그래프와 수치는 **조건을 만족해 평가에 들어온 사용자와 게임에 한정**되므로 전체 Steam 사용자에 대한 성능이 아닙니다. 상세 수치는 노트북에 포함된 집계와 표에서 확인할 수 있습니다.

## 6. 추천을 만드는 과정과 실제 예시

1. 사용자가 좋아한 게임과 싫어한 게임의 Steam App ID를 입력합니다. 입력 게임은 학습된 카탈로그에 있어야 하며 긍정 게임이 최소 1개 필요합니다.
2. **콘텐츠 기반:** A·B 설명과 태그의 텍스트를 정리하고 기본 단어 분리 후 TF-IDF 숫자 벡터로 바꿉니다. 긍정 게임들의 평균 벡터와 후보 게임의 코사인 유사도를 계산하고, 설정된 부정 가중치만큼 부정 프로필 유사도를 뺍니다. 별도 형태소 분석기는 사용하지 않습니다.
3. **Item-KNN:** A에서 사용자별 긍정 +1·부정 -1로 만든 게임–사용자 행렬에서 게임 간 코사인 유사도를 구합니다. 양의 유사도만 이웃으로 남기고, 입력 게임마다 가까운 K개 게임으로 점수를 합산합니다. 부정 입력은 설정된 가중치로 감점합니다.
4. Linux 지원 후보 중 입력에 없던 게임을 점수 순으로 최대 10개 표시합니다. 동점은 A의 긍정 리뷰 수, 그다음 App ID로 정렬하며, 유사도 0인 게임도 자리를 채울 수 있습니다. 콘텐츠와 KNN은 별도 목록이며 점수 크기를 서로 직접 비교할 수 없습니다.

아래는 실제 C 평가에서 사용자 ID를 제외하고 기록한 v3 예시입니다. ✓는 숨긴 정답입니다.

| 항목 | 게임 |
|---|---|
| 긍정 입력 | RaceRoom Racing Experience |
| 부정 입력 | 없음 |
